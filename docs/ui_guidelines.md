# 画面と文言のガイドライン

この文書は、cordmux が利用者に見せるテキストと、画面の見た目とふるまいを決める。画面の文字列、手順書、ドックの見た目を変えるときに読む。対象は、ドック、設定ウィンドウ、参加者の設定ウィンドウ、ダイアログ、OBS の一覧とソースのプロパティ、Vencord のプラグインの説明、配信画面に描画する名前ラベルと話している人の光、手順書 (`guide/ja.md` と `guide/en.md`) である。OBS のログの行は CODESTYLE.md の「OBS のログ」に、変更履歴は docs/release.md の「変更履歴の書き方」に従う。cordmux のテキストは OBS のウィンドウの中で OBS のテキストと並ぶので、ルールの多くは OBS・Discord・Windows の画面に合わせてある。この文書にない場面でも、それらの画面に合わせる。

ドックの各部の呼び名 (1 行目、メインとサブの行、タブ、スクロール領域、下のバー) は「ドックの構成」に、メッセージのレベル 1 から 3 の決め方は「メッセージのレベルと表示方法」にある。

## 対象読者と文体

読み手は、OBS のシーン、ソース、音声ミキサーと、Discord の通話、画面共有、招待を使える利用者である。コマンド、ビルド、映像と通信の仕組み、設定ファイルは知らない前提で書き、OBS と Discord そのものの使い方は説明しない。英語の画面は、英語だけを読む人に向けて書く。

起きていること、その影響、次にすることだけを書く。感嘆、冗談、励まし、謝罪、宣伝、ほめ言葉 (「うまくいきました」) は書かない。警告は配信の最中に読むので、事実のほかの言葉は読む量を増やすだけになる。

丁寧さは UI 要素の種類で決め、1 つの文字列の中で形を混ぜない。Microsoft の日本語のスタイルガイドの割り当てを元にし、チェックボックスだけは OBS のプロパティの画面に合わせて短くする (スタイルガイドは「〜する」の形)。

| 形 | UI 要素 |
|---|---|
| 名詞で止める (「名前を変更」)。和語の動詞は辞書形 (「フォルダーを開く」)。句点を付けない | ページ、見出し、ボタン、メニュー項目、入力欄のラベル、表の列の見出し、ウィンドウとダイアログのタイトル、OBS の一覧の名前 |
| 機能の名前 (名詞) か短い句。句点を付けない | チェックボックス、動作を表す選択肢 (下の「チェックボックスと選択肢」) |
| です・ます。句点まで書く (メッセージの見出しとダイアログの主文には付けない) | メッセージ、押せない理由、ダイアログの主文と補足、ツールチップ、空の一覧の文、手順書の地の文 |
| 状態の値 (「状態の表示」)。句点を付けない | 参加者の行の状態、メッセージの中の段階の行、1 行目の要約 |
| 一段丁寧 (「ご確認ください」「もう一度お試しください」) | 確認、再試行、注意を頼む定型の言い方だけ |

ほかの尊敬語と謙譲語 (「〜いただく」「〜なさる」)、「申し訳ございません」、「〜しましょう」は使わない。

「あなた」「私たち」を書かない。英語は "you" を使ってよいが、"we" "our" は書かない。cordmux が自動ですることは、主語を省くか受け身で書く (「自動で再接続します。」)。どのアプリが動くか、どのアプリで操作するかで利用者のすることが変わる文では、アプリの名前を書く (「これらの設定を反映するには、OBSの再起動が必要です。」)。

cordmux が観測した範囲のことだけを書く。書けるのは、cordmux の状態、cordmux への操作の結果、観測したこと (届いた、届かない、見つからない) までで、配信の出力、視聴者に見えるもの、観測していない原因は断定しない。影響は「枠には」のように cordmux が確認できる範囲を主語にする。確認できなかった事実 (「次のシーンコレクションは確認できませんでした。」) と、cordmux の動作として決まっている影響 (「切れている間の映像と声は録画されません。」) は書いてよい。推測 (「Discordの更新が原因かもしれません」) は書かず、原因の候補は、確認するものを次の操作として書く (「Vesktopで、画面共有の映像が映っているか確認してください。」)。

同じことは 1 回だけ書く。ドックの 1 画面や 1 つのウィンドウの中で、状態の値、ボタンの名前、別の行が伝えていることを文で言い直さない。言い直してよいのは、別々に読まれるもの (確認のダイアログと手順書、画面のテキストとアクセシブルな説明) と、押す直前に必要な注意をボタンやメニュー項目に添えるとき (「cordmuxを無効にする (録画も終了します)」) だけである。

対象の語は、書かなくても指す物が分かるときは付けない。分かるかどうかは、文言だけでなく、見た目の配置 (どのウィンドウ、ページ、組、見出し、罫線の中か、隣に何があるか) で決まる。分かりにくいときは、先に配置で分かるようにできないか (置く場所、組と見出し、区切り、文の順) を考え、語を足すのは配置で解けないときだけにする。語が増えるほど読む負担が増えるためである。

- 付けない例: ドックの録画のボタン [録画を開始] (ドックの録画は cordmux の録画だけ)、1 行目の「cordmuxは無効です」の隣の [有効にする]、録画のボタンのツールチップの「無効にしている間は」(同じドックの 1 行目に「cordmuxは無効です」が出ている)、「cordmuxの設定」ウィンドウの中のツールチップの「録画」、ドックのメッセージの「設定を読み込めませんでした」(Vesktop の設定のメッセージは「Vesktopの」と書くので、何も付けない「設定」は cordmux の設定と読める)。
- 配置で解いた例: [保存先] の説明は「変更は、次に録画を開始したときから反映されます。」を先に置き、OBS の「録画ファイルのパス」の文をその後にする (逆の順だと、「録画」が OBS の録画とも読める)。
- 配置で解いた例: [音声の形式] は、録画ファイルの設定なので [録画] ページに置く ([詳細設定] の「映像と音声」の組では、何の音声かが分からない)。[録画] ページの並びは、保存するファイルの設定の [保存先] と [音声の形式] を隣に置き、保存そのものに関わらない [残り時間の警告] はその下に置く。[映像の受信] ページは「受信する映像」と「Vesktopでのエンコード」の 2 つの組に分け、[映像エンコーダ] と [チューニング] が Vesktop 側の設定だと組の見出しで分かるようにする。
- 組の見出しで分かる語は付けない: [表示] タブの枠の組の [間隔] (アクセシブル名には組の見出しを添える)。
- 短い語に、語を足さずにツールチップを付ける: 行の [自動] のタグに、行のメニューの [自動で枠に載せる] と同じ文を出す。
- 付ける例: ドックのメニューの [cordmuxを無効にする] (メニューの項目には、ドックだけか、cordmux 全体か、ほかの何かかを示す配置がない)、1 行目の「cordmuxは無効です」、Vesktop にも Vencord が入っているときの「cordmuxに同梱の」、「OBSで録画中」と並んで出るアンインストールできない理由の「cordmuxで録画中」、OBS の [ツール] メニューと OBS から開くダイアログ (「cordmuxをアンインストール」)。
- ほかのアプリの中の物を指すとき (OBS の「cordmux」のソース、「Vesktop側のcordmux」) は残す。

英語は、日本語と同じ事実を同じ順に、英語として自然な言い方で書く。日本語を先に書き、日本語の語順と言い回しを持ち込まない。

## UI 要素ごとの書き方

### ページ、タイトル、見出し

ページの名前とウィンドウのタイトルは、中身を表す名詞か短い名詞句にし、英語は Title Case にする。OBS の [設定] に同じ中身のページがあれば、OBS のページの名前を使う (「詳細設定」)。ダイアログのタイトルは操作の名前を名詞で止めた形にし (「cordmuxのアンインストール」)、ファイルやフォルダーを選ぶダイアログは、OBS と同じく動詞を含める (「録画の保存先を選択」)。まとまりの見出し (`QGroupBox` のタイトル) は名詞句にし、「〜の設定」を付けず、同じページの見出しの形をそろえる (「現在の参加者」と「過去の参加者」)。種類の違う入力欄が 5 つ以上並ぶページは、見出しで分ける。

### ボタンとメニュー項目

ボタンには、押すと何が起きるかを、操作と対象が分かるいちばん短い形で書く。長さは表示したときの幅で確認する。

- 漢語とカタカナ語の動詞は「する」を落とし (「作成を再開」「再インストール」)、和語の動詞は辞書形にする (「ファイルの場所を開く」)。「有効にする」は OBS と同じく「する」を残す。
- 対象の語 (何の録画か、どのアプリの設定か、など) を付けるかどうかの決め方は、「対象読者と文体」にある。
- 同じ操作には、場面が違っても同じ名前を付ける (インストールの日に Vesktop の設定を書く操作も、ほかの Vencord を読むように変わった設定を書き直す操作も [Vesktopに追加])。逆の向きの操作は、対の語にする ([Vesktopに追加] と、状態タブの [Vesktopから削除])。
- 英語は動詞で始め、Title Case にし、ピリオドを付けない。
- 閉じるボタンとやめるボタンの名前は、押した結果で選ぶ。何も残さずにやめるのは [キャンセル]、済んだことが残る中断は [停止]、変更のないウィンドウとすぐ反映されるウィンドウ (参加者の設定ウィンドウ) を閉じるのは [閉じる]、結果と失敗のダイアログは [OK] (OBS と同じ) にする。[OK]、[キャンセル]、[適用]、[閉じる] のテキストは、OBS の [設定] と同じにするため cordmux の ini に持たず、OBS の ini から読む (`src-obs/ledger/text_ids.h` の `obs_keys`)。

押した後に入力、選択、確認がさらに必要なボタンとメニュー項目は、末尾に半角のピリオド 3 つ「...」を付ける (「名前を変更...」「診断情報をエクスポート...」)。ウィンドウを開くだけのもの (「cordmuxの設定」)、確認のダイアログの中の実行のボタン、押せば終わる操作には付けない。条件によって確認を表示するボタンは、多くの利用者が通る場合で決める ([Vesktopに追加] は、ほかの Vencord を使っている人にだけ確認を表示するので付けない)。文の中でボタンを指すときは「...」を省く。

状態を持つ操作は次の 3 つの形で作り、「切り替える」「ON/OFF」"Toggle" と書かない。

- 状態を持ち続ける設定は、チェックボックスにする。
- 始めると終わるまで続く操作は、押すと起きる側を書いたボタンにして状態でテキストを替え ([録画を開始] と [録画を終了])、1 秒を超えて処理が続くときは「開始処理中...」「停止処理中...」にする (OBS の「録画停止処理中...」と同じ形)。
- 向きが決まっている操作は、その向きだけを書く ([有効にする])。

メニュー項目は、名詞で止める形かボタンと同じ形にし、チェックの付く項目もこの形にする (「自動で枠に載せる」)。サブメニューを持つ項目は、中身をまとめる名詞にする (「使う声」)。今は使えない項目は押せなくし、短い理由を後ろの括弧に添える (「はなこ (既に「たろう」の行で使っています)」)。

### チェックボックスと選択肢

チェックボックスは、チェックを付けると何が有効になるかが読める、いちばん短い形で書く。文字が増えるほど読む負荷が増え、判断が遅れるためである。まとまりの見出しの下で意味が決まるなら、機能の名前だけにする (見出し「アバター」の下の [表示]、見出し「話している人の強調」の下の [光])。OBS のテキストソースのプロパティも [輪郭] [グラデーション] [垂直方向] と機能の名前で書く。名前だけでは何のチェックか分からないときは「〇〇を表示」の形にする ([Botを表示])。文にするのは、名前を付けにくい動きのときだけにする (「1人のときは非表示」)。どの形でも肯定にし、外したときの説明は書かない。英語は sentence case にする。ラベルの列にチェックだけを置かず、チェックの横に語を置く。例外は、チェックの隣に人の名前を置く参加者の行である。

選択肢は同じ形と同じくらいの長さにそろえ、違う所だけを書く。入力欄のラベルは、選択肢が答える問いにする (「枠に載せる人の選び方」に「手動」と「自動」。違いはツールチップに書く)。勧めるものには「(推奨)」を付ける。「(既定)」は、選択肢の間に優劣がなく既定を名前から読めないもの (映像のエンコーダ、チューニング、映像のデコード、音声の形式) にだけ付け、何もしない値 (「制限なし」「そのまま」) が既定のものと、数の選択肢には付けない。補足は半角の括弧で短く書き、確認した事実だけを書く。英語は、全部の選択肢が 1 語から 3 語の名前なら Title Case、1 つでも句を含むなら全部を sentence case にする。

### 入力欄のラベルと単位

ラベルは名詞句にし、末尾にコロンを付けず、英語は Title Case にする。OBS に同じものの入力欄があれば、OBS のラベルを使う (「フォントサイズ」「同期オフセット」)。数の単位は入力欄の後ろに付け (キーは `cordmux.settings.unit_*.label`)、付けられないときだけラベルの後ろの括弧に入れる。ラベルと値は同じものを指すようにし (「残り時間の警告」の値は分)、上限の入力欄は OBS と同じく「最大」を前に置く (「最大解像度 (長辺)」)。正負で向きが変わる入力欄は、ツールチップに向きを書く (「正の値で音声を遅らせます。」)。

プレースホルダーには、空のまま使ったときに入る値 (名前を変更する入力欄では Discord での名前) か、入れる値の例を表示する。操作の説明は、入力を始めると消えるので書かない。空のときのふるまいは、入力欄の下に常に表示する補足に書く (`cordmux.settings.save_folder.text`)。

### 状態の表示

状態の値は、Discord や VS Code が同じ状態に使うテキストを使う (「接続済み」「通話中」は Discord、「接続されていません」は VS Code と Discord)。無ければ短い名詞句か「〜ていません」の文にし、同じ列に並ぶ値は同じ形にそろえる。数は算用数字で単位を付けて括弧に入れ (「通話中 (4人)」)、句点を付けない。

「確認中...」は問い合わせを実際にしている間だけ表示し、前の段階が接続されていないために読めない値は、行ごと表示しない。一度も届いていないものを「届いていません」と書かない。メッセージの中の準備の段階は「名前: 値」の形 (「Vesktop: 接続済み」「cordmuxのソース: 追加済み」) にし、全体を 1 つのキーに持つ。

参加者の行のチェックが表すのは、枠に載せる指定だけである。行の状態は、枠に載っている人の枠に現在の映像が出ていないときと、cordmux の録画の対象の人の映像が届いていないときにだけ表示する。

| 状態 | ja | ja の短い形 | en |
|---|---|---|---|
| 載せたが、映像がまだ一度も届いていない | 映像を待っています... | 映像待ち | Waiting for video... (短い形は No video yet) |
| 届いていた映像が届かなくなった | 映像が届いていません | 映像途切れ | Not receiving video |
| 画面共有していない | 画面共有していません | 共有なし | Not sharing |
| Vesktop の cordmux が、送る映像の画質を下げている | 画質を下げています | 画質低下 | Lower quality |
| 同上。下げているのがフレームレートだけ | 画質を下げています (フレームレート) | FPS低下 | Lower frame rate |
| 同上。下げているのが解像度だけ | 画質を下げています (解像度) | 解像度低下 | Lower resolution |
| 同上。解像度とフレームレートの両方 | 画質を下げています (解像度とフレームレート) | 画質低下 | Lower resolution and frame rate |
| Vesktop の cordmux が、その人の映像を送っていない | 映像を表示できません | 表示不可 | Can't show video |

行の状態は、幅にかかわらず短い形で表示する (日本語は 5 字まで。Discord の「〜なし」「〜不可」と同じ形)。狭い所で全文の末尾を省くと、日本語は打ち消しが文末に来るので、「映像が届いて...」のように逆の意味の先頭が残るためである。英語は語順で先に問題を書けるので、短い形がない状態は全文のまま表示する。全文はツールチップとアクセシブルな説明に入れる。

進行中の表示は、末尾に「...」を付ける。自然な「〜中」がある値は「〜中...」(「確認中...」)、ほかは「〜しています...」にする (英語は "-ing...")。進み具合の数は実際の作業から来るときだけ添え、ファイルは「8ファイル中3ファイル完了」/ "3 of 8 files done"、現在のファイルは「4番目」と書く。経過時間は「経過時間: 12分」と名前を付けて別の値として添え、時計の数を進み具合に見せない。

1 行目に出すメッセージがないときの 1 行目は、次のどれかにする。状態をつなぐときは、前後に半角の空白を入れたハイフン「 - 」を使う (OBS がタイトルバーで状態をつなぐ形)。

| 状態 | ja | en |
|---|---|---|
| 通話中で、枠に映像が描画されている人がいる | 通話中 (4人) - 表示中 (3人) | In a call (4 people) - 3 displayed |
| 通話中で、描画されている人がいない | 通話中 (4人) - 表示中の人はいません | In a call (4 people) - None displayed |
| Vesktop と接続していて、通話に参加していない | Vesktopと接続済み - 通話に参加していません | Connected to Vesktop - Not in a call |
| Vesktop が起動していない | Vesktopが起動していません | Vesktop isn't running |
| OBS を起動した直後に、Vesktop が起動しているかを問い合わせている | 確認中... | Checking... |
| Vesktop と接続していないことのレベル 2 のメッセージを既読にした | Vesktop: 接続されていません | Vesktop: Not connected |
| cordmux を無効にしている | cordmuxは無効です | cordmux is disabled |
| ダミー映像を表示している | ダミー映像を表示中 - Discordの画面共有と声は使っていません | Showing placeholders - Discord video and voice aren't used |

「表示中」の人数は、枠に載っていて映像が今描画されている人の数である (`src-obs/ledger/rules_dock.cpp` の `displayed()`)。自分の枠を出している間は、自分も 1 人として数える (自分の枠の人が Discord の画面共有でも枠に載っているときは、二重に数えない)。利用者が自分で選んだ状態 (無効、ダミー映像) と「Vesktopが起動していません」は、警告のアイコンも色も付けずに表示する。

表のセルの「-」は値を読めないときにだけ使い、そのセルのアクセシブル名を「取得できません」にする。空の一覧には、何もない理由と次にできることを書く。1 行目が理由を伝えているときは言い直さず、ここに何が表示されるかとその条件を書く (「Vesktopと接続されると、ここに参加者が表示されます。」)。

### メッセージ

メッセージには、見出し、影響、次の操作を書く。

- 見出しには、何が起きているかを、利用者に見えるものの名前で、影響の大きい事実を先に 1 文で書く。です・ます で句点を付けず、名詞で止めない (状態の値と見分けが付かない)。
- 影響には、何ができず何が続くかを、コードで確認してから書く。
- 次の操作は、ボタンを置けるならボタンにし、置けないなら「〜してください。」の 1 文にする。人によって次の操作が違うときは、1 文ずつ並べる。修正する手段がないときは、情報を残す操作 ([診断情報をエクスポート...]) を名前のまま置き、修正する操作のように書かない。
- 長さは、見出しと 2 文ほどを目安にするが、続くもの、止まるもの、次の操作を、文の数のために削らない。

| Vesktop との接続が切れたメッセージ | ja | en |
|---|---|---|
| 見出し | Vesktopとの接続が21:30に切れました | Disconnected from Vesktop at 9:30 PM |
| 影響と次の操作 | 再接続するまで、画面共有と声は届きません。自動で再接続します。しばらくしても再接続されないときは、Vesktopを再起動してください。 | Screen shares and voice won't arrive until Vesktop reconnects, which happens automatically. If it doesn't reconnect after a while, restart Vesktop. |
| 録画しているときに加える文 | 切れている間の映像と声は録画されません。 | The recording won't include video or voice from the period when Vesktop was disconnected. |

同じ原因のメッセージは 1 件にまとめて件数を見出しに入れ (「画面共有の映像が届いていません (2人)」)、誰なのかは参加者の行が表す。レベル 1 が 2 件以上あるときは、1 行目の見出しの後ろに残りの件数 (「(ほか2件)」/ "(+2 more)") を添える。メッセージのテキストは、ほかのメッセージがあるかどうかで変えない。不具合の報告先は書かない (「手順書の書き方」)。メッセージが消えるときと既読の付き方は「メッセージのレベルと表示方法」にある。

狭いドックでは、1 行目に入らない見出しがある (1 行目の文字の大きさは「1 行目」にある)。末尾を省略すると問題を表す語 (打ち消し、「上書き」、「違い」) が落ちる見出しには、短い形を持たせる (キーは見出しの「もの」に `_short` を付ける。一覧は `src-obs/ledger/rules_dock.cpp` の `kShortHeadlines`)。

- 問題を先に書いた自然な文にし、名詞で止める形と、コロンで区切ったラベル (「追加失敗:」) にしない。
- 20 em の幅に入る長さにする。入る自然な文がないときは、初めてドックを表示するときの幅 (26 em) に入ればよい。
- 状態タブのメッセージに見出しの全文が表示されるので、主語 (「Vesktopの」「cordmuxの」) は、見出しと本文から指す物が分かるときは省く。OBS にも同じものがある語 (録画、シーン、設定) は、同じメッセージの中に OBS の物が出てきて紛れるときだけ、cordmux を省かない。
- 日本語の打ち消しの文は、述語の前に助詞を 1 つ残す (「Vesktopに追加されていません」)。述語だけだと、さらに狭い幅で「追加されていま...」と逆の意味に読める。
- 事実を変えない (「新しい」や人数を落とさない)。語順で問題を先に書けるメッセージでは、その言語の短い形を全文と同じにする (英語の多くのメッセージ)。見分ける必要のある 2 つのメッセージ (作成待ちと作成の失敗) は、短い形も別のテキストにする。

### 確認と結果のダイアログ

ダイアログを表示する場合と、ダイアログの見た目とふるまいは、「ダイアログ」にある。この節には、確認と結果のダイアログの文言を書く。

確認のダイアログのタイトルは操作の名前、主文は「〜しますか？」の 1 文 (「〜してもよろしいですか」と "Are you sure" は使わない)、ボタンは主文に答える動詞 ([アンインストール] [切り替え]) と [キャンセル] にする。補足には、判断に必要なことだけを、削除するもの、元に戻すもの、残すもの、この後にする作業の順に書く。削除と復元を 1 つの箇条書きに混ぜず、3 つ以上並ぶものは箇条書きにし、ボタンの説明はしない。既定のボタンと Esc は [キャンセル] にする。

結果のダイアログの主文には、結果か次にすることを書き、利用者の作業が残る操作を「〜しました」と完了したように書かない (「OBSを終了してから、cordmuxのフォルダーを削除してください」)。場所は文の中に入れず、場所の行に置く (「ダイアログ」)。途中で止まったときは、残ったものを「確認できなかったもの」「元に戻せなかった設定」「削除できなかったもの」に分けてこの順に並べ、次の操作をまとまりごとにその直後に置く。OBS を終了する前にする作業を先に読ませるためである。確認できなかったものを「残っています」と書かない。ボタンは [OK] だけにする。

### エラーと押せない理由

失敗のダイアログは、タイトルを操作の名前にし、主文を「〜できませんでした」の 1 文 (句点なし) にする (「診断情報をエクスポートできませんでした」/ "Couldn't export diagnostics")。「〜に失敗しました」「エラーが発生しました」で済ませず、英語を "Error:" で始めない。補足には、分かるなら理由を利用者の語で 1 文と、次の操作を 1 文書く (「選んだフォルダーに書き込めません。別のフォルダーを選んで、もう一度お試しください。」)。理由が分からないときは次の操作だけを書き、Qt のエラーの文 (`errorString()`) は表示しない。

押せない理由は、押せないボタンのすぐ下か横に、理由と押せるようになる条件を 1 文ずつ書く。条件は利用者がすることで書き (「配信中はアンインストールできません。先に配信を終了してください。」)、「〜してから押してください」とは書かない。待つほかに手がないときは理由の 1 文 (「...の状態を確認しています。」) だけにし、「お待ちください」を加えない。指す人は名前で書き (「「はなこ」の声は、既に「たろう」の行で使っています。」)、OBS の録画と cordmux の録画のどちらのためかで文を分ける。全員に共通の理由も一覧の上に書かず、1 行目やメッセージが伝えている理由と同じく、ツールチップとアクセシブルな説明にだけ入れる。押せないボタンは、位置が変わって押し間違いを生むので隠さない。

### ツールチップとアクセシブル名

ツールチップには、ラベルに入らない情報だけを、です・ます の 2 文までで書く (「画面共有の音声の同期オフセット」のツールチップは「正の値で音声を遅らせます。」)。省略されたテキストの全文はツールチップに表示するが、押せない理由や警告をツールチップだけに置かない。参加者の行の状態のツールチップには、枠に何が映っているかの 1 文を加え、「配信には」ではなく「枠には」と書く (「枠には、最後に届いた映像が止まったまま映っています。」)。

アクセシブル名には「誰の」「何の」を入れ、ウィジェットの種類は入れない。見えているテキストがあるときは、名前をそのテキストで始める (WCAG 2.2 の Label in Name)。

| ウィジェット | 名前 | 説明 (accessible description) |
|---|---|---|
| 参加者の行のチェック | 見えている人の名前 | 「枠に載せる」/ "Add to slot" と、行の 2 行目、状態のツールチップと同じ文 |
| 参加者の行の [...] | 「その他の操作 (たろう)」/ "More actions for Taro" | |
| 下のバーの [...] | 「その他の操作」/ "More actions" | |
| 参加者の一覧 | 「参加者」/ "Participants" | 枠がすべて使用中のときは、その理由 |
| ドックのスクロール領域 | ドックのタイトル「cordmux」 | 付けない |
| cordmux の録画のボタン | 見えているテキスト | 「画面共有と声を、参加者ごとに別のファイルに録画します。」 |
| 1 行目 | 見出しの全文か要約 | 「状態タブを開きます。」 |
| タブ | 見えているテキスト (件数を含む) | |
| 状態タブのメッセージ | 見出し | 影響 |

参加者の行のチェックの名前は、人の名前だけにする。「たろうを枠に載せる」にすると、チェックが付いた状態で操作の名前と状態が混ざって読まれる。

### Vesktop のプラグインの説明

Vencord のプラグインの一覧に表示される説明 (`src-vencord/index.ts` の `description`) は、英語の 1 文と日本語の 1 文を 1 つの文字列に並べる。Vencord の画面は英語だけなので、英語を先に置く。語は cordmux の画面の語 (Vesktop、画面共有、声、OBS) だけを使い、英語の文を小文字の cordmux で始めない。止め方の案内は加えない (止め方はドックのメニューが伝える)。日本語の文は、画面の文字列と同じく「表記」のルールに従う。

## 表記

画面の文字列と手順書の表記は、次のとおりにする。Microsoft の日本語のスタイルガイドに従い、空白と疑問符だけは OBS と Discord の画面に合わせる。

- 常用漢字表にない漢字はかなで書く (つながる、そろう)。形式名詞、補助動詞、接続詞と一部の副詞はかなで書き (こと、とき、もの、ため、ほか、〜てください、できる、ない、および、または、すべて)、中身のある語 (時刻、場合、表示) と副詞の「既に」は漢字で書く。慣用の言い回しは漢数字で書く (一度、一時的に)。
- 英語の -er、-or、-ar で終わる語には「ー」を付ける (フォルダー、サーバー、ユーザー)。OBS が画面に名前として表示するものは OBS の表記にする (フィルタ、プロパティ、エンコーダ、リプレイバッファ)。カタカナの複合語の間に空白を入れない (フォントサイズ、シーンコレクション)。
- 半角の英数字と全角の文字の間に空白を入れない (「OBSの」「%1人」)。現在の書き方は `test/lint/ja_style.txt` の `spacing` の値で持つ。ただし、OBS の一覧の名前の末尾の番号の前 (「cordmux 2」)、数字と半角の単位の間 (「500 ms」「60 FPS」)、半角の括弧と [ ] の外側 (「通話中 (4人)」「[OK] を押します」) には空白を入れる。「%」と全角の単位は詰め (「50%」「30分」)、括弧と「」の内側、「、」「。」に接する側、「？」「:」「...」の前、範囲の「1-4」、「有効/無効」、「1920x1080」には空白を入れない。全角の空白は使わない。
- 文として読ませるもの (メッセージの本文、押せない理由、補足、ツールチップ、空の一覧の文、手順書の地の文) は、1 文でも最後まで「。」で終え、英語は "." で終える。ボタン、ラベル、見出し、チェックボックス、選択肢、状態の値、メッセージの見出し、述べる形のダイアログの主文には句点を付けない。句点は ini の値に書き、コードで加えない。
- 語は「、」で並べる。画面の文字列では中黒「・」を使わず、「/」は対になる語 (有効/無効) だけに使う。3 つ以上の手順と、削除するものや残すものの一覧は行を分ける。英語で 3 つ以上を並べるときは、最後の and か or の前にカンマを置く。
- 括弧は半角の ( ) を使い、入れ子にしない。括弧に入れるのは補足だけで、利用者がすることとパスは入れない。
- [ ] は押す、選ぶ、入力する UI 要素の名前に使い、ボタン以外は後ろに種類の語を付ける ([詳細設定] ページ、[表示] タブ、[枠に載せる人の選び方] 欄)。「」は画面の文、状態の値、入力する文字、シーンやファイルの名前、手順書の節の名前、文の中の人の名前に使う。『』は使わない。英語は [ ] と ASCII の "..." を使い、左右の形が違う引用符は使わない。
- ini の値と手順書に書く省略記号は半角のピリオド 3 つ「...」にし、1 文字の三点リーダーは書かない。使うのは、さらに入力が必要なボタンとメニュー項目と、進行中の表示だけである。Qt がテキストを省略したときの記号と、名前ラベルで名前を省略したときの記号は、Qt が描画するままにする。
- 感嘆符は使わない。日本語の疑問符は全角の「？」、英語は "?" にする (`test/lint/ja_style.txt` の `question`)。
- 入力欄のラベルの後ろにコロンを付けない。文の中の「名前: 値」は、半角のコロンの後ろにだけ空白を入れる (「声: はなこ」)。
- 範囲は半角のハイフン (「1-4」) か「から」で書く。波ダッシュ、em ダッシュ、横線は使わない。状態を 1 行に並べるときは、前後に空白を入れた「 - 」でつなぐ。
- 数は半角の算用数字で書き、1 桁も半角にする。数え方は、人は「人」、枠は「つ」、ファイルは「ファイル」、場所は「箇所」、順番は「番目」にする。4 桁以上の数は 3 桁ごとにカンマで区切り (「1,024」)、年、解像度、ポート番号、ID、バージョンには使わない (`src-obs/ledger/rules_dock.cpp` の `group_digits()`)。
- 単位は入力欄の後ろと文の中で同じ記号にする (ms、px、FPS、GB、MB、%)。英語の時間は、文の中では "seconds" "minutes"、入力欄の後ろと「名前: 値」の値では "min" と書く。容量は 1024 の累乗で計算し、小数 1 桁で書く (「1.5 GB」。Windows のエクスプローラーと同じ数になる)。足りない量は小数 1 桁へ切り上げる。少なめに表示すると、空けた後もまだ足りないことがある (`src-obs/ledger/rules_dock.cpp` の `byte_size_1024()`)。解像度は「1920x1080」、フレームレートを添えるときは「1920x1080 (60 FPS)」と書く。
- 日付は Windows の地域の設定の短い形にし (Qt の `QLocale` に任せ、ini に書式を書かない)、時刻は時と分にする。日本語の画面では 24 時間制にする。秒はログと診断情報にだけ書く。今日でない日の時刻には日付を添える。
- 差し込む人の名前に「さん」を付けない。名前の後ろに助詞を直接続けず、文の中では名前を「」で囲む (「「%1」の声は、既に「%2」の行で使っています。」)。名前だけで意味が通る所 (「声: %1」) と英語では囲まない。
- 製品の名前は、cordmux (常に小文字)、OBS (必要なものの一覧では OBS Studio)、Discord、Vesktop、Vencord、Windows、FFmpeg と書き、カタカナにしない。英語の文は cordmux で始めず、主語をほかのものにするか "The cordmux ..." と書く。ボタン、ラベル、OBS の一覧の名前、状態の値は cordmux で始めてよい ("cordmux is disabled")。
- 英語の Title Case は、ボタン、メニュー項目、ページ、見出し、入力欄のラベル、表の列の見出し、タイトル、OBS の一覧の名前、1 語から 3 語の名前だけの選択肢に使い、ほかは sentence case にする。OBS の英語の画面がこう分けているので合わせる。Title Case の書き方は、Microsoft Writing Style Guide の title-style capitalization に従う。
- 英語の文の中では短縮形を使い (can't、isn't、couldn't)、ラベルとボタンには使わない。"please"、"simply"、"easily" は書かない。"(s)" で単数と複数を兼ねない (「ini のキーの書式」)。
- 文の断片をコードでつながない。区切りの「 - 」や「: 」も含め、画面に表示する形のまま 1 つの文字列として ini に置く。翻訳する人が見る単位を途中で割らないためである。値が読めないときは「-」を差し込まず、その値を含まない別の文字列にする。

## 文字列の確認

新しい文字列と変えた文字列は、次の順に確認する。

1. lint を実行し、エラーを修正する。
2. UI 要素の種類の形に合っているか、1 語ずつ OBS・Discord・Windows の画面にある語かを見る。それらの製品で同じ場面に使われている文字列も探して並べる。
3. 内容を確認する。テキストが表す状態と cordmux が観測していることは同じか。語が断定していることはコードのふるまいと合うか。済んだことと利用者の作業が残っていることを分けたか。削除する、元に戻す、削除しない、確認できなかった、を分けたか。何の状態か、何の数かが読めるか。何が続き何が止まるかをコードで確認したか。日本語と英語で伝える中身が同じか。

## lint でチェックする記号と表記

画面の文字列の記号と表記は、`test/lint/forbidden_ui_words.py` が ini の値に対してチェックする (キーとコメントは見ない)。

- `test/lint/forbidden_ui_words.txt` は、画面に表示されたら直す記号と表記の一覧で、一致すると lint がエラーになる。使わない記号、長音と OBS が表示する名前の表記の誤り、内部の語と番号、空白の誤りがある。
- `test/lint/ja_style.txt` は、日本語の表記の 2 つの設定 (`spacing` は英数字と日本語の間に空白を入れるか、`question` は疑問符を全角にするか) と、その例外のキーを持つ。一覧の行のうち、先頭に `spacing=` か `question=` の指定がある行は、この値と合うときだけ使う。書き方を替えるときは、`test/tools/wording/apply_ja_style.py` で ini の値とこのファイルを一緒に書き換える。

一覧の行は Python の正規表現 (`re.ASCII`) で、行の先頭の指定で使う範囲を絞れる (`ja:` と `en:` は言語、`not_names:` は OBS の一覧の名前のキーを除く)。行の書き方は `forbidden_ui_words.txt` の先頭のコメントにある。`forbidden_ui_words.txt` の一部は、手順書のチェック (`test/lint/install_guide.py`) とリリースノートのチェック (`test/tools/dist-zip/make_release_notes.py`) にも使う。行を追加するときは、正しい書き方の例を `test/lint/fixtures/forbidden_ui_words/good` に追加して `--selftest` を実行する。

## ini のキーの書式

画面の文字列は、Vencord のプラグインの説明を除いて `src-obs/data/locale` の `ja-JP.ini` と `en-US.ini` に置く。`ja-JP.ini` と `en-US.ini` は同じキーの集合を持ち、キーの形は `cordmux.<画面>.<もの>.<種類>` である。

- 画面は、`dock` (ドック)、`look` (ドックの表示タブ)、`status` (ドックの状態タブ)、`settings` (設定ウィンドウと OBS の [ツール] メニューの項目)、`participants` (参加者の設定ウィンドウ)、`dialog` (ダイアログ)、`source` (ソースの種類と名前、ソースのプロパティ、録画ファイルの名前の語)、`plugin` (プラグインの説明) のどれかにする。
- ものは snake_case の英語で書く。短い形のキーは、元のキーのものの後ろに `_short` を付ける (`cordmux.dock.vesktop_not_added_short.headline`)。
- 種類は、UI 要素の種類を表す次の 14 の語のどれかにする。`test/lint/locale_shapes.py` が、種類ごとに値の形を確認する。

| 種類 | UI 要素 | 値の形 |
|---|---|---|
| `button`、`menu` | ボタン、メニュー項目 | 句点と「です」「ます」「ください」で終えない。英語は Title Case。末尾の「...」は日本語と英語でそろえる |
| `page`、`heading`、`title`、`label` | ページ、まとまりの見出し、タイトル、入力欄のラベルと単位と OBS の一覧の名前 | 句点を付けない。英語は Title Case |
| `option` | 選択肢 | 句点を付けない。英語の大文字は、選択肢の全体で決める |
| `check` | チェックボックス | 句点を付けない。英語は sentence case |
| `status`、`headline` | 状態の値と 1 行目の要約、メッセージの見出しとダイアログの主文 | 句点を付けない (です・ます で終えてよい)。英語は sentence case |
| `text` | メッセージの本文、補足、押せない理由、ダイアログの補足 | 句点か疑問符で終える (「:」で終わる前置きと「...」で終わる進行中の文を除く)。箇条書きの項目 (ものが `_item` で終わる) は句点を付けない |
| `tip`、`empty` | ツールチップ、空の一覧の文 | 句点で終える |
| `a11y` | アクセシブル名と説明 | 英語は sentence case |

`headline`、`text`、`tip`、`empty` の英語の文は sentence case で、cordmux で始めない。

数で形が変わる文字列:

- 英語の形が数で変わる文字列 ("1 person" と "2 people") は、数がちょうど 1 のときのキーを組で持つ。名前は元のキーの後ろに `_one` を付け (`cordmux.dock.summary_call.status_one`)、日本語の ini にも置く。日本語の値は元のキーと同じでもよく、数で語が変わるとき (「この」と「これらの」) は違ってもよい。
- コードは、数がちょうど 1 のときだけ `_one` のキーを使い、0 と 2 以上では元のキーを使う (英語では 0 も複数の形)。組は `CountedId` (`src-obs/ledger/plural.h`) で持ち、`pick()` でしか選べないので、`_one` の行がないキーで `_one` を引いてキーがそのまま画面に表示されることはない。
- `_one` の値は、元のキーと同じ番号の `%N` を同じ数だけ持つ。
- 1 つの文字列に、後ろの語の形を決める数を 2 つ置かない (キーが 4 つ必要になる)。片方を、数が後ろに来る形か、数で形が変わらない単位の記号 ("Elapsed: 12 min") にする。数が単位の記号や「名前: 値」の後ろに来るだけの文字列 ("60 FPS") には、`_one` を作らない。

`%N` を持つキーの行の真上のコメントには、`%N` ごとに `%N=中身` の形で何が入るかを書き、日本語と英語で `%N` ごとの数を同じにする。コードは `src-obs/ledger/text_ids.h` の定数でキーを指し、定数の名前はキーから決める (`cordmux.dock.summary_call.status` は `kDockSummaryCallStatus`)。`test/lint/locale_ids.py` は、コードが指すキーと ini のキーを両方向に突き合わせ、2 つの ini のキーの集合、`_one` の組、`%N` の数とコメントを確認する。

## 手順書の書き方

手順書は `guide/ja.md` と `guide/en.md` (Markdown) である。利用者は、GitHub で読むか、配布用の zip の中の `はじめに.txt` と `README-en.txt` (Markdown から生成したテキスト) を読む。`test/lint/install_guide.py` が、`test/lint/install_guide_rules.txt` のルールでチェックする。zip の中のテキストの作り方は dist/README.md の「手順書の形」にある。

### 読み手と、読む場面

- 読み手は OBS で配信している人である。OBS のシーン、ソース、ドックは知っている。Vesktop は知らないことがあり、Vencord と cordmux の仕組みは知らない。OBS と Discord そのものの使い方は説明しない。
- 読み手は、インストールの日、配信の前、困ったとき、更新とアンインストールの日に、別々に開く。困ったときは、ドックのメッセージや検索から、項目に直接来る。1 回で全部を読む人はいないので、どの節と項目も、そこだけで分かるように書く。
- 読み手は走査し、知りたいことが見つかった所で読むのをやめる。節と項目の最初の文に、読み手がそこで求めることを書く。冒頭に置いたものは最も重要なことと受け取られるので、文書と節の冒頭に、仕組みや語の定義を並べない。
- 読み手が聞かなくても伝えること (Vesktop の設定を書き換えること、映像と声が同じ PC のほかのプログラムから読まれうること) は、冒頭ではなく、それが関係する所 (「始める前に」と、その操作の手順) に、元に戻す方法と組で短く書く。

### 節

タイトルは「cordmuxのインストールと使い方」/ "Installing and Using cordmux" にする。タイトルの下に、何をするプラグインかの 1-2 文、この説明書に何があるかの 1 文、節の目次 (リンク) を置く。節は次の 9 にし、この順に並べる。

| ja | en | 書くこと |
|---|---|---|
| 始める前に | Before You Start | 必要なもの (1 行に 1 つ、名詞で始める。動く最低の条件 (OBS のバージョンの下限) を書き、保証や約束、動作確認した環境は書かない)。通話のほかの参加者は何もしなくてよいこと (定型文。`install_guide_rules.txt` の `contains:`)。2 つの使い方のどちらにするかの決め手 (通話に Vesktop と公式の Discord アプリのどちらで参加するか)。cordmux が変えるものと、安全について |
| インストール | Installation | 冒頭に、終えると何ができるかを 1 文。手順は `### 1.` から `### 4.` の見出しにする |
| 配信のたびにすること | Each Time You Stream | 配信のたびに行う操作を、行う順に 4 つまでの番号で |
| 使い方 | Using cordmux | 機能ごとの `###` の項目。見出しは、読み手がしたいこと (「枠に載せる人を選ぶ」) か、知りたい話題にする |
| 困ったとき | Troubleshooting | 症状ごとの `###` の項目 |
| 更新 | Updating | 新しいバージョンに入れ替える手順 |
| アンインストール | Uninstalling | 取り除く手順 |
| 互換性 | Compatibility | OBS、Vesktop、Discord が更新されると動作しなくなることがある、の 1 文 (リリースノートにもそのまま載る) |
| ソースコードとライセンス | Source Code and Licenses | ソースコードの入手先とライセンス |

画面の文言は、手順書の見出しを名前で指している (「インストール」の手順2、「通話の声が二重に聞こえる」、「アンインストールが途中で止まった」)。これらの見出しの名前と手順の番号は変えない。変えるときは、ja-JP.ini と en-US.ini の文も一緒に直す (`install_guide.py` が、ini から手順書への参照が実在する見出しを指すかを照合する)。

### 手順の書き方

1. 1 つの番号に 1 つの操作を書き、場所を先に書く (「ドックの [Vesktopに追加] を押します。」)。操作するアプリや場所が変わる所では番号を分ける。番号付きの項目は入れ子にしない (GitHub は入れ子の番号を別の形で表示する)。補足は、番号の下に「- 」の箇条書きを 1 段だけ置く。「配信のたびにすること」の番号は 4 つまでにする。
2. 文末は「〜します。」にし、「〜してください。」は注意 (「〜しないでください。」) とほかの節への案内だけに使う。
3. ボタンは「押します」、メニュー項目と選択肢は「選びます」、チェックボックスは「チェックを付けます」「チェックを外します」、入力欄は「入力します」にする。「クリック」は使わない (「右クリック」と「ダブルクリック」はよい)。英語は select、select the ... check box、clear the ... check box、enter にする。
4. UI 要素の名前は [ ] で、画面に表示される文は「」で、ini のテキストのまま書く (ボタンの末尾の「...」は省く)。画面の文の一部の語 (「Vesktop側のcordmux」) を引用するときも、ini にある語のまま書く。
5. 条件のある手順は、条件を番号か段落の先頭に書く (「サブアカウントを使う人だけ、...」)。条件が操作の後に来ると、条件に合わない人も先に操作してしまう。
6. 手順の最後に、その手順が済んだと分かる表示を書き、すぐ後に表示されないときの行き先を書く (「表示されないときは、「困ったとき」の「...」を見てください。」)。済んだと分かる表示は、手順が実際に済んだことを示すもの (cordmux の録画なら保存先のファイル) にし、ボタンのテキストが替わったことや、表示が消えたことだけで済んだとしない。
7. 手順と OBS の画面の文字列は、最新の OBS のものだけを書く。OBS のバージョンで分けた手順は書かない。分けると手順が読みにくくなり、古いバージョンの分は使う人が減っていくためである。最新の OBS がどれかは「必要なもの」に 1 行で書く。
8. 番号の中には、操作と、操作に要る条件、済んだと分かる表示、うまくいかないときの行き先だけを書く。機能の説明と、操作の後に起きることの細かい決まりは「使い方」に書く。語の定義は、初めて使う所に短く書く。手順の途中に説明が挟まると、操作の流れを追いにくい。
9. まれな場合の手順 (ポータブル版の OBS、管理者の権限がない場合) は、本筋の手順の後に段落を分けて置く。本筋の番号の中に混ぜない。

「配信のたびにすること」には、毎回しないと元に戻るもの (cordmux の録画は、OBS を起動するたびに止まった状態に戻る) を必ず入れ、手順に必要な前提 (相手が画面共有していること) は、その操作の前に書く。

「困ったとき」の項目の見出しは、利用者が見る症状にし (「ドックが表示されない」)、ドックに表示される文は「」のまま書く。各項目には、症状の見分け方と、試すことを試す順に、それが必要な条件を添えて書く。OBS が表示するダイアログ (セーフモードで起動するかの問い) で起きることも症状として置く。診断情報のエクスポートは、修正する手順ではなく、何が起きたかを残す操作として書く。

不具合の報告先と問い合わせ先 (GitHub の Issue、作者の連絡先) は、手順書にも、画面にも、リリースノートにも書かない。診断情報は、エクスポートできることと中身だけを書き、「作者に送ってください」と書かない。送り先のない指示を読んでも、次にすることが分からない。

英語の手順書は、節、項目、番号の数を日本語と 1 対 1 にし、英語として書く。命令形で場所を先に書き ("In the dock, select [Add to Vesktop].")、Windows の項目は英語の Windows のテキストのまま書く。

### 形式

- Markdown は手で折り返さず、1 段落を 1 行で書く (箇条書きと番号付きの項目も 1 項目 1 行)。日本語の段落の途中の改行は、ブラウザーによっては空白として表示される。表示のときの折り返しは、GitHub の表示やメモ帳などの、読む側の設定に任せる。zip の中のテキストも、生成するツールが 1 段落を 1 行のまま書く。
- ほかの節への案内は、見出しへのリンクにする。zip の中のテキストではリンクが外れるので、リンクの前に節の名前を書く (「「困ったとき」の「[...](#...)」を見てください」)。
- 使える記法は、見出し (`#` `##` `###`)、段落、箇条書き (入れ子は 1 段)、番号付きの項目、パスとファイル名のインラインのコード、リンクだけにする。太字と強調、表、画像、HTML は使わない (zip の中のテキストで読めないため)。
- バージョンごとに変わる値 (ソースコードの URL) は書かず、`<!-- zip:source_url -->` の印だけを置く。zip の中のテキストを作るときに、印がその値の 1 行に置き換わる。公開の前に埋める仮の文字列は、`install_guide_rules.txt` のルールに従う。

## 見た目とふるまい

### ドックの構成

警告と状態は全部ドックに表示する。ドックと cordmux のウィンドウは音を鳴らさない (デスクトップの音を取り込んでいる OBS では、その音が配信に入る)。ドックは、配信者が配信画面を見ながら片手で操作する場所である。視界の端で短く見られるので、その見方でも読み取れる形を先に決める。

ドックの設計は次の原則で判断する。

| 原則 | 理由 |
|---|---|
| 操作する要素の位置を、メッセージや外部の出来事で動かさない | 押し間違いは配信に直接出る |
| 1 つの事実は 1 か所に置く。行で分かることを 1 行目で繰り返さない | 本当に重要な表示が目立たなくなる |
| 赤は、今の配信か録画が損なわれていて、今できることがあるときだけに使う | 何もできない物が赤く出続けると、次の問題に気付けない |
| 配信中に映像や音を確認しながら触る物はドックに置き、すぐ反映する | [適用] を押してウィンドウをどける手順は配信中に使えない |
| 毎回使う物は固定の位置に置く | サブアカウントを一覧から探さない |
| スクロールの操作で値を変えない | ホイールで一覧を動かしただけで配信の音が変わるのを防ぐ |
| 確認は操作の重さで決め、確認するのは配信中の [退出] だけにする | 戻せる操作 (チェック、ミュート) は、間違えても戻せる。配信中の [退出] は、全員の映像と声が止まる |
| 最悪の条件で確認する | 平常の 4 人の画像では見えない。30 人、235x300、メッセージの重なり、途切れの繰り返しで見る |

```
+------------------------------------------+
| 1 行目 (高さ固定、折り返さない)          |
| メイン  名前      通話の名前      [変更] |
| サブ    名前      通話の名前 [移動][退出]|
+------------------------------------------+
| 参加者 | 音声 | 表示 | 状態 (件数)       |
+------------------------------------------+
| タブの中身 (ここだけスクロールする)      |
+------------------------------------------+
| [録画を開始]                        [...]|
+------------------------------------------+
```

- 1 行目、メインとサブの行、タブ、下のバーの高さと位置は、何が起きても変えない。メインアカウントだけの構成では「サブ」の行がない。これは利用者が選んだ構成なので、変わるのは [変更] を押したときだけである。
- タブは [参加者] [音声] [表示] [状態] の 4 つで、幅を同じにする。件数の表示でタブの幅を変えない。開いているタブは保存し (`dock_tab`)、次の起動でも同じタブを開く。
- スクロール領域はスクロールバーの幅を常に確保する。

#### 1 行目

1 行目はボタンで、押すと状態タブを開く。本文と操作のボタンは 1 行目に置かず、状態タブに置く。1 行目は次の順に 1 つを選ぶ (`src-obs/ledger/notice_tracker.h` の `settle_first_line()`)。

| 順 | 中身 | 見た目 |
|---|---|---|
| 1 | レベル 1 のメッセージの見出し | 危険の色の背景と、円の中に x |
| 2 | 「cordmuxは無効です」 | 色なし。[有効にする] を右端に置く。幅によらず必ず表示する。無効の間は、未読のレベル 2 を既読にしない |
| 3 | 未読のレベル 2 のメッセージの見出し | 色なしで、三角の中に ! |
| 4 | 「全画面: (名前)」(1 人を全画面で表示している間。名前は配信に出している名前) | 色なし。[元に戻す] を右端に置く (2 の行と同じ作り)。ボタンの短い形は持たず、幅が足りないときはテキストを省略する (1 行目の倍率 `first_line_scale` を本文より大きくしているときは、先に本文の大きさにする) |
| 5 | 「ダミー映像を表示中」 | 色なし |
| 6 | 状態の要約 | 色なし |

1 行目のテキストは本文と同じ大きさ (1 em。メッセージの見出しは太字、平常の状態は普通の太さ) にする。OBS のテーマの文字の大きさの段 (`--font_base` 1、`--font_large` 1.1、`--font_xlarge` 1.5) のうち、1 行目に出うる見出しと状態の文 (プレビューツールの場面の 64 通り) が初めてドックを表示するときの幅 (26 em) で省かれずに全文が入る割合が、いちばん高い段である (1.5 で日本語 52%・英語 45%、1.1 で 80%・70%、1 で 88%・80%)。太字は、メッセージの見出しを平常の状態の文と見分けるために残す (状態タブのカードの見出しと同じ見た目になる)。

高さは空のときも 1 行分を取って変えず、折り返さない。幅が足りないときは後ろの「 - 」の区切りから丸ごと落とし、最初の区切りも入らないときだけ末尾を省略する。数と人数の語、英語の短縮形、日本語の打ち消しの述語の途中では省略せず (`src-obs/dock/ui/dock_ui_calc.h` の `safe_cut()`)、残りの件数「(ほか2件)」は落とさない。見出しが入らないときは短い形を表示する。全文は状態タブのメッセージと、ツールチップとアクセシブル名に入れる。

#### メインとサブの行

- 通話の名前が分からないときは「-」、接続していないときは「未接続」、通話に参加していないときは「通話なし」と表示する。サブアカウントがメインアカウントと別の通話に参加しているときは、通話の名前を注意の色にする。
- ボタンは常に同じ位置に置き、使えないときは押せない表示にして、ツールチップで理由を出す。
- [移動] は、サブアカウントをメインアカウントがいる通話へ移動する。移動先はメインアカウントがいる通話だけで、別のサーバーでもサブアカウントがそのサーバーにいれば移動できる。入れないときは押せない。自動では動かない。
- [退出] は、サブアカウントを通話から退出させる。全員の映像と声が止まるので、配信中だけ確認する。押した場所の隣で [退出] と [通話を続ける] (英語は Leave と Stay in Call) に変わる。やめる側は、押した結果が分かる [通話を続ける] にする。[配信中の退出を確認] (`confirm_while_streaming`。既定はオン) で切り替える。フォーカスを奪うのでダイアログにしない。
- [変更] は、通話中の人と過去の参加者から選ぶメニューを開く。「メインアカウントを使わない」も選べる。ユーザー ID は入力させない。
- サブアカウントは参加者の一覧に出さない。

#### 参加者タブ

```
枠3/4
[ ] (A) メインの名前 [メイン]    [M]     [...]
画面共有中 (3)
[x] (A) hanako       (位置) [M] [S]      [...]
[x] (A) Taro  映像途切れ (位置) [M] [S]  [...]
通話中 (2)
[ ] (A) kenji               [M]          [...]
```

- 上の 1 行 (枠の数) はスクロールしない。
- メインアカウントの行を先頭に固定する。[先頭に配置] が付いている (既定) 間は、枠でも左上 (名前順と載せた順で、メインアカウントの画面共有を先頭に置く。自分の枠があればその次) なので、順序が一致する。外すと、枠では並び順の位置になり、一覧の行は先頭のまま変えない。メインアカウントだけの構成では、Vesktop のアカウントの行をここに置く。
- その下を「画面共有中 (N)」と「通話中 (N)」の 2 組に分ける。組の中は表示名の自然順である。上部だけ見れば共有している人が分かる。
- 通話から抜けた人は、枠を持っていた人も、声の枠だけを持っていた人も、一覧にも音声タブにも出さない。枠を持つのは画面共有している人だけで、画面共有をやめるか通話から抜けると枠が空くためである。Vesktop のアカウントが通話を抜けたときも、全員の枠が空く。
- 画面共有していない人のチェックは押せず、薄く表示し、ツールチップは「画面共有していません。画面共有を始めると載せられます。」にする。Vesktop のアカウントの行と自分の枠のチェックは別の意味で、この規則に従わない。
- 共有の開始と終了で、行は組の間を移る。ポインターが一覧の上で動いている間は保留し、ポインターが止まって 2 秒たったら反映する (`layout_hold_idle_ms`。settings.json でだけ変えられる)。ボタンを押している間とメニューを開いている間は保留を続ける。操作とフォーカスは行の位置ではなく人に結びつけ、表示された直後と動いた直後のボタンとチェックは、Windows のダブルクリックの時間 (既定は 500 ms) の間、クリックを受け付けない。
- Vesktop との接続が切れても行を消さず、切れる前の組のまま薄くして押せなくする。行の状態は出さない。
- 行の状態は「映像途切れ」などで、1 行目には出さない。誰か 1 人の映像が止まったことは、行と OBS の映像で分かる。
- 画面のアイコンの中の四角で枠の位置 (左上、右上、左下、右下、全面) を示す。枠に載っていない共有中の人は四角なしのアイコンにする。位置は配信の並びと同じ関数で決める (`src-obs/ledger/slot_cells.h` の `plan_slot_cells()`)。
- アバターは 20 px で、名前ラベルに渡している画像を使う。なければ色の丸と頭文字にする。幅が足りないときは最初に省く。
- [メイン] と [自動] の小さなタグを名前の右に置く。[自動] は [自動で枠に載せる] が付いている人である。
- マイクのボタンは、話している間は緑の縁と緑のアイコン (配信に出ている声だけ)、ミュートは赤い斜線、まだ声が届いていない人は薄くして押せなくする。これ以外は灰色にする。
- スピーカーのボタンは、共有していない人には場所だけ取って表示しない。ミュートは赤い斜線にする。届いているが出していないことは音声タブの灰色のメーターで分かる。
- 押せるボタンには背景を付けて、押せないアイコンと区別する。
- 枠が埋まっているとき、載っていない人のチェックは薄くする。押すと「入れ替える相手」のメニューを開き、選ぶと 1 回で入れ替わる (`ActionId::ReplaceSlot`。途中の並びが配信に出ない)。
- 「空いている枠がありません」の文は一覧の上に出さず、チェックのツールチップにする。
- 行のメニュー ([...]) は「自動で枠に載せる」「全画面で表示」「名前を変更...」「使う声」にする。音量は音声タブに置く。「全画面で表示」はチェックの付く項目で、cordmux のソースに今映っている人 (自分の枠を含む) と、画面共有している人の行でだけ押せる (枠に載せていない人を全画面にすると、受信を始めて映像が届いてから切り替わる)。ほかの行でも項目は出し、押せなくする。その人を全画面で表示している間はチェックが付き、押すと元に戻す。押せないときは、「自動で枠に載せる」と同じく理由をツールチップに表示する (「画面共有している人と、cordmuxのソースに映っている人だけを、全画面で表示できます。」)。
- 2 行目 (補足の文字色) は、利用者が付けた値 (cordmux での名前、使う声) があるときと、同じ名前の人がいるとき (ユーザー名) だけ表示する。
- メインアカウントだけの構成では、Vesktop のアカウントの行に、自分の枠のチェックと、[自動で枠に載せる] だけのメニュー ([...]) を常に表示する。自分の枠に映す映像を OBS から選んでいない間は、チェックを押せず、理由を出す。詳しくは「自分の枠」にある。
- 最初の設定 ([Vesktopに追加] など) は、参加者の一覧が空の間だけ、一覧の場所にも表示する。行がないので何も動かない。[Vesktopに追加] は Vesktop の起動中は押せず、押せない理由 (「Vesktopの起動中は追加できません。先にVesktopを終了してください。」) を状態タブのカードと同じく、ボタンの下に文で出す。

#### 音声タブ

```
hanako   声   [---o-------] 100% [M]
              ||||||......
         画面 [---o-------] 100% [S]
              |||.........
```

- 全員を 1 人 2 行で並べる。順序はメインアカウントが先頭で、ほかは表示名の順にし、組分けしない。高さは共有の有無で変えない。共有していない人の画面の行は「共有していません」と出す。
- 上のつまみが音量 (0 から 200%、ダブルクリックで 100% に戻す)、下のメーターが音の大きさ (-48 dB から 0 dB。緑、黄 -20 dB から、赤 -9 dB から) である。
- メーターは、いつも音量を掛けた後の大きさを出す。つまみを動かして、出力される音がちょうどよくなるように合わせられるようにするためである。
- 音を出している間は配信に出ている値を色付きで出し、ミュート中の行は、ミュートを外したときに出る大きさを灰色で出す。ミュート中に話している人を見て、外すか決められるようにするためである。灰色の大きさは、掛ける前の値に、つまみの音量の利得を掛けた値で、利得はミキサーに渡す値と同じ関数 `config::gain_of_person_volume` で求める。音量 0 は利得 0 なので、灰色のメーターは振れない。
- メーターは音声タブを開いている間だけ動かす (10 回/秒)。マイクの光は参加者タブを開いている間も動かす。
- まだ声が届いていない人の声の行には「まだ声が届いていません」と出す。共有しているが画面共有の音声がない人の画面の行には、「音声がありません」と出す (行の見出しが「画面」なので、「画面共有の」を繰り返さない)。どの文も、つまみの場所に同じ高さで置く。
- 名前の欄の幅は、行の幅から計算し (`calc::name_column_px`)、どの行も同じ幅にする (つまみの位置をそろえる)。余った幅を 3 段で配る。
  1. 狭いうちは、つまみを最小 (3 em) のままにして、名前の欄を最小の 5.5 em から min(全員の名前の全文の幅の最大, 9 em) まで広げる。
  2. 次に、つまみを 3 em からゆとりのある幅 (6 em。0 から 200% を約 80 px で操作できる) まで広げる。
  3. さらに余れば、名前の欄を全員の名前の全文の幅の最大まで広げる (9 em を超えてよい)。残りはつまみが取る。ドックの最小幅は、最小の名前の欄と最小のつまみの和のままで変えない。16 文字ほどの名前が、ドックの幅 26 em で省かれずに出る。名前の欄の幅は、行の追加と削除と同じく、並びの保留の間は変えない (人が入れ替わって全員の名前の最大が変わっても、配信者がつまみを操作している間や、ポインターを一覧に置いている間に、つまみが横に動かない)。保留が解けたときに変える。
- 名前が欄に入らず省かれているときは、名前のラベルのツールチップに全文を出す。省かれていないときは出さない。アクセシブル名は全文。
- パーセントの欄の幅は、ラベルに当たるフォントで測った「200%」の幅にする。
- 1 人の 2 行の見出しは、名前の右の 1 語 (「声」「画面」) にする。「画面共有」と書くと、つまみの幅を最小幅 (266 px) で確保できない。
- 参加者タブと同じ人を出す。Vesktop のアカウントの行 (メインアカウントだけの構成) は、声も画面共有の音声も受信側に届かず、操作しても配信の音に反映されないので、音声タブに出さない。
- 合成のソースがない間は、値が配信の音に反映されないので、行を出さず、一覧の場所に「OBSにcordmuxのソースを追加すると、ここで音量を調整できます。」を出す。行がない間は「参加者の音量とメーターが、ここに並びます。」を出す。
- Vesktop との接続が切れても、参加者タブと同じく行を消さず、薄くして操作できなくする。
- 行の追加、削除、並べ替えは並びの保留に従う。つまみを動かしている間 (マウスのボタンを押している間) は行を動かさず、外からの値でつまみを書き換えない。
- つまみはホイールを受け取らず、スクロールに渡す。クリックと Tab でフォーカスを取り、フォーカスがあるときだけキーで動く (動き方は「コントロールとキーボード操作」のつまみ)。ダブルクリックで 100% に戻す。
- 操作はすぐ反映する (`SetVoiceVolume`、`SetScreenAudioVolume`)。

#### 表示タブ

- 上から「枠」と「名前ラベル」と「話している人の強調」と「ダミー映像」に分ける。「名前ラベル」の組は「名前」「輪郭」「アバター」「背景」「名前ラベル全体」「画面共有している参加者」「画面共有していない参加者」に分ける。
- 名前ラベルの見た目の値 (大きさ、色、輪郭、背景、話している人の光と暗さ、画面共有していない参加者の並び) は、このタブでだけ変える。名前ラベルの位置もこのタブで変える。
- 枠には、[枠に載せる人の選び方]、[並び順]、[間隔]、[自分の枠に映す映像]、[先頭に配置] を置き、その後に小見出し「背景」を置いて、[表示]、[色]、[不透明度] を並べる (映像を描かない所の色。名前ラベルの「背景」と同じ部品、同じ文言、同じ並びで、[表示] がオフの間は [色] と [不透明度] を押せない。既定は表示する)。
- 2 つの「背景」は見出しが同じなので、枠の背景の入力欄のアクセシブル名と色の選択のダイアログのタイトルは、まとまりの名前を「枠の背景」にして (`cordmux.look.slot_background_group.a11y`)、「表示 (枠の背景)」の形で聞き分ける。
- ダミー映像の [表示] は、めったに使わない、表示を確認するための操作なので、いちばん下の組「ダミー映像」に置く。チェックのテキストは、ほかの組と同じく [表示] にし、アクセシブル名を「ダミー映像を表示」にする。
- 見出しは 2 段にする。大きい分類 (枠、名前ラベル、話している人の強調、ダミー映像) の大見出しは、本文の色の 1.1 em の太字 (OBS のテーマの段 `--font_large`) にし、上にはっきりした罫線 (背景との比 3:1 以上。色は OBS のテーマの背景から本文の色の方へ寄せて作る。`ui::calc::rule_color`) を引く。前の行から罫線まで 1 em、罫線から見出しまで 1 em、見出しの下 0.5 em。中くらいの分類 (名前、輪郭、アバター、背景、名前ラベル全体、画面共有している参加者、画面共有していない参加者) の中見出しは、本文の色の 1 em の太字にし、罫線は引かない。上 2.25 em、下 0.25 em。大見出しのすぐ後の中見出しは、大見出しの下の余白だけを空ける。値は `DockStyle` にあり、プレビューツールの `--heading-scale` と `--heading-space` で変えて比べられる。
  - 階層は太さと余白で作り、色の弱さでは作らない。中見出しを補足の色 (Yami では #999999) にすると、項目の名前 (白) より目を引かず、見出しが項目より重要でないと読まれる。Yami では補足の色が押せない部品の文字の色と同じなので、押せない項目の名前とも見分けにくい。
  - 大きさで段を分けるのは大見出しの 1.1 倍だけにする。まとまりの見出しを本文と同じ大きさの太字にするのは、Windows の設定、macOS、GNOME、OBS の `QGroupBox` の題に共通の形で、狭いドックで段を大きさで分けすぎない。
  - 中見出しは、見た目の上の余白 (前の部品の下端から見出しの字の上端まで) を 1 em 以上、かつ見た目の下の余白 (字の下端から次の部品の上端まで) の 3 倍以上にし、見出しを前のまとまりより自分の中身の近くに置く (近接の原則)。中見出しの前には罫線がないので、余白だけで、見出しがどの項目の見出しかが分かるようにする。見た目の余白には、字の上下の空きと部品の中の余白 (チェックボックスの印の上下、コンボボックスと数の入力欄の枠の外) が足されるので、レイアウトの値の比では決めない。レイアウトの下を行の間の 0.25 em にしても、見た目の下は 6-11 px (1 em が 13.3 px のとき) あるので、上を 2.25 em にして見た目で 34-37 px にする。前の行の部品の種類による見た目の違いは 3 px 以内なので、種類ごとに余白を変えない (変えるには部品の種類ごとにテーマの値を読む必要がある)。
  - 大見出しのすぐ後の中見出し (「名前ラベル」の後の「名前」) は、この 3 倍の対象にしない。前にあるのは自分を含む組の見出しで、前のまとまりの項目ではないので、どの項目の見出しかを取り違えない。上を 3 倍にすると、大見出しだけが罫線の近くに離れて残る。
  - 大見出しも、この 3 倍の対象にしない。上のはっきりした罫線が組を分けるので、見出しを中身に寄せなくても、どの組の見出しかを取り違えない。罫線から字までは見た目で 1 em 以上にする (0.75 em では、濁点のある「ダミー映像」で 13 px になり、1 em に届かなかった)。
  - 状態タブの見出しは中見出しと同じ見た目にするが、上は 1 em にする。配信中のドックは縦の場所が限られ、見出しのすぐ下は 1 行の値か表なので、見出しが 4 つ並ぶ状態タブで上を 2.25 em にして表や [映像のバッファ] を下に押すより、狭さを優先する。
  - 中見出しの前の薄い罫線は引かない。中見出しが本文の色の太字になれば、切れ目と何の切れ目かの両方を見出しが示し、罫線は情報を足さない。
- 話している人の強調の中の光り方 (対象から [フェードアウト]) と光る条件 ([自分の枠の音声ソース]、[しきい値]) の間は、見出しのない意味の違う部分の切れ目なので、罫線を引かず 1 em を空ける (見出しがないので、見出しを中身に寄せるための中見出しの上の余白ほどは空けない)。
- ダミー映像の [表示] の下の説明の文は、説明の文の見た目 (「色とフォント」) にし、左端を [表示] の文字の頭 (チェックボックスの四角の右) にそろえる。
- 「名前」「輪郭」「アバター」「背景」(名前ラベルの背景と、枠の背景)「画面共有している参加者」「画面共有していない参加者」の組は、最初の行に [表示] を置く。「画面共有している参加者」は、上から [表示]、[1人のときは非表示]、[位置]、[アバターの位置] にする ([1人のときは非表示] は [表示] と意味が近いので、そのすぐ下に置く)。[表示] を外すと、ほかの 3 つは押せない (並びの [表示] と同じ)。
- 変えても効果のない入力欄は操作できなくする (`ledger/look_tab.h` の `look_control_enabled`)。輪郭の [表示] は名前を表示するときだけ押せ、輪郭の [色] と [サイズ] は輪郭の [表示] がオフのとき押せない (背景の [表示] がオフのときの [色] と [不透明度] と同じ。値は残す)。
- フォントの種類はタブの中の `QFontComboBox` で選び、太さはフォントが持つ太さの一覧にする。OS のフォントのダイアログ (`QFontDialog`) は、そこで選んだ大きさが反映されないので開かない。斜体は選べないようにする。
- 変えるとすぐ配信画面に反映する。[適用] はなく、保存は変更の 1 秒後にまとめて行う (OBS を閉じるときも保存する)。つまみとスピンボックスを動かしている間に配信画面へ渡す回数は、`ledger::kLookReflectIntervalMs` (100 ms) ごとに 1 回へ間引き、最後の値は必ず渡す。
- ホイールはスクロールに渡す。つまみ、スピンボックス、コンボボックスのすべてで、フォーカスがあっても同じである。
- つまみは、段数が 1000 以下の数の入力欄に、数の入力欄と並べて置く (どちらを動かしても同じ値になる)。つまみもフォーカスを受け、キーで動き、ダブルクリックでその設定の既定値 (`config::Settings` の既定値) に戻す (「コントロールとキーボード操作」のつまみ)。Tab の順は、つまみ、数の入力欄の順になる。
- 外から値が変わったとき (設定ファイルの書き換え、メインアカウントの変更) は、操作していない入力欄に反映する。操作している最中の入力欄 (フォーカスがある、つまみを押している、変えた値をまだ渡していない) は書き換えない。
- 設定ウィンドウの [適用] は、表示タブの値とメインアカウントを上書きしない (`SettingsOwner::DockTab` と `SettingsOwner::Action` の行は、ウィンドウがコピーしない)。
- ソースの候補 (自分の枠に映す映像、自分の枠の音声ソース) は、タブを開いたときとコンボボックスを開いたときに OBS から集める。
- ダミー映像を表示している間は、話している人の光を順に回す (`dummy_cycle_ms`)。光の見た目を通話なしで確認するためである。

[並び順] (`slot_order`) は、枠に載っている人を配信のどの位置に置くかを決める。どちらも左上から詰めて置き、途中の人が抜けると後ろの人が前へ詰まる。

| 値 | 位置の決め方 |
|---|---|
| 名前順 (既定) | 表示名の順 |
| 載せた順 | 手動ならチェックを付けた順、自動なら画面共有を始めた順 |

[自分の枠に映す映像] の映像 (自分の枠と、「Discordの画面共有」のときのメインアカウントの画面共有) は、[先頭に配置] (`self_slot_first`。既定はオン) が付いていれば、並び順によらず左上に置く。既定をオンにするのは、この設定を足す前と同じ配置になる (`settings.json` にキーがなければオンとして読む) ことと、参加者の一覧でメインアカウントの行が先頭に固定されるのと順序がそろうためである。外すと、ほかの参加者と同じ並び順で置く。名前順では、自分の枠を自分の枠の名前ラベルに出す名前で比べ、メインアカウントの画面共有はほかの人と同じ表示名で比べる。載せた順では、自分の枠を、メインアカウントの行にチェックを付けて自分の枠が映り始めた時の順にする (OBS を起動したときから付いていて、ほかの人より先に映れば、最初に載せた人になる)。チェックが付いていても映っていない間 (映像が「Discordの画面共有」の間、選んだソースが見つからない間) には決めない。利用者に見えない時の並びで位置が決まらないようにするためである。[自分の枠に映す映像] を替えても位置を変えない (「Discordの画面共有」から OBS のソースに替えたら、メインアカウントの枠の位置を自分の枠が引き継ぎ、逆に替えたら、自分の枠の位置にメインアカウントを載せる)。ダミー映像の間は、[先頭に配置] によらず自分の枠を左上に置く (ダミーの枠の名前と順は仮のもの)。[自分の枠に映す映像] が「(なし)」の間は、置くものがないので押せない (「(なし)」かは、メインアカウントの有無と映像の選択で決まる。`ledger::look_self_slot_first_enabled`)。1 人だけのときの全面は、2 つの並び順と [先頭に配置] のどれでも同じである。

#### 状態タブ

1 列に、上から次の順に置く。横にはみ出さず、ホイールはタブのスクロールに渡す。

1. 現在のメッセージ: レベルの順に本文と操作のボタンを並べる。なければ「ありません」と出す。録画ファイルの作成の進み具合もここに置く。
2. 録画: 「録画中です。」、「最後の録画: 21:04 (12分)」と [フォルダーを開く]、「まだ録画していません」の 3 つ。最後の録画は録画を始めた時刻と長さで、この起動の中だけ覚える (ファイルを読まない)。
3. 映像の受信: 名前、途切れ、合計、遅延率、最大の 5 列の表と、表の下の 1 行の説明、[途切れの累計をリセット]、[映像のバッファ]。途切れと合計は配信を通した累計、遅延率と最大は直近 1 分である。行のツールチップに直近 1 分の詳しい値 (遅延フレーム、カクつき、平均遅延、最大遅延) を出す。
4. Vesktop: Vesktop の設定が同梱の Vencord を指していて、Vesktop が起動していない間だけ置く。「Vesktopにcordmuxが追加されています。」と [Vesktopから削除]。Vesktop の起動中と、起動しているかを読めていない間は組ごと置かない。この起動で Vesktop の設定を書かないときだけ、押せず、その理由をボタンの下に文で出す (Vesktop を終了しても押せないので)。確認のダイアログは出さない ([Vesktopに追加] で戻せる)。
5. 履歴: 時刻つきで最大 60 行、新しいものが上。メッセージの発生と解消 (全レベル。待ちを通した後の状態)、Vesktop との接続と切断、枠に載せた人と外した人、録画の開始と終了を書く。人の出入りと映像途切れの出入りは書かない。この起動の中だけ覚える。

[Vesktopから削除] は、Discord の更新に同梱の Vencord が合わず、Vesktop の画面が真っ黒のままになったときに戻す操作で、その案内は Discord の内部への依存箇所のメッセージにある (「Vesktopを終了して、[Vesktopから削除] を押してください。」。終了すると組が現れる)。Vesktop の起動中に組を置かないのは、配信中の配信者が見る状態タブに、押せないボタンと「先にVesktopを終了してください。」を常に出すと、ふだんの使い方で意味のない指示になるためである。メッセージのカードにボタンを置かないのは、Vesktop を終了すると接続が切れてカードが消え、押せるようになったときにはボタンがないためである。映像の受信の下に置くのは、配信中に見る表とバッファを押し下げないためで、履歴の上に置くのは、60 行まで伸びる履歴の下では見つけにくいためである。

映像途切れの累計の決まり。

- 「途切れ」は、参加者の行に「映像が届いていません」(狭いときは「映像途切れ」) が出ていない状態から出ている状態に変わった回数で、「合計」は出ている間の時間の合計である。行が使う判定をそのまま使い、別の判定を作らない (`ledger::stalled_people()`)。
- 配信の開始とリセットでゼロに戻る。その時点で途切れが続いている人は、その途切れが終わるまで数えない。配信していない間も数える。
- 通話を抜けた人も、累計が 0 でなければ行を残す。リセットで消える。行は名前の自然順で、値が変わっても並びを変えない。
- メモリだけに持ち、settings.json に書かない。
- 直近 1 分の列は、状態タブが見えている間だけ Pipeline から受け取る (列そのものは常に記録しているので、タブを開いた瞬間から直近 1 分の全部が出る)。累計は、タブが見えていなくても数え続ける。

[映像のバッファ] は、変えるとすぐ表の遅延率を計算し直し、入力が 0.3 秒止まってから配信の処理に渡す。渡すたびに映像と画面共有の音声が一時的に止まったり飛んだりするので、つまみを動かしている間と、数を打っている途中は渡さない。保存は表示タブと同じく渡した 1 秒後にまとめる。つまみと数の入力欄はホイールを受け取らない。つまみのダブルクリックで既定値 (100 ms) に戻し、矢印のキーで動かした値も、入力が 0.3 秒止まってから渡す。

表の遅延率と最大は 2 秒ごとに書き換える (OBS の統計ウィンドウと同じ)。周期ごとに書き換えると数字がちらついて読めない。途切れの回数と合計は周期ごとに書き換える。説明の文と [途切れの累計をリセット] は表についてのものなので、表がないときは出さない。

位置を動かす更新 (メッセージの増減、表の行の増減、録画の節の高さの変化) は、参加者タブと同じ並びの保留に従い、保留中は座標を動かさない。数字の更新と履歴の追加は保留しない。

#### 下のバーと録画

左に cordmux の録画のボタン、右端にドックのメニューのボタン ([...]) を置き、スクロール領域との間に区切り線を引く。

- 録画中はボタンの中に経過時間を出す (`録画を終了 12:34`)。ボタンの幅は変えない。ボタンの名前 (読み上げソフトが読む名前) は「録画を終了」のままにし、経過時間を入れない。毎秒変わる名前は、フォーカスがボタンにある間、読み上げソフトが読み続ける。
- 録画の終了、ダミー映像の表示、[cordmuxを無効にする] は、配信中でも録画中でも確認しない。確認するのは、配信中の [退出] だけである (「メインとサブの行」)。
- [配信時に自動的に録画する] (`record_with_stream`。既定はオフ) をオンにすると、配信の開始で録画を始め、配信の終了で録画を終える。オフのときは、配信を終えても録画は止めない。録画そのものは起動のたびにオフから始まる。
- ドックのメニュー ([...]) は「設定」「参加者の設定」「診断情報をエクスポート...」、区切り線、「cordmuxを無効にする」を持つ。無効の間は、最後の項目を [cordmuxを有効にする] にする。OBS の [ツール] メニューには、「cordmuxの設定」と、そのすぐ下に「cordmuxをアンインストール...」を置く。

#### 設定ウィンドウ

配信中に触らないものだけを、設定ウィンドウと参加者の設定ウィンドウに置く。設定ウィンドウのページは次の 4 つにする。

| ページ | 項目 |
|---|---|
| 録画 | 保存先、音声の形式、残り時間の警告、配信時に自動的に録画する、[フォルダーを開く] |
| 映像の受信 | 組「受信する映像」: 最大解像度、最大フレームレート、受信する人 (`receive_scope`: 枠に載せた人だけ (既定) / 画面共有している全員)。組「Vesktopでのエンコード」: 映像エンコーダ、チューニング |
| 詳細設定 | 組「映像と音声」: 映像デコーダ、音声の同期オフセット。組「ドック」: 配信中の退出を確認 |
| バージョン情報 | バージョン、診断情報、アンインストール |

[受信する人] が既定の「枠に載せた人だけ」のときは、Vesktop は枠に載せた人と全画面にした人だけを視聴し (ほかの人の画面には視聴者として出ない)、cordmux の録画の画面もその間だけになる (声は全員分を録画する)。「画面共有している全員」にすると、載せる前から全員の映像を受信し、録画の画面も全員分になる。コンボボックスの順は、既定を先頭にする。

メッセージを表示するまでと消すまでの時間、映像が届き始めるまでの待ち時間、一覧の並びを動かすまでの時間、接続が切れてから枠を空にするまでの時間は、利用者が変えたいものではないので、どのページにも置かず、設定ファイル settings.json でだけ変えられる。

| ウィンドウ | 中身 | 反映 |
|---|---|---|
| 設定ウィンドウ (「cordmuxの設定」) | 上の表の項目 | [OK]、[キャンセル]、[適用] (OBS の [設定] と同じ) |
| 参加者の設定ウィンドウ (「参加者の設定」) | 現在の参加者と過去の参加者の、自動で枠に載せる、cordmux での名前、使う声、通話のみ時ラベル非表示。列の見出しで並べ替える (既定は最終参加日時の新しい順) | すぐ反映される。ボタンは [閉じる] だけ |

参加者の設定ウィンドウの列の見出しは、どの列も文字を灰色の部分 (OBS のテーマの見出しの枠線の内側) の中央に置き、並べ替えの三角は文字の右に置いて、文字と組にして中央に置く (並べていない列は文字だけを中央に置く)。Qt の表の見出しの既定 (`Qt::AlignCenter`) で、OBS 自身の表の見出しも同じ形だからである。左右の余白は同じにし、灰色の部分の内側に 0.5 em ずつ空ける (OBS のテーマは見出しの左右の余白を 0 にしているので、空けないと字が灰色の部分の端に付く)。列の幅の下限は「文字 + 間 + 三角 + 左右の余白」で、並べていない列も三角の分を含める (並べ替えを変えても列の幅が動かない)。列の中身 (名前、入力欄、チェックボックス、日時) の揃え方は、見出しとは別に決める (チェックボックスは中央、ほかは左)。

1 つの値を、反映のしかたが違う 2 つの場所で変えられるようにしない。[OK] で反映するウィンドウと、すぐ反映される場所の両方で変えられると、片方の古い値でもう片方の変更を上書きするためである。設定ウィンドウで OBS の再起動が必要な設定を変えたら、そのページに「これらの設定を反映するには、OBSの再起動が必要です。」を表示する。2 つのウィンドウは、開いている間もドックと OBS を操作できるようにする。

### メッセージのレベルと表示方法

メッセージのレベルは、次の順に問うて決める。

1. 配信者がほかの場所で気付けるか。気付けるなら 1 行目に出さない (行だけにする)。映像の途切れは行に出ていて、OBS の映像でも見える。
2. 今の配信か録画が損なわれていて、今できることがあるなら、レベル 1 にする。
3. そうでなければレベル 2 にする。何かをさせないものはレベル 3 にする。

「何が損なわれるか」だけで決めない。何もできないものが赤く出続けると、次の本当の問題に気付けないためである。

| 規則 | レベル | 理由 |
|---|---|---|
| Vesktop との接続が切れた (`ConnectedThenDropped`。Vesktop が起動していないと分かったときは、配信中で枠に人が載っているときだけ) | 1 | 全員の映像と声が止まる |
| 録画を始めようとして保存先に書き込めなかった (`RecordDirUnwritable`)、空き容量が尽きて録画が止まった (`RecordStoppedSpaceExhausted`) | 1 | 配信の映像に出ないので、ほかで気付けない |
| Vesktop の cordmux が上書きされた、Vesktop の設定がほかの Vencord を読む、[Vesktopに追加] と [再インストール] の失敗の、配信中で枠に人が載っていて接続していないとき | 1 | 配信が損なわれていて、操作で修正できる |
| 声が二重に入っている (`DoubleAudio`) | 配信中は 1、ほかは 2 | 視聴者全員に聞こえる。OBS のミュートで今修正できる |
| 映像が届かない (`AllVideoStoppedHint`) | 2 人以上が止まり、対象の中に映像が届いている人がいないときだけ 2。ほかはメッセージにしない | 1 人なら行で分かり、OBS の映像でも見える。全員同時なら、全員に共通する所 (配信者の PC かネットワーク、Discord の側など) に原因があることが考えられる |
| Vesktop の中で cordmux が使う部分が見つからない (`ContactUnavailable`) | 2 | 今できることがない |
| 作成できなかった録画ファイルがある (`RecordFinalizeFailed`) | 2 | 過去の失敗で、配信の後に対応すればよい |
| Vesktop に cordmux が追加されていない、cordmux のソースがない、空き容量が少ない、バージョンが違う、設定を保存できていない、書き込めなかった保存先が残っている (今は録画を始めようとしていない)、アンインストールの後の作業が残っている、[Vesktopから削除] の失敗 (`VesktopRemoveFailed`) | 2 | 今の配信は損なわれていない |
| 録画のためだけに受け取っている、録画ファイルの作成の進み具合、録画の途切れ | 3 | 何かをさせない |

- 映像が届かない人を数えるのは、枠に載っているか cordmux の録画の対象の人だけである。どちらでもない人は、その人の行にも状態を出さない。
- レベル 1 と 2 は警告で、「これを見て利用者が何をするか」を書けるものだけにする。レベル 3 は警告ではない状態の行で、これがないと見えているものを読み違えるとき (録画のためだけに受け取っている理由がないと、人が枠に映らないのを故障と思う) に置き、何かをさせる文は書かない。利用者が自分で選んだ状態 (無効、ダミー映像) はメッセージにしない。

メッセージを OBS のログに書くときのログレベルは、メッセージのレベル 1 は Error、メッセージのレベル 2 と、メッセージを表示しない操作の失敗 (診断情報をエクスポートできなかった、など) は Warning、ほかは Info にする。対応は `src-obs/ledger/rules_dock.cpp` の `rule_log_level()` にあり、規則ごとのメッセージのレベルとログレベルは `src-obs/tests/test_ledger_tiers.cpp` の `kTierCases` が確認する。

一覧の上にメッセージを挟まない。メッセージが出ても消えても、操作する要素の位置を動かさないためである。

| | 1 行目 | 状態タブの件数 | アイコン | 色とテキスト |
|---|---|---|---|---|
| レベル 1 | 解決するまで出す (録画だけの失敗は、状態タブを開くまで) | 数える | 円の中に x | 1 行目の背景をテーマの危険の色にする。テキストとアイコンは白か黒。状態タブのカードは赤く塗らず、左端の線を危険の色にする |
| レベル 2 | 未読の間だけ出す (無効の間は「cordmuxは無効です」を先に出す) | 数える | 三角の中に ! (OBS の警告のアイコンと同じ形) | 1 行目は色を使わない。状態タブのカードは左端の線を注意の色にする |
| レベル 3 | 出さない | 数えない | 円の中に i | 色は使わない (左端の線なし)。録画ファイルの作成の進み具合だけは 2 行目を持つ |
| メッセージがないとき | 無効、ダミー映像、要約 | - | なし | 色は使わない。状態タブには「ありません」と出す |

状態タブと参加者タブの最初の設定のカードは、同じ部品で描く。背景はパネルの色 (テーマの `frame-notice` の背景。持たないテーマや、カードの上でボタンが見分けにくくなるテーマは、ドックの背景を本文の色の方へ少し寄せた色)、見出しは太字、影響と次の操作は補足の色、左端に 3 px の線を引く。赤い背景と太い枠は使わない (赤は 1 行目だけ)。

メッセージはポーリングのたびに状態から作り直すので、現在の障害のメッセージは直れば消える。障害が残した結果 (cordmux の録画の途切れ) は、レベル 3 の行 (「録画が21:30から3分間途切れました」) として残し、次に cordmux の録画を開始すると消える。

既読は状態タブを開くことでだけ付き、閉じるボタンは置かない (`src-obs/ledger/notice_tracker.h` の `settle_first_line()`)。

- 状態タブを開くと、その時点のレベル 2 は既読になり、1 行目から消えてタブの件数だけに残る。開いている間に新しく出たレベル 2 も、同じ画面の一覧で読めるので既読にする。
- レベル 1 は既読にならず、解決するまで 1 行目に残る。例外は、cordmux の録画だけが止まった失敗 (空き容量が尽きて録画が止まった、録画の開始に失敗した) で、レベル 2 と同じに、状態タブを開くと既読になって 1 行目から消える (メッセージは状態タブに残る)。未読に戻る条件もレベル 2 と同じである。
- 既読のメッセージが消えて、別の配信で再び出たら未読に戻す。同じ配信の中で再び出たときは既読のままにする。
- 配信の外では、消えて 60 秒以上たってから出たら未読に戻す。
- 消えていない間は、配信をまたいでも既読のままにする。既読は保存せず、OBS を起動するたびに未読から始める。

状態タブの件数はレベル 1 と 2 の合計で、0 のときは出さない。

- 推測で決まる状態 (ハートビートの応答が届かない、映像が届かなくなった) は、一定の時間続いてから表示し、消すときも一定の時間続いてから消す。既定は 2 秒で表示し、1 秒で消す (`src-obs/config/settings.h` の `notice_show_delay_ms` と `notice_clear_delay_ms`。settings.json でだけ変えられる)。映像が止まったとみなすしきい値 (`video_stall_ms`。既定 2 秒) とは別の値である。
- 画面共有を始めたのにフレームが 1 枚も届かないときは、届くまでの時間を見込んで長く待つ (`first_frame_wait_ms`。既定 5 秒。settings.json でだけ変えられる)。待ち始めは、映像の受信を始めた時刻である。「枠に載せた人だけ」では、画面共有していると分かった時刻と、枠に載せた (視聴の範囲に入れた) 時刻の遅いほうにする。ずっと前から共有している人のチェックを付けた瞬間に、待ち時間を超えたことにしないためである。
- 推測ではなく確かに分かること (Discord から画面共有の終わりが届いた) は、待たずに表示する。
- 1 分の間に 3 回以上表示されるメッセージは、表示の規則の不具合として直す (数えるツールは `test/tools/notice-count/notice_count.py`)。
- 状態タブでは、メッセージのレベルの順に並べ、同じレベルの中では先に出たものを上にし、新しいものを下に追加する (読んでいる途中のメッセージを動かさない)。
- 状態タブのメッセージは、アイコン、見出し、影響と次の操作、操作のボタン (多くても 2 つ) の順に持つ。次の操作が設定を変えることなら、その場所を開くボタンにする ([保存先を変更])。押しても同じ起動の中では同じ失敗になると分かっているボタンは置かず、次の操作を文で書く。
- 何も壊れていない間も表示され続け、起きるかもしれない問題を伝えるだけの行は置かない。そうした注意が常にあると、本当の警告が目立たなくなる。
- スクリーンリーダーには `QAccessibleAnnouncementEvent` で読み上げさせ、フォーカスは動かさない。レベル 1 が表示されたときはその見出しを Assertive (現在の読み上げに割り込む) で読ませる。レベル 2 と 3 が表示されたときはその見出しを、レベル 1 が消えたときは消えた後の 1 行目のテキストを、枠がすべて使用中になったときと空いたときは `cordmux.dock.no_free_slot.text` と `cordmux.dock.slot_free.a11y` を、Polite (現在の読み上げの後に読む) で読ませる。

### 色とフォント

色は OBS のテーマから取り、色の値をコードに書かない。テキスト、背景、枠線、選択、押された見た目は、Qt のウィジェットと OBS のクラス (`text-muted`、`frame-notice`、`btn-tool`、`icon-dots-vert`、OBS の `button-primary`) に任せる。cordmux が自分のスタイルシートに書く値は、計算した後の数と色だけにする (`var()`、`calc()`、QSS の `em` は書かない)。cordmux が自分で塗る色 (1 行目のレベル 1 の背景、アイコン、フォーカスリング) は、OBS のクラスを付けた見えない `QLabel` のパレットから読み、テーマがクラスを持たないときは、テーマの色だけで作った代わりを使う。テーマ、[フォントサイズ]、[密度] が変わったとき (`OBS_FRONTEND_EVENT_THEME_CHANGED`) に、もう一度読む。cordmux だけでテーマの明暗を切り替える設定は作らない。

- テキストの色は、本文の色と補足の色 (`text-muted`) の 2 つだけにし、`text-danger`、`text-warning`、`text-success` をテキストに付けない。補足の色は、背景とのコントラストが 4.5:1 に届かなければ本文の色にする (WCAG 2.2 の 1.4.3)。
- 見出し (表示タブの大見出しと中見出し、状態タブの見出し、参加者の設定ウィンドウの見出し) は本文の色にする (補足の色にしない。理由は「表示タブ」の見出しの項)。参加者タブの一覧の組の名前 (「画面共有中 (N)」「通話中 (N)」) は、人数を添えた一覧の区切りで、配信中に見る名前の行より目立たせないために補足の色のままにする。
- 説明の文 (項目の名前でも値でもない、項目に添える文。表示タブのダミー映像の説明、状態タブの表の下の「途切れと合計は...」、設定ウィンドウの [保存先] の下と [映像の受信] の上限の下の文、「名前を変更」のダイアログの補足) は、補足の色の 1 em にし、説明する項目のすぐ下 (上の余白は行の間だけ) に置く。左端は説明する項目の文字の頭にそろえ (チェックボックスなら四角の右の文字の頭、入力欄なら入力欄の列)、下に 0.5 em を空けて次の項目と分ける (設定ウィンドウでは、フォームの行の間 (テーマの値。Yami で 6 px) がほぼ 0.5 em なので、行の間のままにする)。どの項目の説明かを、語を足さずに配置で示すためである。大きさは下げない (日本語は 1 em より小さいと読みにくい。10 pt の本文の 0.9 倍は 9 pt になる)。押せない理由と、状態の値 (「ありません」など、今の状態を示す文) は説明の文に含めない。押せない理由は、次の操作を決めるために読む文なので本文の色にする。
- 1 行目のレベル 1 の背景の上のテキストとアイコンは、白と黒のうち背景とのコントラストが高い方で描画する (どの色の上でも 4.58:1 以上になる)。その背景とドックの背景のコントラストが 3:1 に届かないテーマでだけ、1 行目の外側に本文の色の 2 px の枠線を描画する。
- 色を持つのは次のものだけにする。1 行目のレベル 1 の背景 (危険の色)、状態タブのカードの左端の線 (レベル 1 は危険の色、レベル 2 は注意の色)、ミュートの赤い斜線、話している間のマイクの緑の縁と緑のアイコン、音声タブのメーターの緑、黄、赤、サブアカウントが別の通話にいるときの通話の名前 (注意の色)。危険の色を飾りや戻せない操作のボタンに使わない。ほかに色が入ると、1 行目が赤くなっても目立たなくなる。
- 状態のアイコンは、cordmux が 16 x 16 のグリッドに同じ描き方で描き、テーマの本文の色の 1 色で塗る (`src-obs/dock/ui/status_icons.h`)。枠の位置を示す画面のアイコンも cordmux が描く (テーマのアイコンには中に四角を描く余白がない)。[...] はクラス `btn-tool icon-dots-vert` を使う。大きさはテーマの [...] のアイコンに合わせ、`devicePixelRatio` で描画する。
- cordmux の録画のボタンの押された見た目 (`QPushButton:checked`) は、押したときではなく、録画の処理が保存先に書けたと返したときに付け、テキストの切り替えを必ず添える。開始に失敗したときに、画面が実際と違うことを言わないためである。
- 見た目を変えたら、色覚の違い (1 型と 2 型) をまねた画像と白黒の画像で、メッセージのレベルと行の状態が見分けられるかを確認する。
- フォントの種類と固定のフォントサイズは書かず、OBS の本文のフォントサイズ (1 em) の倍率で決める。テキストの見た目は、1.5 em (ダイアログの主文。OBS のテーマの `--font_xlarge` と同じ倍率)、1.1 em の太字 (表示タブの大見出し。`--font_large` と同じ倍率)、1 em の太字 (メッセージの見出し、1 行目のメッセージ、中見出しと状態タブの見出し)、1 em (本文と、1 行目の平常の状態)、1 em の補足の色 (補足と説明の文) の 5 つだけにし、斜体と下線は使わない。1.1 em の太字は、表示タブの見出しが 2 段あり、本文と同じ大きさの太字だけでは大見出しと中見出しを見分けにくいために足した (「表示タブ」の見出しの項)。倍率の元にする大きさは、スタイルシートを書いていないウィジェットから読む (倍率を付けたウィジェットから読むと倍率が重なる)。
- 行とラベルの高さは固定の px で決めず、`sizeHint` とレイアウトに任せる。日本語は OBS のフォントにない文字なので、ほかのフォントで描画されて高さが変わることがある。

テキストの省略と折り返し:

- 1 つのラベルは、折り返すか、1 行で末尾を省略して全文をツールチップとアクセシブル名に入れるかのどちらかにし、右が切れるだけのラベルを作らない。
- 人の名前は 1 行で末尾を省略し、チェックボックスのテキストにせず隣のラベルに表示する (長い名前でドックの最小幅が広がらないため)。名前には 4 em 以上を残し、見えている名前が同じ文字になる行は真ん中を省略する。
- メッセージの見出しと本文は省略せずに折り返し、行の数を増やさない範囲で、最後の行が 2 字以下にならないようにする。
- 数、バージョン、時刻、ボタンのテキストは省略しない。数と単位の語 (「(2人)」「30分」) は途中で分けない。文の中で角かっこで囲んだボタンの名前 (「[Vesktopに追加]」) は、1 行に入り、分けなくても行が増えないときは途中で分けない (`dock_ui_calc.h` の `button_name_spans`。行が増えるとカードの高さが変わるので、そのときは分ける)。フォルダーとファイルの場所は省略せず、区切りの「\」の後で折り返す (`src-obs/dock/ui/dock_ui_calc.h` の `path_break()`)。

### 余白と幅

ウィジェットの内側の余白は OBS のテーマに任せる。cordmux が自分で置く余白は、本文のフォントの大きさからコードで計算する次の値だけにする。固定の px を書くと、[フォントサイズ] を変えても動かない。値は `src-obs/dock/ui/dock_style.h` の `DockStyle` にある。

- 小 0.25 em (同じまとまりの項目の間)、大 0.5 em、まとまりの間 0.75 em (表の列の間など)
- 意味やまとまりが違う部分の間は 1 em。状態タブの [途切れの累計をリセット] と [映像のバッファ] の間、表示タブの光り方と光る条件の間、参加者タブの組の名前 (「画面共有中 (N)」「通話中 (N)」) の上、参加者の設定ウィンドウの「過去の参加者」の上など。同じまとまりの項目の間 (0.25 em) と同じ狭さだと、意味の違うものが 1 つのまとまりに見える (近接の原則)
- 見出しの段の余白 (大見出しは前の行から罫線まで 1 em、罫線から見出しまで 1 em、下 0.5 em。中見出しは上 2.25 em、下 0.25 em。状態タブの見出しは上 1 em、下 0.25 em。理由は「表示タブ」の見出しの項) と、説明の文の下の 0.5 em

ドックの外側の左右の余白だけは、テキストの左端を OBS のシーンのドックにそろえるため、OBS のテーマを適用した見えない一覧の項目から読む。

ドックの最小幅は中身から計算し、状態によらず固定する。下のバー (録画のボタンのどの状態のテキストのうちでもいちばん広いもの。ボタンの幅は状態で変えない)、一覧の 1 行 (チェック、名前の 4 em、アイコン、[...]、スクロールバー)、メインとサブの行、タブ、1 行目のうち、いちばん広いものにする。状態タブのメッセージは含めない (文とボタンは折り返す)。幅が減るときは、アバター、解像度とフレームレート (行に使える幅が 32 em 以上のときだけ表示する)、行の状態のテキスト (アイコンは残す) の順に消してツールチップに移し、メッセージの本文は折り返す。消すかどうかは一覧の行に使える幅で決め、全部の行に同じルールを適用する。広いドックでは、名前の列が余りの幅を受け、段落は 40 em で折り返す。

- 一覧の行の高さは中身から決め、24 px を下限にする。行どうしの間は、0.25 em と 4 px (フォーカスリングとその外の 1 px) の大きい方にする。
- チェックをクリックできる範囲は、チェックボックスから見えている名前の右端までの、行の高さ全部の長方形にする。行の空いた所をクリックしても、誰かを枠に載せない。
- [...] は OBS の `btn-tool` の大きさのままにし、中心に置いた直径 24 px の円が、ほかのクリックできる範囲と重ならないように間を空ける (WCAG 2.2 の 2.5.8)。
- スクロールはタブの中身の縦に 1 つだけにし、横のスクロールと入れ子のスクロールを作らない。キーボードでフォーカスが移ったウィジェットは、フォーカスリングまで見える所までスクロールする (`src-obs/dock/ui/focus_ring.h` の `reveal_focus_mark()`)。
- 初めて起動したときは、フローティングのドックを OBS のメインウィンドウの中央に表示し、2 回目からは OBS が覚えた位置と大きさに任せる。
- 設定ウィンドウは OBS の [設定] と同じ形にする。左にアイコン付きの項目の一覧、右に `QGroupBox` で分けた入力欄、下に [OK] [キャンセル] [適用] (`QDialogButtonBox` の Windows の並び) を置く。入力欄は `QFormLayout` で並べ、幅が足りないときはラベルの下に置き (`WrapLongRows`)、ラベルは右寄せにして入力欄を列の幅まで伸ばす (`AllNonFixedFieldsGrow`)。大きさと位置は覚える。

### コントロールとキーボード操作

ボタンは 3 種類にする。

- 通常のボタンは `QPushButton` の既定の見た目にする。
- プライマリのボタンは、その画面で次に押す 1 つだけにし、OBS のクラス `button-primary` を付ける。
- 戻せない操作のボタン ([cordmuxをアンインストール...]) は色を変えず、[バージョン情報] ページのいちばん下に、ほかのボタンから 1 em 以上離して置き、確認のダイアログを挟む。配信中、OBS の録画中、リプレイバッファと仮想カメラの動作中、cordmux の録画中、Vesktop の起動中は押せなくする。OBS の [ツール] メニューの「cordmuxをアンインストール...」は、設定ウィンドウをこのページで開いてから、このボタンと同じことをする。

状態を持ち続ける設定は `QCheckBox`、始まって終わる処理は `QPushButton` にし、スイッチは使わない。

- Tab の順は「チェック、ミュートのボタン、[...]、次の行のチェック」にする。フォーカスのあるチェックが押せなくなったら、フォーカスを同じ人の [...] へ移す (次のミュートのボタンに移ると、続けて押した Space が配信の音を切り替える)。Space でチェックを付け外しし、Space か Enter でミュートを切り替え、Enter か Space で [...] のメニューを開き、Esc で閉じたら、フォーカスを開く前のウィジェットに戻す。同じメニューは、右クリック、Menu キー、Shift+F10 でも開く。押せないチェックには Qt がフォーカスを渡さないので、理由は一覧のアクセシブルな説明と読み上げで伝える。
- 押せないチェックは、名前の中の色の絵文字も含めて押せない見た目にする (ラベルの不透明度を下げる)。
- メニューの中の現在の値はチェックマークで表す (「使う声」は 1 つだけ選べる `QActionGroup`)。押せない項目の長い理由は、メニューのツールチップに入れる。マウスを乗せたときだけ表示されるボタンは作らない。
- 数の入力欄は、OBS と同じく、クリックと Tab でだけフォーカスを取り (`Qt::StrongFocus`)、フォーカスがないときはホイールで値を変えない。コンボボックスは OBS がアプリ全体の `QStyle` でホイールを止めているので、cordmux はどのウィジェットにも自分の `QStyle` を設定しない。ドックのタブの中のつまみ、コンボボックス、スピンボックスは、ホイールを受け取らずスクロールに渡す。
- ドックの行のボタンとチェックは、クリックではフォーカスを取らず、Tab でだけ取る。OBS が前面のまま Space を押して同じ操作が働くのを防ぐ。
- つまみ (音声タブの音量、表示タブの数の入力欄の隣、状態タブの [映像のバッファ]) は、クリックと Tab でフォーカスを取る (`Qt::StrongFocus`。OBS のミキサーとプロパティのつまみと同じ)。フォーカスがある間は、矢印のキーで 1 段 (右と上で増え、左と下で減る)、PageUp と PageDown で大きい刻み (10 段。範囲の段数の 4 分の 1 を超えない)、Home と End で両端に動く (Qt の `QSlider` の既定。HTML の range と Windows のトラックバーも同じ)。ダブルクリックで、その設定の既定値 (音量は 100%) に戻す。ホイールを受け取らないのは、スクロールしている途中にポインターがたまたまつまみの上を通っただけの操作を、値の操作と取り違えないためで、キーを受け取るのは、フォーカスが利用者がそのつまみを選んだ結果だからである。ボタンとチェックがクリックでフォーカスを取らない理由は、つまみには当てはまらない。つまみは Space で何もせず、矢印のキーで動くのは 1 段 (音量なら 1%) で、動いた値はつまみと数字ですぐ見える。数の入力欄のないつまみ (音量) は、クリックした後に矢印のキーで細かく合わせられないと、ドラッグだけでは 1% 単位に合わせにくい。共通の部品は `src-obs/dock/ui/no_wheel.h` の `NoWheelSlider` で、音量のつまみも表示タブのつまみも同じ動きにする。
- フォーカスリングは、最後の入力がキーボードのときだけ、フォーカスを受けるウィジェットのクリックできる範囲を 1 px 空けて囲む 2 px の線を、テーマの本文の色で描画する。ウィジェットの上に重ねた透明なウィジェット (`QFocusFrame` と同じ考え方) が描画し、スタイルシートとレイアウトは変えない。つまみも同じで、Tab で移ったときと、クリックした後に矢印などのキーを押した時点で表示する (OBS のテーマはつまみのフォーカスの見た目を持たないので、ほかのウィジェットと同じリングで示す)。
- タブストップは操作できるウィジェットだけにする。ただし、ドックのスクロール領域は常にタブストップにし、ボタンのないメッセージの文も、キーボードでスクロールして読めるようにする。

下のバーの録画のボタンは、録画の処理の状態から次の状態を表示する。

| 状態 | テキスト | 押された見た目 | 押せるか |
|---|---|---|---|
| 待機 | [録画を開始] | なし | 押せる |
| 開始の処理中 (録画の処理が保存先に書けたと返すまで) | 1 秒を超えたら「開始処理中...」 | なし | 押せない |
| 録画中 | [録画を終了 12:34] (経過時間を添える) | あり | 押せる |
| 終了の処理中 (録画が止まるまで) | 1 秒を超えたら「停止処理中...」 | あり | 押せない |
| 始められなかった、空き容量が尽きて止まった | 待機と同じ | なし | 押せる (原因が直っていないと分かっているときは押せない) |

始められなかったことと止まったことはレベル 1 で伝え、ボタンの見た目だけで失敗を伝えない。録画ファイルの作成の進み具合は、ボタンではなく状態タブのレベル 3 の行に表示する。押せないときは、ボタンを消さずに理由をツールチップとアクセシブルな説明に入れる。処理の後、フォーカスが Qt の移した先のままならボタンに戻す。

### ダイアログ

ダイアログを表示するのは、次の 3 つの場合だけにする。どれも利用者の操作の直後にだけ表示し、cordmux の側で起きたことはドックに表示する。

- 戻せない操作と、ほかのアプリの設定を変える操作の確認 (アンインストール、Vesktop が読む Vencord の切り替え)
- OBS を終了する前に場所を知る必要がある操作の結果 (アンインストール)
- ウィンドウから始めた操作が失敗したときと、途中で止まったとき

見た目とふるまいは次のとおりにする。

- 親ウィンドウは操作を始めたウィンドウ (ドックから始めたならドックのあるウィンドウ) にし、その中央に表示する。モーダルでないトップレベルのウィンドウにし、入力を止めるのは操作を始めた範囲 (設定ウィンドウ、参加者の設定ウィンドウ、cordmux のドック) だけにする。OBS のメインウィンドウとほかのドックは、配信中も使えるままにする。
- フォーカスは既定のボタンに置き、閉じたらダイアログを開いたウィジェットに戻す。
- 左上に Windows の標準のアイコン (`QStyle::standardIcon`) を置く。確認と失敗のダイアログは警告にする。結果のダイアログは、途中で止まったときと確認できなかったものがあるときは警告、成功したときは情報にする。「?」のアイコンは使わない。
- 主文は 1 文で、補足より大きいテキスト (1.5 em) にし、2 行になるときは日本語では読点の後で折る。ボタンは右下に置く。本文は 1 行 40 字前後で折り返し (幅の上限は 45 em)、中身が画面の作業領域に入らないときだけ本文をスクロールする。「今後表示しない」は置かない。
- `QMessageBox` は使わず、同じ形の `QDialog` で作る。`QMessageBox` は表示するときに読み上げの Alert のイベントを出し、Windows の音が鳴ることがあり、その音が配信に入る。主文と補足はダイアログのアクセシブルな説明に入れる (`test/lint/forbidden_qt_usage.py` が、音が鳴る呼び出しをチェックする)。

フォルダーとファイルの場所とバージョンの文字列は、文の中の括弧に入れず、文の外の独立した行 (場所の行) に、選択してコピーできる折り返すラベルで全文を表示する。読み取り専用の `QLineEdit` は、末尾のフォルダー名が見えなくなるので使わない。フォルダーの行には [フォルダーを開く] を、ファイルの行には [ファイルの場所を開く] (ファイルを選んだ状態で親のフォルダーを開く) を、行の右に置く。アンインストールが済んだダイアログの削除するフォルダーの行だけは、[フォルダーの場所を開く] にする。これらのボタンは、右下の閉じるボタンの列に混ぜない。ファイルかフォルダーかは、拡張子の有無から推測しない。バージョンの一覧には [コピー] を添える。

### 操作への応答と待ち時間

利用者の操作が失敗したら、必ず画面に表示し、ログに書くだけで済ませない。押しても何も起きないボタンを置かない。表示する場所は操作を始めた所の近くにし、メッセージのレベルはほかのメッセージと同じ決め方にする。

- cordmux の録画を開始できなかったときはレベル 1 にする。
- Vesktop への追加の失敗はレベル 2 (配信中で枠の映像が損なわれているときはレベル 1) にする。
- Vesktop からの削除の失敗はレベル 2 にする (外せなかったときは押す前のままで、何も損なわれない)。
- 診断情報のエクスポートの失敗は、設定ウィンドウを親にした失敗のダイアログ (メッセージにしない) にする。
- 設定を保存できなかったときは、失敗のダイアログで今は反映されているが次の起動で元に戻ることを伝え、設定ウィンドウは閉じず、保存できていない間はレベル 2 を表示する。

応答と待ち時間は次のとおりにする。

- 押したものは 0.1 秒以内に見た目で応える (Qt のボタンの押した見た目で足りる)。結果まで 1 秒を超えうる操作 (Vesktop に追加、エクスポート、アンインストール、録画の開始と終了) は、ボタンを押せなくしてテキストを進行中の形にし、二度押しを受け付けない。
- 10 秒を超えうる処理 (録画ファイルの作成) の進み具合は、実際の作業の数 (済んだファイルの数と全体の数、取れるときは現在のファイルの割合) からだけ表示し、割合は整数にする。数が一定の時間進まなかったら、進んでいないことと、最後に進んでからの時間を表示する (`record_finalize_stall_s`。既定 120 秒)。元のファイルは消えないので、レベル 3 のままにする。
- ドックはポーリングのたびに、変わった値だけを今あるウィジェットに書き込み、ウィジェットを作り直さない。フォーカス、開いているメニュー、スクロールの位置、入力の途中のテキストを失わない。
- 成功した結果は押した所の近くに表示し、成功したことだけを伝えるダイアログ、音、自動で消える通知は使わない。診断情報のエクスポートは、どこから始めても、設定ウィンドウの [バージョン情報] ページのボタンを押したのと同じにし、済んだらそのボタンの下に「診断情報をエクスポートしました」と場所の行を表示する。ドックの操作が成功したことは、状態が変わることで伝える。
- 推測で決まる状態は、行の状態も、表示する前と消す前の待ちを通す (`src-obs/ledger/notice_tracker.h` の `stabilize()`)。
- ドックのポーリングの間隔は、ドックの表示にだけ使い、配信画面の表示に関わるもの (話している人の光) はこの間隔に縛らない。間隔は `dock_poll_ms` (既定 200 ms) で、設定ファイルでだけ変えられる。既定を決めた測定は docs/architecture.md の「ドック」にある。

### 配信画面に描画するもの

配信画面に描画するのは、名前ラベル (名前とアバター) と話している人の光だけにする。警告、状態、枠の番号は描画しない (ダミー映像の番号を除く)。名前が読めない人に ID などの代わりのテキストを描画せず、名前もアバターも無ければ名前ラベルごと描画しない。cordmux の録画には何も描画しない。

- 名前ラベルの大きさと光の太さは名前ラベルの em (フォントサイズ) から決め、em は配信画面の高さに対する割合で持つ。既定は 2.5% (1920x1080 で 27 px) で、1.0% から 8.5% まで 0.1 刻みで選べる (`src-obs/config/settings.h` の `label_em_ratio_pct`)。値は cordmux 全体で 1 つにする。
- cordmux のソースの中では、どの配置でも自分の枠でも同じ大きさにし、人数や送信側の解像度が変わっても変えない。保証するのは cordmux のソースの中までで、ソースを縮めて置いたときは、映像と一緒に拡大、縮小される。ソースを反転したり回転したりしたときも、名前ラベルは映像と一緒に反転、回転する (cordmux のソースはシーンの中での変形を知らないため)。
- 名前は白の太字 (UD デジタル 教科書体 NK-B。その PC に無ければ Yu Gothic UI) に、黒の輪郭 (0.1 em) を付けて描画する。輪郭は表示タブの「輪郭」の組の [表示] (`label_show_outline`。既定はオン) で描くかを選び、オフのときは太さ 0 と同じ見た目にする。背景は既定で描き (`label_show_plate`)、黒の不透明度 50%。アバターは直径 1.5 em の円にする。形は丸、角丸 (角の半径は一辺の 1/4)、四角から選べ (`label_avatar_shape`)、画面共有していない参加者の並びも同じ形にする。アバターの画像がないときの頭文字も同じ形で描く。
- 位置は、映像のセルの四隅のどれか (既定は左下) で、端から配信画面の高さの 0.5% 離す。位置は全員一律の 1 つ (`label_corner`) で、参加者ごとには持たない。参加者ごとに持つと、画面共有する人が入れ替わるたびに配置が崩れるためである。
- アバターは名前の左に置く。右に置くこともでき (`label_avatar_side`)、右のときは名前ラベルの中の並びを左右に入れ替える。
- 名前ラベルの幅は映像の矩形の 50% を目安にし、名前を 6 em 以上見せることを優先する。狭い矩形ではアバターを先に省くが、同じシーンに同じ名前の人が 2 人以上見えているときは省かない。収まらない名前は末尾を省略し、見えている文字がほかの名前ラベルと同じになるときは真ん中を省略する。名前の 2 字未満しか見えないときは、名前を描画しない。
- 話している人には、アバターと名前の縁に光を付ける (選べば枠にも)。光は既定の色 #57F287、太さ 0.10 em、ぼかし 0.10 em で、ぼかし 0 なら色の帯になる。声が始まったら 150 ms でフェードインし、止まってから 200 ms 保ち (保持時間)、150 ms でフェードアウトする (`label_border_rise_ms`、`label_border_hold_ms`、`label_border_fade_ms`)。話していない人の名前ラベルは色を 30% 暗くし (`label_dim_pct`)、話し始めると光と同じ時間で明るくする。cordmux がその人の声を聞けないときと、OBS のミキサーで cordmux のソースがミュートか音量 0 のときは、光らせず暗くもしない。
- 通話に参加している人は、画面共有しているか、メインアカウントかに依らず、全員の名前ラベルをどこかに描画する (配信を見る人が、通話で誰が話しているかを分かるようにするため)。いま名前ラベル付きで描いている枠がある人は、その枠に名前を出し、ない人は「画面共有していない参加者」の並びに出す (`roster_show`。既定はオン)。並びに出るのは、画面共有していない人のほか、次の人である。
  - 画面共有していても枠に載せていない人 (手動で載せる設定でチェックを外した人) と、枠が足りずに描けない人
  - 全画面で描かれていない枠の人
  - 「1人のときは非表示」で名前ラベルを隠した人
  - 「画面共有している参加者」の [表示] (`label_show_in_slot`。既定はオン) を外したときの、枠の人 (自分の枠を含む)
  - 映像がまだ届いていない枠の人
  - 自分の枠を出していないか、自分の枠の名前ラベルを描いていないときのメインアカウント
- 「画面共有している参加者」の [表示] を外しても、枠の光は枠に描く (枠は残るので、[対象] で [枠] を選んでいれば従う。`composite_tiles_framed`)。アバターと名前の光と、話していない人の暗さは、名前ラベルと一緒に並びに移る。[1人のときは非表示] で隠す全面の 1 枚には、前と同じく名前ラベルも光も描かない。
- どちらに出すかは、枠に名前ラベルを描くかを決める関数で、同じ描画の中で決める (`sources/composite_label_plan.h` の `composite_tiles_labeled`)。同じ人が枠と並びの両方に出ることも、どちらにも出ないこともない。並びの名前ラベルの画像は、いま枠に出ている人の分も先に描いておき、全画面の始まりと終わりで並びに移った人が一瞬消えないようにする。
- 並びから除くのは、次の人である。
  - 受け取りに使うサブアカウント
  - Bot (既定。[Botを表示] で出せる)
  - ほかの人の「使う声」に選ばれている人 (その声は選んだ人の名前ラベルを光らせる)
  - 参加者の設定ウィンドウで「通話のみ時ラベル非表示」を付けた人 (チェックは並びに出さない向きで、既定はチェックなし。メインアカウントの行でも付けられる。枠に載っているときの名前ラベルは変えない)
- メインアカウントだけの構成では、Discord が本人の声を返さないので、自分の枠の音声ソースを選んでいないと、並びのメインアカウントも光らず暗くもしない (自分の枠と同じ)。
- 並びは、既定でキャンバスの右下に縦に並べ、アバターを右に置いて右揃えにする (`roster_anchor`、`roster_direction`、`roster_avatar_side`)。配置は四隅と上下左右の辺の中央の 8 か所から選べ、上下の中央は横並び、左右の中央は縦並びだけにする。
- 配置と余白で決まる位置から、表示タブの [オフセット] で横と縦にずらせる (`roster_offset_x_px`、`roster_offset_y_px`。キャンバスのピクセルで、右と下が正。既定は 0、範囲は -7680 から 7680)。配信の画面の時計などの装飾と重ならないように、ピクセルで合わせるためで、キャンバスの解像度を変えてもピクセルのまま変えない。画面共有している参加者の名前ラベルには持たない (余白だけ)。
- 人と人の間は 0.25 em (`roster_gap_ratio`)。名前の幅は 12 em まで (`roster_name_max_em`。表示タブの [名前の最大幅])。長すぎる名前の人が、並びでキャンバスの幅を取らないようにするためで、超える名前は省略する (省略の仕方は映像のセルの名前ラベルと同じ)。入りきらなければキャンバスの中央の側へ折り返す。どこで折り返すかは、ずらす前の位置で決める。
- 並びは映像のセルの名前ラベルと干渉しない層として重ね、重なっても、キャンバスの外へはみ出しても、自動ではずらさない (ずらすと、利用者が配置を予測できなくなる)。
- 枠に載っている人が替わったら、新しい人の最初のフレームと同時に名前ラベルを替え、前の人の名前を新しい人の映像に重ねない。自分の枠の名前とアバターは、メインアカウントのもの (メインアカウントだけの構成では Vesktop のアカウント) を使う。
- ダミー映像は、落ち着いた単色の背景に枠の番号を大きく描画し、名前ラベルに「ダミー 1」などを描画する (`cordmux.source.placeholder.label`)。動いていることは細い線をなめらかに動かして示し、1 往復を 2 秒以上 (既定 4 秒) にする。明暗が入れ替わる形にしない。
- 映像を縦横の比を保って枠に収めて中央に置く。2 つ以上の枠は、キャンバスを 4 等分した位置 (左上、右上、左下、右下) に [並び順] のとおりに置き、自分の枠を出しているときは、[先頭に配置] が付いていれば左上に置く (外していれば、ほかの人と同じく [並び順] のとおり)。1 つだけのときは全面に置く。
- 画面共有の終わりが分かったとき (Discord から終わりが届いた、枠から外した、通話を退出した) は、待たずに枠から外して並べ直す。Vesktop との接続が切れたときとハートビートの応答が届かないときは、最後のフレームを 2 秒保ってから枠を空にし (`link_lost_hold_ms`。settings.json でだけ変えられる)、並べ直さない。並べ直すと、接続が戻ったときにもう一度配置が変わる。保っている間は、名前ラベルのアバターと参加者の並びも切れる前のままにする (見た目の一部だけが先に変わると、保っている映像と合わない)。接続し直してから 10 秒たっても映像が戻らない人の枠は、そのときに並べ直す (`reconnect_layout_hold_ms`)。
- 接続は生きているのに、ある人のフレームだけが届かないときは、枠を空にせず最後のフレームを表示し続ける。静止した画面の画面共有と止まった画面共有は、フレームの間隔だけでは見分けられないためである。

### 自分の枠

自分の行は、ほかの人の行と同じ動きにする (自分だけ、チェックの有無、枠に出す条件、外れる条件を変えない)。自分の枠に映す映像は、ドックの [表示] タブの [自分の枠に映す映像] で、「Discordの画面共有」(サブアカウントがあるとき)・OBS のソース・OBS のシーンから選ぶ。cordmux の合成のソースを含むシーンは候補に出さない。

自分の枠は、選んだ OBS のソースかシーンが合成のソースに結び付いている間だけ出る。結び付いていない間は、何も出さない。出る条件は、ドックの自分の行 (自分の枠の人の行。サブアカウントを使う構成ではメインアカウント、メインアカウントだけの構成では Vesktop のアカウント) のチェックが付いていること。チェックは、次のときに付く。

- ドックで付けたとき。
- 自分が Discord で画面共有を始めたとき。ただし、ほかの人と同じ規則のときだけ (枠に載せる人の選び方が「自動」か、自分の行の [自動で枠に載せる] が付いているとき)。「手動」で [自動で枠に載せる] なしなら、共有してもチェックは付かない。

共有を止めても、チェックは外れない。映像が OBS のソースかシーンなら、チェックがある間は映り続ける (共有と関係のない映像なので)。ドックで外した後は、ほかの人と同じく、共有をやめて始め直すまで、自動では付かない。枠が埋まっていれば人を押しのけない。

自分の共有の状態が分からない間 (送信側が未接続、facts の sharing を読めない、自分の枠の人が決まらない)は、「共有していない」と扱わず、現在の状態を変えない。

自分の行のチェックは、映像を OBS から選んでいる間、自分の枠の付け外しになる (文字列はほかの行と同じ「枠に載せる」)。映像が「Discordの画面共有」でサブアカウントがあるときは、ほかの行と同じ意味 (その人の Discord の画面共有を枠に載せる) のままである。サブアカウントがなく、映像を OBS から選んでいないときは、メインアカウントの Discord の画面共有を受け取れないので、チェックは押せず、理由を出す (「[表示] タブの「自分の枠に映す映像」で映像を選ぶと、枠に載せられます。」)。Discord の人が画面共有の枠 4 つを埋めているときは、付けられない (押せない理由は、ほかの行と同じ「空いている枠がありません」)。外す向きは、いつでも押せる。自分の行にも [自動で枠に載せる] を出す (サブアカウントがない構成の自分の行は、メニューにこれだけを出す)。

残す値は、チェックの状態 (`settings.json` の `self_frame_on`、既定 false)。付いたり外れたりするたびに書く。OBS を共有の最中に起動したときは、最初の周期を共有の始まりとして扱い、ほかの人と同じ規則で判定する。

映像を替えたときは、チェックを引き継ぐ。OBS のソースかシーンを選んだとき、メインアカウントが枠を持っていれば、自分の枠のチェックを付ける (その枠は空ける)。「Discordの画面共有」へ戻したとき、チェックが付いていれば、メインアカウントを枠に載せる。起動の途中で結び付いただけでは、引き継がない。

OBS のソースかシーンを選んでいる間は、メインアカウントの Discord の画面共有を、画面共有の枠に載せない (自動でも手動でも、自分の枠を外している間も同じ)。自分の枠と同じ画面が 2 枚出ないようにするためで、声と録画は変えない。Discord の画面共有をそのまま載せたい人は、映像を「Discordの画面共有」にする。

自分の枠を出している間は、枠に載せられる Discord の人は 3 人まで (自分の枠と合わせて 4 つ)。

### OBS の中の名前と録画ファイル

合成のソースの種類には OBS のウィンドウキャプチャのアイコン (`OBS_ICON_TYPE_WINDOW_CAPTURE`) を付ける。cordmux はシーンもソースも作らず、利用者が [+] で追加する (既にあるシーンアイテムの順は変えない)。`obs_module_name` は「cordmux」を、`obs_module_description` は 1 行の説明 (`cordmux.plugin.description.text`) を返す。

- cordmux の録画の保存先は、選んでいなければ、録画を始める時点の OBS の録画の保存先の中の「cordmux」フォルダーにする。OBS の録画の保存先が読めないときだけ、Windows の「ビデオ」フォルダーの中にする。
- 保存先に書けないときは、ほかの場所に移して書かない。録画を始めず、レベル 1 で、始められなかったこと、場所、理由、[保存先を変更] を表示する。[録画] ページの保存先の入力欄は、空のときも実際に書く場所を表示し、[フォルダーを開く] を添える。
- 録画のセッションのフォルダーの名前は、OBS の録画の既定のファイル名と同じ形 (「2000-01-01 21-30-45」) にする。直下には作成した録画ファイル (参加者ごとに画面共有と声) だけを置き、録画の中間ファイルは OBS の言語によらない名前の `data` フォルダーにまとめる。作成中の一時ファイルは、作成が成功したら消し、元のセグメントファイルは消さない。
- 録画ファイルの名前は、人の名前、種類の語 (「画面共有」「声」)、日時の順にし、書式を 1 つの文字列 (`cordmux.source.file_name.label`) に持つ。
- 診断情報の zip の名前は `cordmux-diagnostics-YYYYMMDD-HHMMSS.zip` にする。開発者が読むファイルなので、言語で名前を変えず英字だけにする。保存のダイアログのタイトルは「診断情報のエクスポート」、ファイルの種類は「診断情報 (*.zip)」にする。
