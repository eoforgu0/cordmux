# src-obs/pipeline

OBS 側の処理の流れ。ws/ の Listener が受け取った映像と音声を、デコードとタイムスタンプの調整を通して、sources/ の合成のソース (`composite_source.h`) に渡す。録画 (record/) への受け渡し、送信側に送る media と limits の決定、ドックが読むスナップショットの作成も受け持つ。仕組みは docs/architecture.md の「映像と音声の流れ」と「録画」にある。

## 入口

- `pipeline.h` の `Pipeline`: plugin-main.cpp が 1 つ作り、`start()` で ws::Listener のコールバックに自分の関数を登録する。ドックは `snapshot()` で状態を読み、`assign_slot()`、`release_slot()`、`set_assign_policy()`、`set_recording()` などで操作する。
- `pipeline.h` の純粋関数 (`decide_media`、`media_inputs_of`、`limits_from_settings`、`classify_settings_file`、`run_startup_vencord_dir_rewrite` など): 起動の処理と、送信側に送る値の判断。

## 遅れの行の読み方

10 秒ごとの統計に、ストリームごとの `Stats stream=N video_latency` と `audio_latency` の行がある。値は「受信側の OBS の時計 - 送信側のタイムスタンプを OBS の時計に換算した値」で、換算の差は接続ごとに決める (`sender_clock.h`) ので、送信側でタイムスタンプが付いてから、その段階までにかかった時間である。`recv_` は WebSocket で受け取った時 (送信側の読み出し、エンコード、送信、転送の合計)、`decoded_` はデコードし終えた時、`handed_` は OBS に渡す直前である。隣り合う差が 1 つの段階にかかった時間を表す (`decoded_` - `recv_` はキューで待った分とデコード、`handed_` - `decoded_` は整列と OBS に渡すまで)。`p95_ms` は 1 ms 刻みの近似で、`n` はその周期の数である。音声の `handed_` は、`AudioMixer` に置いた時である。音声のタイムスタンプはチャンクの先頭なので、チャンクの長さの分だけ映像より大きく出る。

映像の行の末尾の `shown_` は、OBS が実際に表示に選んだフレームの遅れである。OBS は渡されたフレームを、タイムスタンプを見て表示の時刻に合わせて選ぶので、`shown_` - `handed_` が「OBS に渡してから、表示に選ばれるまで」(OBS の中で待った分) を表す。60 fps の描画で 30 fps のフレームなら同じフレームを 2 回表示するが、表示に選ぶフレームが替わった時だけ数えるので、`shown_n` はフレームの数に近い。基準は `handed_` と同じ送信側のタイムスタンプで、OBS に渡したタイムスタンプからタイムスタンプの整列の補正と画面の音のずれの補正の分を引いて戻してある。引く値は、最後に OBS に渡したフレームの分を使うので、表示に選ばれたフレームの本当の補正とは、整列の補正の変化の分だけ違う (整列の補正は 1 フレームに最大 0.5 ms 動く)。子に付けた測定のフィルタを外す、または無効にした枠は測れず、`shown_n` が 0 になる。「表示に選ばれた」までを測っていて、そのフレームが実際に画面に出るまでの描画と、配信への出力の遅れは含まない。

## 表示の緩衝 (display_buffer_ms)

画面共有の映像を OBS に渡す時刻を、OBS の緩衝ではなく cordmux が決める渡し方である。画面共有の映像は **合成のソース** (sources/ の `composite_source.h`) の子にだけ渡す。設定の `display_buffer_ms` (ms。0 から 1000。既定値は
100) で D を決める。既定値の 100 ms は、テスト用の送信側で映像の欠落が 0 になる値で、実際の通話の映像が届くまでの遅れ (平均約 17 ms、95 パーセンタイルで約 40 ms) を吸える。

D はドックの状態タブの「映像のバッファ」で選ぶ。値は `settings.json` から起動のときに読み、動いている間はドックが設定を渡し直したときに替わる (`Pipeline::set_display_buffer_ms`)。参加者ごとの直近 1 分の届き方が、状態タブの映像の受信の表に出る。届き方の列は常に記録し、`Pipeline::set_arrival_watch(true)` の間だけ `PipelineSnapshot::arrival_by_user` にコピーする。

D が 0 でも、常にフレームを参加者ごとの待ち行列 (`FramePacer`) に積み、送信側のタイムスタンプ + D の後の最初の OBS の描く刻みに表示されるよう、その半刻み前に渡す (下の「刻みに合わせる」)。渡し先の子は OBS の緩衝なし (`async_unbuffered`) にする。D が 0 のとき OBS の緩衝を使うと、映像は OBS の緩衝の深さ (実際の通話で約 80 ms) で遅れ、音は cordmux の時刻で出てずれる。D は「送信側でフレームが生まれてから表示に選ばれるまで」の長さなので、受信までの遅れ (`video_latency` の `recv_avg_ms`) より長くしないと、フレームは届いた時点で時刻を過ぎていて、そのまま渡る (揺れを吸えない)。

渡してよいかは `frame_delivery_plan.h` の `frame_deliverable` が決める。合成のソースがない間は、待ち行列に積まずに捨てて数える。積んだ後に合成のソースがなくなったときも、渡す時点で見直して捨てて数える。

渡すスレッド (`frame_pacer_loop`) は全ストリームで 1 本である。時刻が来たフレームが同時に複数あれば最も新しい 1 つだけを渡し、古いフレームは捨てる (OBS の緩衝なしでも最新の 1 つしか表示されないため)。待ち行列の上限は D の間に届くフレームの数 (60 fps とみなす) に余裕の 6 フレームを足した数と、1 ストリームあたり 256 MiB の小さいほうで、超えると古いほうから捨てる。1080p60 の NV12 は 1 フレーム約 3.1 MB で、D = 1000 ms のときの待ち行列は 1 ストリームで約 205 MB になる。画面の音は `AudioMixer` に D を足した時刻で置き、映像とそろえる (下の「合成のソースの音」)。

### 刻みに合わせる

OBS は映像を決まった間隔の刻みで描き、刻みの直後に、非同期のソースが表示するフレームを選ぶ。フレームを送信側のタイムスタンプ + D の時刻のまま渡すと、送信側の間隔と刻みの間隔が同じ 60 fps で位相が近いときに、起きる時刻の 1 ms 程度の揺れで、1 つの刻みに 2 フレーム (古いほうは表示されない) と次の刻みに 0 フレーム (前のフレームがもう 1 回出る) が繰り返され、フレームが飛ぶ。そこで、フレームごとに「タイムスタンプ + D の後の最初の刻み」を決め、その半刻み前に渡す。渡す側と描く側の起きる時刻の揺れの合計が半刻み (60 fps で約 8 ms) 未満なら、フレームは必ず決めた刻みに表示される。同じ刻みに複数のフレームが入るのは、送信側の間隔が刻みより本当に短いとき (60 fps の共有を 30 fps で描くなど) だけである。

刻みの時刻と間隔は、`obs_get_video_frame_time` と `obs_get_frame_interval_ns` で読む (OBS の時計 `os_gettime_ns` の上)。渡すスレッドが回るたびに読み直し、OBS の映像が動いていないとき (間隔か刻みの時刻が 0) は、刻みに合わせずタイムスタンプ + D の時刻に渡す。待ち行列の積む・取り出す・待つの時計も、この OBS の時計にそろえてある。

### 表示の緩衝の行の読み方

D が正のとき (または周期の間に待ち行列が動いたとき) だけ、10 秒ごとの統計にストリームごとの `Stats stream=N video_pacer` の行が出る。

- `paced_delay_ms`: 現在の D。
- `paced_tick_us`: 渡す時刻を合わせている OBS の描く刻みの間隔 (マイクロ秒。60 fps なら 16667)。0 なら刻みに合わせていない。
- `paced_on_time`: 時刻まで待ってから渡した数。
- `paced_late`: 積んだ時点でもう表示の時刻 (タイムスタンプ + D) を過ぎていて、すぐ渡した数。多いときは D が受信までの遅れに対して短い。
- `paced_dropped`: 渡さずに捨てた数 (同時に時刻が来た古いフレーム、待ち行列の上限、ストリームの終わりの破棄)。
- `paced_queue_max`: 周期の間の待ち行列の長さの最大。D の間に届くフレームの数に近ければ、揺れを吸うために待っている。

D の動作は、同じ周期の `video_latency` の `shown_avg_ms` (OBS が表示に選んだフレームの遅れ) で確認する。D が正で `paced_late` が少なければ、`shown_avg_ms` は D に OBS の描画 1 回 (60 fps で最大 16.7 ms) を足した値の内に収まる。

## 音を混ぜるコンポーネント (audio_mixer.h)

合成のソース 1 つから全員の音を出すためのコンポーネントである。人 (user_id) と種類 (声 / 画面の音) の組ごとに音を受け取り、組ごとの利得を掛けて足した 1 本を、10 ms (480 フレーム) の区間にして返す。libobs に依存せず、時計も読まない。OBS への受け渡し (`obs_source_output_audio`) は呼び出し元の仕事である。

利用者にとっての意味は 4 つある。

1. 画面の音は、その人の画面の映像と同じ遅れ D で出て、映像とそろう。
2. 声は D で遅らせない。
3. 音量とミュートを参加者ごとに、声と画面の音を別々に変えられ、変えた結果は D を待たずに聞こえる。
4. OBS の全体の音の遅れを増やさない。

D と声の遅延を足すのは呼び出し元で、このコンポーネントは、組ごとに置く位置を渡された時刻に追従させるだけである (docs/architecture.md の「音声の時計の差の吸収」)。

- 自分で混ぜる理由: OBS は 1 つのソースに時刻が重なるように渡された音を、後に渡した音で前の音を消す形で置く (libobs の `obs-source.c` の `source_output_audio_place` は、時刻の位置に `deque_place` で上書きし、その後ろを `deque_pop_back` で切り捨てる)。参加者ごとの音をそのまま同じソースに渡すと互いに消し合う。
- 時刻の領域は 1 つで、呼び出し元が OBS の時計 (`os_gettime_ns` / 1000) に変換した値 (マイクロ秒) である。`add` の `at_us` (置く時刻) も、`take` の `now_us` も、返す区間の開始の時刻もこの領域にある。OBS はタイムスタンプが `os_gettime_ns` から 2 秒以内なら、その時刻に直接置く (`obs-source.c` の `source_output_audio_data`)。`AudioMixer` が出す区間は起点からのサンプル数で途切れずに並ぶので、OBS の側の続きの判定 (`TS_SMOOTHING_THRESHOLD`) には掛からない。
- 追従: 組ごとの `align::AudioDriftCorrector` が、前のチャンクの続きに書き、続きの位置と `at_us` の差を、ごくわずかなサンプルレートの変換で連続的に戻す。差が置き直しのしきい値 (画面の音の組は設定の `audio_resync_ms`、既定 45 ms。声の組は `voice_audio_resync_ms`、既定 70 ms。理由は `AudioMixerConfig::voice_resync_us` のコメント) を超えたときと、続けて書くと出し終えた位置より前になるときは、`at_us` に置き直す。音を取り出す時計と OBS の時計の速さの差は、この変換が吸収する。
- 先渡し: 区間の終わりが `now_us` + 先渡しの幅 (`kMixerLookaheadUs`、既定 55 ms) 以内になったら返す。ソースの音のタイムスタンプが OBS の混ぜている区間より古いと、OBS は全体の音の待ち時間を足し (`obs-audio.c` の `add_audio_buffering`)、OBS を閉じるまでは戻さない。タイムスタンプは音の出る時刻のままなので、先に渡しても音は遅れない。ただし区間の終わり近くの音は、その時刻のほぼ先渡しの幅だけ前に返る。声の J との関係は、下の「時刻の変換」の J にある。
  - OBS の振る舞い: OBS は 1 回に 1024 フレーム (約 21.33 ms。`kObsMixSpanUs` は切り上げた 21334 us) の区間を、実時間が区間の終わりを過ぎてから混ぜる (`media-io/audio-io.c` の `audio_thread`)。ソースの溜まりが 1024 フレームに満たないと混ぜずに保留にし (`obs-source.c` の `process_audio_source_tick`)、区間の終わりまでの音も溜まっていなければ、溜まりの音を捨てずに先頭の時刻を区間の終わりに付け直す (`obs-audio.c` の `discard_audio`)。以後の音は続きに積まれるので、そのソースの音は付け直した分 (最大 21.33 ms) 遅れたまま戻らず、ログにも何も出ない。続けて起きると積もる。
  - 守るべき条件は 2 つ。(1) 定常: 今より先に渡してある長さが、どの瞬間も 0 以上 (区間の終わりを過ぎてから混ぜるので、そのとき区間の終わりまで溜まっていれば足りる)。(2) 起点の直後: 最初の音の時刻は OBS の区間の途中に来るので、最初の音の時刻から 1 回分が溜まるまで混ぜない。最初の取り出しで起点から (先渡しの幅 - 区間の長さ) より先まで返すので、先渡しの幅は区間の長さ + 1 回分 (31.33 ms) 以上にする (`static_assert`)。
  - 先に渡してある長さは取り出しの直前に最も短く、先渡しの幅から「区間の終わりで返す丸め (最大 10 ms) + 取り出しの間隔 10 ms + 取り出しの起きる遅れ」を引いた長さまで減る。55 ms は取り出しが 35 ms 遅れても (1) を守る。長くすると J が同じだけ延びて声が遅れるので、短くするかは統計の `min_ahead_us` (取り出しの起きる遅れの実測) を見て決める。
  - 統計の `min_ahead_us` と `short_ahead_takes` が、(1) の監視である (下の統計)。
- 起点: 最初の `add` か `take` の `now_us` から、無音の区間で返し始める。最初の音の位置から始めると、D を足した遠い位置の画面の音が先に届いたとき、後から届く声の位置が起点より前になって捨てられる。`now_us` より前から始めると最初からタイムスタンプが古い。音のない区間も無音として返し続ける (返さない区間があると、OBS は時刻の飛びとして扱う)。やめるのは `reset()` のときである。区間の開始の時刻は起点からのサンプル数で計算するので、丸めの誤差は積もらない。
- 利得は返すときに掛ける。置くときに掛けると、D だけ先に置いた画面の音の音量が、操作から D だけ遅れて聞こえる。変えたときは次の区間の中で前の値から新しい値へ直線で移し、プチッと鳴らさない。ミュートは利得 0 と同じ扱いで、`remove` した組も次の区間で 0 へ移してから捨てる。
- 切りそろえない: 振れ幅を -1 から 1 に切りそろえるのは、ソースの音量 (ミキサーのフェーダー) を掛けた後の最後の段階である (`media-io/audio-io.c` の `clamp_audio_output`)。ここで切りそろえると、利用者がミキサーで音量を下げても割れた音が残る。
- 取り出しが遅れたとき: たまった区間は続けて返す。ただし区間の開始の時刻が `now_us` から 20 ms (`late_limit_us`) より古くなる区間は返さずに飛ばして数える。古いタイムスタンプの音をまとめて渡すと OBS が待ち時間を足すためである。20 ms は OBS が 1 回に混ぜる長さより約 1 ms 短く、OBS が混ぜている区間の始まりがどこまで過去かは測っていない。OBS が混ぜている区間の始まりは今から 1 回分ほどの過去にあり、先渡しの幅には依らないので、先渡しの幅を変えても動かさない。
- 置き直しの数: Discord は無音の間は送らないので、声が話し始めるたびに許容幅を超えた置き直しを数える。多くても不具合ではない。
- 保持の上限: 組ごとに、出し終えた位置から 108720 フレーム (約 2.27 秒。声の遅延の上限 2000 ms、揺れを吸う幅 200 ms (この計算にだけ使う値で、声を置く時刻の J の既定 65 ms より大きい)、先渡し 55 ms、チャンク 480 フレーム) まで先の音を持つ。1 組で約 0.87 MB (フレーム数 x 2 チャンネル x 4 バイト) で、音を出している組の分だけ確保する。30 人の声と画面共有 4 つの音の 34 組で約 30 MB (声の枠に上限はないので、組の数は話した人の数で増える)。出し終えた位置より前の音と、上限より先の音は捨てて数える。
- 統計 (`take_stats`): 組ごとに置いた・遅れて捨てた・先すぎて捨てた・置き直したフレーム数と回数、全体で返した区間の数、取り出しの遅れで開始の時刻が `now_us` より前になった区間の数、飛ばした回数と長さ。あわせて、取り出しのはじめ (区間を返す前) に測った、今より先に渡してある長さの周期の最小 (`min_ahead_us`) と、それが 0 を下回っていた (先に渡した分を使い切っていた) 取り出しの回数 (`short_ahead_takes`)。起点ができた後の最初の取り出しは測らない。

## 合成のソースの音

画面の音と声は `AudioMixer` に置く。専用のスレッド (`mixer_loop`。`frame_pacer_loop` とは別) が 10 ms ごとに混ぜた区間を取り出し、合成のソースに `obs_source_output_audio` で渡す (48 kHz、ステレオ、float のインターリーブ。タイムスタンプは区間の開始の時刻)。ミキサーに出る cordmux の行は 1 つで、全員の音にトラック・モニター・フィルターを OBS の普通の操作で掛けられる。合成のソースがない間と、ダミー表示の間は、音を置かずに捨てて数える (`composite_audio_plan.h` の `mixed_audio_admitted`)。ダミー表示は映像を色のタイルに替える表示である。

### 時刻の変換

`AudioMixer` の時刻はすべて OBS の時計 (`os_gettime_ns` / 1000) の上にある。送信側のタイムスタンプ (整列した値) は送信側の時計の上にあり、接続ごとに決めた差を足して変換する (`sender_clock.h` の `sender_to_obs_us`)。映像の待ち行列が `age` を決める変換と同じ差なので、画面の音と映像は同じ基準でそろう。

- 画面の音の置く時刻 = 変換した時刻 (`av_offset` の `map_audio` の後) + D + 半刻み - 負の補正の絶対値。
- 声の置く時刻 = 届いた時の OBS の時計 + J + 声の遅延 (`voice_audio_delay_ms`)。

**半刻み** (`screen_audio_half_tick_us`): 映像は「時刻 + D の後の最初の刻み」に表示されるので、刻みの上に来るまで 0 から 1 刻み、平均で半刻み遅れる。画面の音にも OBS の描く刻みの間隔の半分を足して、平均で映像とそろえる。刻みの間隔は `obs_get_frame_interval_ns` で読み、読めなければ (OBS の映像が動いていない) 足さない。

**J** (`kVoiceMixJitterUs`、既定 65 ms): `AudioMixer` は区間の終わり近くの音を、その時刻の先渡しの幅 (55 ms) だけ前に出す。声のチャンクの先頭がその区間のどこに来るかは決まっていないので、J は先渡しの幅以上にする (`static_assert`)。短いと、チャンクの先頭が届く前にその区間を返してしまう。足している 10 ms は届き方の揺れの余裕である。実際の通話で測って決めた値ではなく目安の値で、声は J の分だけ遅れて鳴る。

**画面の音の下限**: 画面の音の置く時刻は、届いた時の OBS の時計 + J より前にしない。D が小さい (D = 0 も選べ、映像は待ち行列を通る) と、計算した時刻が `AudioMixer` の受け付ける位置より前になり、画面の音が全部「遅れて届いた分」として捨てられて無音になる。下限があれば、映像より少し遅れても音は出る。そのときのずれは J - D - 半刻み ほどである (D = 0 で約 57 ms)。

**負の補正**: `screen_audio_offset_ms` が負のとき、画面の音の置く時刻から絶対値を引く (映像は遅らせない)。映像の表示の時刻は待ち行列が決めるので、映像のタイムスタンプに足しても表示の時刻は変わらない。

### 組の出入りと利得

組は人 (user_id) と種類 (声 / 画面の音) である。画面の音は画面共有の人、声は枠に載っている人の組に入れる。使う声 (`voice_links`) で別の人の声を運んでいる枠でも、枠に載っている人の利得が動作する。

- 経路や割り当てが変わる所 (configure、枠の付け替え、枠から外す、切断、停止) で、名簿 (`MixerRoster`) を経路と割り当て表から作り直し、どのストリームも使わなくなった組を `AudioMixer::remove` する。枠を空けられた前の人の残りの音は鳴らない。
- 音のチャンクが届くたびにも、組が変わっていないかを見る。
- `AudioMixer` は remove すると利得も捨てるので、参加者ごとの利得とミュートは pipeline の表 (`MixerLevels`) が持ち、組が名簿に入るたびに当て直す。音量は 0 から 200 の % (利得は 100 で割った値) で、既定は 100% とミュートなし。変える口は `Pipeline::set_person_audio_volume`、`set_person_audio_mute`、`set_person_volumes` (ドックの人の行の操作が呼ぶ)。
- 自分の声 (メインアカウントの声。下の「自分の声」) のミュートは、参加者ごとの値ではなく 1 つ (`self_voice_muted`。既定はミュートで、settings.json の同じ名前のキーを起動のときに受け取る)。メインアカウントの userId が替わっても、新しい人の声に同じ値が当たる。
- 画面共有の音は、共有が始まるたびにミュートから始める。始まりは、configure に画面のストリームがある人と facts の sharing にいる人の和 (`screen_sharers_of`。sharing が信じられないときは configure だけ) が新しく現れたことで見分ける (`ScreenShareTracker`)。`handle_configure` と `handle_facts` の両方から見分ける。受け取る範囲が「枠に載せた人だけ」のとき、視聴を始めるまでストリームが現れず、チェックを外すと消えるが、共有は続いているので、facts の sharing も見る。枠の付け替えで組が出入りしても始まりではない。送信側との接続が切れた後、`kShareResumeWindowUs` (10 秒) の間に同じ人の画面のストリームが戻れば、同じ共有の続きとして扱い、外したミュートを戻さない。
- 枠の割り当て (`try_assign`) の判断は、参加者ごとのミュートと音量を理由にしない。ミュートと音量は人に付き、枠を別の人に割り当て直しても前の人の値は失われず、次の人にも引き継がれないためである。シーンコレクションを切り替えても、参加者ごとの値はそのまま動作する。
- 表示の緩衝 D を変えたら、全員の画面の音の組を `AudioMixer::resync` する (続きに置く許容 (`audio_resync_ms`) が D の変更を飲み込むため)。
- `AudioMixer::reset()` は、`Pipeline::start()` と `stop()`、合成のソースが現れた・なくなったときに呼ぶ。

### ロックの順

`mixer_mu` は `AudioMixer` と名簿と参加者ごとの音量とミュートの表を守る。受信の関数は `mu` を持ったまま取ってよい。取り出すスレッドは `mixer_mu` だけを持ち、その中で `mu` を取らない。取り出した区間は `mixer_mu` を放してから `obs_source_output_audio` に渡す (libobs はその中で `filter_mutex` の下に利用者が付けた音のフィルタを動かすため)。渡す相手は `sources::output_composite_audio` が参照を取るので、消されている最中のソースには渡らない。

### 統計の行の読み方

10 秒ごとの統計に、次の行が増える。人の ID は書かず、ストリームの番号か枠の番号で書く。

- `Stats stream=N video_arrival ...`: 画面のストリームの、届くまでの遅れ (表示の緩衝の待ち行列に積むときの OBS の時計と、送信側のタイムスタンプを OBS の時計に換算した値の差) の分布。合成のソースがあるときだけ出る。`arrival_p50_ms`、`arrival_p95_ms`、`arrival_p99_ms`、`arrival_max_ms` は直近 `arrival_window_s` 秒 (最大 60) のフレームの分布で、`arrival_n` はそのフレームの数。p50 から p99 は 1 ms 刻みの上端 (実際の値より最大 1 ms 大きい)。`arrival_window_late_pct` は、その範囲で現在の D (`paced_delay_ms`) にしていたら間に合わなかったフレームの率 (%) で、「D を X にしたら何 % が間に合わないか」は、同じ分布から X を替えて求められる (`ArrivalDelayStats::late_fraction_at`)。`arrival_late` はこの周期の間に合わなかったフレームの数 (`paced_late` と同じ数)、`arrival_late_runs` は続けて間に合わなかったフレームを 1 つと数えたまとまりの数で、見た目のカクつきの回数に近い。
- `Stats mixer ...`: `AudioMixer` のこの周期の数。`mixer_blocks` は出した区間の数、`mixer_catch_up` は取り出しが遅れて開始の時刻が今より前で出した区間の数、`mixer_skips` と `mixer_skipped_frames` は遅れが限度を超えて飛ばした回数と長さ、`mixer_tracks` は今ある組の数。`mixer_catch_up` や `mixer_skips` が増えるときは取り出しが遅れている。`mixer_min_ahead_ms` は取り出しのはじめに測った、今より先に渡してある長さの周期の最小 (ミリ秒、小数 1 桁。測らなかった周期は `none`。先渡しの幅から取り出しの起きる遅れを引いた長さになる)、`mixer_short_ahead` はそれが 0 を下回っていた取り出しの回数。0 でないと、OBS が合成のソースの音の時刻を付け直し、音が 21.3 ms ずつ遅れたまま戻らないことがある (積もっていないかは、長い配信の `mixer_short_ahead` が 0 のままかで見る)。
- `Stats mixer_track voice|screen_audio slot=N ...`: 組ごとの数 (周期の間に何かを数えた組だけ。枠にいない組は `slot=0`)。`late_frames` は出し終えた位置より遅れて届いて捨てた長さ、`ahead_frames` は先すぎて捨てた長さ、`replaced` は置き直した回数、`placed_frames` は置いた長さ (フレーム数)。声の `late_frames` が増えるときは J が足りない。`drift_ppm` は推定した、音を取り出す時計と OBS の時計の速さの差 (正は音の時計が遅い)、`max_error_ms` は周期の間の `at_us` と続きの位置の差の最大で、これが置き直しのしきい値に近いときは、時刻の揺れが大きい (`audio_resync_ms` か `voice_audio_resync_ms` を上げるか、`audio_drift_time_constant_ms` を長くする)。

### 自分の声

サブアカウントの構成では、メインアカウント (settings の `broadcaster_user_id`) の声もサブアカウントの Vesktop に届く。

- 経路。合成のソースがあるときは、メインアカウントの声にもほかの人と同じく声の枠の経路を作る (声の枠を 1 つ使う)。合成のソースがないときは作らない (`stream_router.h` の `AssignPolicy` の `route_main_account_voice`)。合成のソースの有無が変わったら、直前の configure を適用し直す (`refresh_layout_presence`)。
- 既定のミュート。ミキサーでの自分の声の既定はミュート (配信の音に混ぜない) で、`MixerLevels::set_self_voice_user` で決めた人の声の組に適用される。利用者は OBS のマイクで自分の声を配信に出していることが多く、Discord を通った声も鳴らすと遅れて二重になる。Discord を通った声を配信に出したい人は、ミュートを外す (`Pipeline::set_person_audio_mute`)。自分の声の人はドックの `set_assign_policy` が渡し、起動のときは settings からコピーする。
- 話しているかの判定。自分の声の組だけは、利得とミュートを掛ける前の音で判定する (`AudioMixer::set_activity_before_gain`)。ミュートしていても、受け取った声で自分の枠が光り、黙ると暗くなる。ほかの人は掛けた後の音で判定する。
- メインアカウントだけの構成では、Discord が本人の声を返さないので、自分の声の経路はない。

### 話している人の光

合成のソースの名前ラベルの光 (sources/ の `composite_decor.h`) は、送信側の「話している」のシグナルではなく、ミキサーが声を OBS へ出した区間にその人の声の音があったことで決める。シグナルは声が OBS に出る前の事実で、実際に鳴る時刻とずれ、OBS のミキサーでミュートした声も光ってしまうためである。

- 聞こえる音。`AudioMixer::take` が返す区間 (`MixedBlock`) の `audible_voices` に、その区間で利得とミュートを掛けた後のチャンネルの絶対値の最大が `AudioMixerConfig::audible_peak` (既定 0.001、-60 dBFS) を超えた声の組の user_id を入れる (自分の声の組は、掛ける前の値で比べる。上の「自分の声」)。画面の音の組と、`remove` して 0 へ移している最中の組は入れない。Discord は話していない間は音を送らず、送られない間は組に音がない (出し終えた位置より先に音がない) ので、無音の間は対象にならない。しきい値が除くのは、ミュートや利得 0 への直線の移りの末尾と、浮動小数点数のごく小さな値である。話し声のふつうの振れ幅は、これよりずっと大きいと見込んでいるが、小さく話したときの振れ幅は測っていない。しきい値と下の息継ぎの長さは定数で、設定のキーにはしていない。利得を掛けた後の値で比べるので、音量を絞って聞こえなくなった人は光らない。
- 話し始めと話し終わり。`mixer_loop` が区間を受け取るたびに `VoiceActivity::observe` に渡す。聞こえる声が現れた区間の開始の時刻 (音が鳴る時刻。光と声がそろう) が話し始め、聞こえない区間が `kVoiceActivityGapUs` (100 ms) 続いたら、最後に音があった区間の終わりを話し終わりにする。息継ぎや語の間の 10 ms の無音で、話し終わりと話し始めを繰り返さないための長さである。時刻は OBS の時計 (`os_gettime_ns` と同じ領域のナノ秒) で、sources/ の `set_voice_speaking` が表に入れる。光の明るさの立ち上がり、保持、消えるまでの形は、合成のソースの光と同じ式 (`label_border.h`) で、描くたびに現在の時刻から求める。
- ロック。`VoiceActivity` を触るのは `mixer_loop` だけ (起動の前と停止の後の `reset` を除く)。`mixer_mu` の中で `take` までを行い、放してから `observe` と `set_voice_speaking` を呼ぶ。`set_voice_speaking` が取るのは、表のロック (ほかのロックを取らないロック) だけで、`mu` は取らない。合成のソースが現れた、なくなった、停止した、のときは、`VoiceActivity` を `reset` し、`clear_voice_speaking` で表の発言を捨てる (光を残さない)。
- 枠の描く人との結び付け。声の組の user_id は、声の枠に載っている人 (`mixer_key_for` の `slot_owner`) で、画面共有の枠の描く人 (`set_decor_owner`) は、その画面共有をしている人 (経路の user_id) である。同じ人なら同じ文字列なので、user_id の一致で結ぶ。「使う声」で別の人の声を運んでいる枠でも、声の組は枠に載っている人のままなので、枠に載っている人の声で光る。自分の枠の描く人はメインのアカウント (または Vesktop のアカウント) で、その人の声がミキサーの声の組にあるとき (サブアカウントの構成で、合成のソースがあるとき) だけ光る。
- 話している人の音が途中で届かなくなっても、光は残らない。合成のソースがある間、`AudioMixer::take` は音のない区間も無音として返し続け、その区間の `audible_voices` は空なので、`observe` が 100 ms の後に話し終わりにする。
