# src-obs/sources

OBS のソース。合成のソース 1 種類を登録する。ダミー表示、アンインストールで cordmux のものを削除する処理もここにある。cordmux はシーンもソースも作らない (利用者が OBS の [+] から置く)。仕組みは docs/architecture.md の「OBS のソースとシーン」と「シーンコレクションを切り替えたとき」に、利用者から見える動作は docs/spec.md の「枠と配置」「名前ラベルと話している人の光」「自分の枠」にある。

## 入口

- `sources.h` の `register_source_types()`: plugin-main.cpp が obs_module_load の中で呼び出し、ソースの種類を登録する。
- `composite_source.h`: 合成のソース `cordmux` (後述)。ドック (dock/dock_poll_layout.cpp) が周期ごとに配置の入力を `set_composite_input()` で渡し、pipeline/ が合成のソースの有無を `composite_present()` で読む。
- `self_frame_source.h` の `sync_self_frame()`: ドックが周期ごとに呼び出し、設定の `self_frame_source_uuid` と `self_frame_source_name` で自分の枠に映すソースを探して、合成のソースに結び付ける (`composite_bind_self_frame()`)。`list_self_frame_candidates()` が表示タブの候補を集める。
- `screen_feed.h`: pipeline/ が、デコードした映像を合成のソースの子に渡し (`push_screen_video`。合成のソースがあるときだけ呼ぶ)、枠を空ける (`clear_screen_now`、`hold_then_clear_screen`)。いつ空けるかは `screen_end.h` の `screen_end_action` が決める。音声は pipeline/ が混ぜて、合成のソースから出す (`composite_source.h` の `output_composite_audio`)。
- `decor_registry.h` の `set_decor_label_params()`、`set_person_decor()`、`set_decor_owner()`、`set_voice_speaking()`: 名前ラベルの見た目の値、人の名前とアバター、枠の名前ラベルに描く人、ミキサーの声から求めた発言を、名前ラベルと光の表に渡す。
- `dummy_feed.h` の `set_dummy_mode()`: ダミー表示の ON と OFF。番号の入った背景は、ダミーのフレームを渡すスレッドが、始めたときとキャンバスの大きさが変わったときに描画する (名前ラベルの描き直しのスレッドと同じく、QImage と QPainter で描く。下の「Qt の文書」)。
- `cordmux_removal.h` の `remove_cordmux_objects()`: アンインストールで、現在のシーンコレクションの中の cordmux のものを削除する (install/ が呼び出す)。
- `double_audio.h` の `read_double_audio_state()`: ドック (dock/dock_poll.cpp) が周期ごとに呼び出し、声が二重に配信に入る構成かを判断するための値を読む。

## 合成のソース

利用者がシーンに置くソース `cordmux` (型の ID は `cordmux_composite`) 1 つで、参加者ごとの画面共有と自分の枠を、キャンバスの 4 等分の決まった位置に描く。位置は `composite_layout.h` の `plan_composite_layout` が、ドックの行の枠の位置と同じ `ledger/slot_cells.h` の `plan_slot_cells` で決める (自分の枠は、設定の self_slot_first が真 (既定) なら左上で、偽なら画面共有と同じ並び順。画面共有の位置は設定の並び順で決まる。人数が変わっても 4 等分の形は変えない)。

- 型。`OBS_SOURCE_VIDEO | OBS_SOURCE_CUSTOM_DRAW | OBS_SOURCE_AUDIO | OBS_SOURCE_DO_NOT_DUPLICATE`。`OBS_SOURCE_COMPOSITE` は付けない (OBS は COMPOSITE と AUDIO の組を登録できない)。大きさは OBS の映像の基本の解像度。
- 子。画面の枠 (1 から 4) ごとに非公開の子 `cordmux_tile` (非同期の映像だけ) が 1 つずつあり、最初の合成のソースを作るときに作って、最後の合成のソースを削除するとき (と `obs_module_unload`) に解放する。子は `obs_source_create_private` で作り、`OBS_SOURCE_CAP_DISABLED` で「ソースを追加」の一覧に出さない (`obs_source_create_internal` は CAP_DISABLED を見ないので、非公開の作成は止まらない)。シーンコレクションには保存されない。
- 映像の渡し先。`push_screen_video` は枠の子に渡す (合成のソースがなければ渡さない)。
- 自分の枠の映像。利用者がドックの [表示] タブの [自分の枠に映す映像] で選んだ既存の OBS のソースかシーン (設定の `self_frame_source_uuid` と `self_frame_source_name`) を、UUID と弱参照でモジュールに 1 つ持つ (`target_ref.h`)。合成のソースは自分でソースを選ぶプロパティを持たず、どの合成のソースも同じソースを描く。探すのは `self_frame_source.h` の `sync_self_frame` で、UUID で探し、見つからなければ名前で探す。名前で見つけたときと、ソースの名前が変わったときは、設定の UUID と名前を書き直す。見つからない間は、ドックの周期ごとに探し直し、シーンコレクションの切り替えで結び付けを外して探し直す。`composite_bind_self_frame` が結び付け、アクティブか表示中の合成のソースにだけ `obs_source_add_active_child` と `obs_source_remove_active_child` で替えたことを伝える (循環で `obs_source_add_active_child` が偽を返したら、結び付けない)。候補は映像を持つソースと、cordmux を含まないシーンで、cordmux の種類は含めない (描画のループを作らない)。選んだ後にシーンへ cordmux を足されたら、周期の確認で結び付けを外す。描画には再入の守りがある。
- 表示の遅れの測定。OBS が表示に選んだフレームは、子に付けた非公開のフィルタ `cordmux_tile_probe` の `filter_video` が受ける。`obs_source_get_frame` は描画が受け取るフレームを奪うので、描画の前にも後にも使えない。
- 配置の入力。ドックが周期ごとに、見えている画面共有の枠、自分の枠を出しているか、枠に載っている人の表示名と user_id、すき間を `set_composite_input()` で渡す (`composite_input.h` の `make_composite_input` が作る)。描画のスレッドが次の描画から使う。同じ入力に、cordmux がその人の声を聞けるか (`CompositeShare::hears_voice` は既定で真、`CompositeInput::self_hears_voice` は既定で偽) と、画面共有していない参加者の一覧 (`CompositeInput::roster`。user_id、名前、声を聞けるか) も入る。どの値を入れるかはドックが決める (dock/README.md の「合成のソースに渡す値」)。シーンアイテムの変形による自動配置はしない。
- 全画面。配置の入力の `focus_user_id` の人のタイルが、全画面でないときの配置にあれば、`plan_composite_layout` はそのタイルだけをキャンバスの全面に描く (`CompositeLayout::focused`)。どの人をどの枠に載せているかと `dropped` は変えない。全画面で描かれなくなったタイルの人は、画面共有していない参加者の並びに出る (下の「名前ラベルと話している人の光」の並び)。全画面にできるタイルと全画面をやめる条件は、`composite_input.h` の `composite_focus_tiles` と `focus_after_layout` が決める (docs/architecture.md の「全画面」)。配置が変わるたびに、ログに `Composite layout canvas=... count=... self=x,y,w,h slotN=x,y,w,h ...` の 1 行を書く。
- ロック。`composite_source.h` の冒頭に順がある。描画のスレッドが取るのは短いモジュールのロックだけで、子の作成と解放と、子へのフレームの出力は、そのロックの外で行う。

### 名前ラベルと話している人の光

`composite_video_render` が、全部のタイルの映像を描いた後に `CompositeDecor` (`composite_decor.h`) で重ねる。何をどの順にどこへ置くかは `composite_draw_plan.h` の `plan_composite_draws` が決め、`composite_decor.cpp` はそのとおりに置くだけである。順は、全部のタイルの枠の光、全部のタイルのアバターと名前の光、全部のタイルの名前ラベル、続けて画面共有していない参加者の光と名前ラベル。アバターと名前の光はセルの境で切らずにキャンバスの外だけで切り、名前ラベルと枠の光はセルの外を切る。光をタイルごとに映像のすぐ後に重ねると、隣へ広がった光が後に描く隣の映像の下に隠れ、セルの境でまっすぐ切れて見えるためである。映像がまだないタイルと、空けた後のタイルには重ねない。同じ計画を CPU で重ねる `composite_draw_cpu.h` は、同じ画像を同じ式 (乗算済みアルファの「元 + 下 x (1 - 元のアルファ)」、光には明るさを 4 つのチャンネルに掛ける) で重ねるので、テスト (`decor_tests`) とプレビューツール (`decor_preview` の `--composite-sample` と `--composite-sweep`) は製品と同じ値を GPU なしで確認できる。

- 大きさと位置。名前の大きさ (文字の大きさ) = キャンバスの高さ x `label_em_ratio_pct`、枠の隅からの余白 = キャンバスの高さ x `label_margin_pct`。位置の基準は映像の矩形ではなくセル (`tile.rect`)。合成のソースはキャンバスのピクセルで描くので倍率は 1 で、合成のソースのシーンアイテムを縮めれば、名前ラベルも一緒に縮む。余白、背景の内側の余白、アバターと名前の間は、見える縁 (縁取りの外側) から測る。縁取りを太くすると名前ラベルが大きくなり、アバターと名前の間が詰まったり、縁取りが背景の外へ出たりしない。
- 表の読み出し。名前、アバター、角、ほかの名前、枠の描く人、見た目の値は、表 (`decor_registry.cpp` の `DecorRegistry`) から `read_composite_decor` で読む。取るのは表のロックだけで、枠ごとの描く人 (ダミー表示の間の画面共有の枠はダミーの人)、発言、暗さ (`dim_pct`) はいつもコピーし、人の情報と見た目の値は、表の version と描く人が前にコピーしたものと違うときだけコピーする。画面共有していない参加者の値は `read_composite_roster` で読む (並びの設定と発言はいつも、参加者ごとの名前とアバターは、その人の version が前にコピーしたものと違うときだけコピーする)。合成のソースの見た目の値 (`set_composite_label_look`) は別の version を持つので、合成のソースだけの設定を変えても、表の version は進まない。自分の枠の描く人は `set_decor_owner(kSelfSlot, ...)` で入る。
- 枠の背景。映像を描かない所 (空いた枠、枠の間隔、映像の縦横の比が枠と違うときの余り、誰も載っていないときのキャンバス全体) の色で、設定は `slot_background_show` (既定は true)、`slot_background_color` (既定は `#000000`)、`slot_background_opacity_pct` (既定は 100)。ドックが、設定を変えたときと起動時に、名前ラベルの見た目の値と同じ経路 (`DockPoll` の `push_runtime_values`) で `set_composite_background` に渡し、描画のたびに `read_composite_background` でコピーする (version は持たない)。`composite_video_render` が、タイルの映像を描く前に `CompositeDecor::draw_background` を呼び、キャンバス全体に 1 枚の矩形を敷く (タイル、名前ラベル、光、参加者の並びより下。全画面、ダミー映像、自分の枠のときも同じ)。映像は不透明なので、映像のない所にだけ見える。表示を切っているときと不透明度が 0 のときは、何も描かず (描画の処理も呼ばず)、テクスチャも持たない。色の流れは名前ラベルの背景の画像と同じで、乗算済みアルファの 1 画素のテクスチャ (`GS_BGRA`。色か不透明度が変わったときだけ作り直す。画素の値は Qt の乗算済みアルファの式と同じ `composite_background_premultiplied`) を、標準の効果 (`OBS_EFFECT_DEFAULT`) の `Draw` で、混ぜ方 `GS_BLEND_ONE` と `GS_BLEND_INVSRCALPHA` (混ぜるのが止まっていても有効にする) でキャンバスの大きさに伸ばして置く。色を `OBS_EFFECT_SOLID` に直接渡さないのは、HDR や線形の sRGB の描画で、名前ラベルの背景と色がずれるおそれがあるためである。既定が透明なのは、既定で色を置くと配信の画面を汚すためで、誰も載せずに背景を表示しなければ、参加者の並びだけを出せる。
- 描き直すキーと、描き直すスレッド。画像は CPU の QPainter で描くが、描画のスレッドでは描かない。1 回の描画は、1080p の枠の光で約 25 ms、名前の大きさ 27 px の名前ラベルで約 5 ms、名前の大きさが最大の 92 px で約 20 ms かかる。ぼかしと広がりを大きくすると増え、どちらも範囲の上の端なら約 0.5 秒になる。
  - スレッド。描き直しとテクスチャを作るのは `CompositeDecor` ごとに 1 つの専用のスレッドで、その受け渡しは `composite_paint_handoff.h` の `PaintHandoff` である。描画のスレッドは、キーを毎フレーム計算し、テクスチャにある画像のキーと違えば仕事 (名前、アバターの QImage、角、ほかの名前、見た目、大きさをコピーしたもの) を渡す。同じキーの仕事が待っているか、描いている最中か、描き終えて受け取り待ちなら渡さない。タイル (並びの位置) の名前ラベルと枠の光ごとと、画面共有していない参加者 1 参加者ごとに待たせる仕事は 1 つで、新しい仕事が来たら古い未着手の仕事は捨てる。描き直しのスレッドは QImage と QPainter で描き、描いた画像を、そのスレッドで `obs_enter_graphics` に入って `gs_texture_create` でテクスチャにする。できたテクスチャはロックで守った保存先に置かれ、描画のスレッドがフレームのはじめに、いま欲しいキーと同じものだけ受け取って前のテクスチャと置き換える。違うキーのものは捨てる。
  - Qt の文書。描き直しのスレッドで描ける根拠である。QPainter は QImage への描画なら GUI のスレッド以外で使える。別々の QImage になら 2 つのスレッドが同時に描ける。QImage は暗黙の共有で、スレッドをまたいでコピーできる。QFontDatabase の関数はスレッドセーフで、QFont はリエントラントである。
  - キー。名前ラベルとアバターと名前の光のキーは、表の version、見た目の version、枠の描く人、セルの大きさ、名前の大きさと余白 (1/64 ピクセルに丸める)、画面共有していない参加者の名前である。ダミー表示の開始と停止は表の version を変えずに描く人を替えるので、描く人をキーに入れる。ほかの人と見分けるための名前は、表にある映像の枠の人の名前に、画面共有していない参加者 (並びを出す形のときだけ) の名前を足したもので、並びは表の version に入らないので、その名前をキーに入れる。枠の光のキーは、セルの大きさ、色、ぼかし、広がりだけで、人が替わっても描き直さない。キーは `composite_label_plan.h` にあり、キャッシュはタイルの並びの位置ごとに持つ。描く人がいない枠は、仕事を渡さずにすぐ画像を破棄する。画面共有していない参加者のキー (`CompositeRosterLabelKey`) は、user_id、人の情報の version、見た目の version、並びのアバターの位置、名前の大きさ、描くセルの大きさ (名前の幅の上限とキャンバスの高さ)、ほかの人と見分けるための名前で、キャッシュは参加者ごとに持つ。
- テクスチャを作るスレッド。OBS のグラフィックスのコンテキストは 1 つのミューテックスで、描画のスレッドはフレームを描く間 (`gs_begin_frame`、`output_frame`、`render_displays`) だけ持ち、`tick_sources` と次のフレームまでの `video_sleep` の間は放している (OBS 31.1.1 の `libobs/obs-video.c` の `obs_graphics_thread_loop`)。描画のスレッドの中でテクスチャを作ると、作る時間 (大きな光の画像では 12-27 ms を測った) がそのままフレームを描く時間に足される。描き直しのスレッドで作ると、描画のスレッドが待っている間に作れる。ただし、作る間はコンテキストを持つので、描画のスレッドが次にコンテキストに入るまでに終わらなければ、その分だけ描画のスレッドを待たせる。持つ時間を短くするため、形式の変換はコンテキストの外で行い、大きな画像は横長の帯に分けて、帯 1 つごとにコンテキストに入り直してテクスチャにする (`composite_texture_strips.h`)。
  - 帯の大きさの上限は 512 KB (幅 x 4 バイト x 行数) である。OBS の中で測ると、6.5 MB の光の画像 1 つに 11-24 ms、2 MB の画像に 4 ms 未満かかった (1 MB あたり 2-4 ms で、最初の確保は遅い)。描画のスレッドを 1 回に待たせる時間を 5 ms 以下にするため、512 KB (長くても 2 ms ほど) にして 2 倍の余裕を持たせる。上限以下の画像は 1 つのテクスチャのままにする。帯の中身は QImage の行をそのまま渡す (コピーしない)。
  - 帯は上下に 1 行ずつ余分に持ち (画像の端の側には持たない)、余分の行を除いた行だけを置く。合成のソースがシーンで拡大縮小されて Linear で読むとき、帯の境で隣の行を読めるので、1 枚のテクスチャで置いたときと同じに見える。等倍ならピクセルも同じである。
  - 帯を 1 つ作ってコンテキストを出たら、描画のスレッドが次のフレームに進むまで (`obs_get_video_frame_time` の値が変わるまで、1 ms ずつ眠って見に行く) 次の帯を作らない。続けて入ると、ミューテックスを待っている描画のスレッドが間に入れないことがあるためで、待たせるのは 1 フレームに帯 1 つ分までになる。この値は `obs_graphics_thread_loop` の末尾の `video_sleep` が、ソースが見えているかに関係なく毎フレーム書き、書くのはコンテキストを放した後である。待つ長さの上限は 100 ms で、OBS を終えるときのように描画のスレッドが止まっても、描き直しのスレッドは止まらない。
  - その代わり、名前ラベルが出るまでが帯の数 x 1 フレームだけ遅れる (60 fps で帯が 7 つなら約 120 ms)。配信のフレームを遅らせないことを優先した結果なので、この遅れを縮めるために待ちを外さない。全部の帯ができるまで新しい画像は描かず、一部の帯を作れなければ、テクスチャのない画像として扱う。
  - 描画のスレッドに OBS のタスク (`obs_queue_task` の `OBS_TASK_GRAPHICS`) で作らせる方法は、描画のスレッドで作るのと同じ時間がかかるので採らない。フレームの終わりをタスクで伝える方法も、待ちをやめた後や描画のスレッドが止まった後にタスクが残り、壊した物を指すことがあるので採らない。
  - テクスチャは書き換えないので `GS_DYNAMIC` を付けずに中身を渡して作る。libobs の D3D11 は渡した中身のコピーを持ち、デバイスを作り直したとき (GPU のドライバーのリセットなど) にそこから作り直す。中身を渡さずに作って後から書けばコピーの分だけ早いが、作り直したときに透明になり、次に描き直すまで名前ラベルが消えるので、そうしない。
- 新しい画像ができるまでの間。描く人が替わった (キーの描く人が違う) ときは、前の人の名前ラベルと光を描かない (違う人の名前を見せない)。描く人が同じで見た目や大きさだけが変わったときは、前の画像をそのまま描いてちらつきを避ける。ただし前の画像が現在のセルからはみ出すときは、名前ラベルが位置のずれたまま切れて見えるので描かない (`composite_keeps_previous_label`)。光は名前ラベルと同じ判断に従う。枠の光はセルの大きさが同じときだけ前の画像を描く (`composite_keeps_previous_frame_glow`)。
- 描き直しの計数。10 秒ごとの `Stats composite_decor` の行に、渡した仕事の数 (`decor_submitted`)、描き終えた数 (`decor_painted`)、捨てた数 (`decor_dropped`)、1 回の描画 (QPainter) の時間の最大 (`decor_paint_max_ms`)、テクスチャを作るために描き直しのスレッドがグラフィックスのコンテキストに 1 回 (帯 1 つ) 入っていた時間の最大 (`decor_upload_max_ms`。描画のスレッドを 1 フレームに待たせうる時間の上限)、描画のスレッドが受け取って置き換えた仕事の数 (`decor_uploads`。帯の数ではない) とその 1 回の時間の最大 (`decor_swap_max_ms`) を出す。合成のソースがあり、周期の間に何かを数えたときだけ書く。DEBUG のログの `Composite label ready`、`Composite frame glow ready`、`Composite roster label ready` にも、描いた時間 (`paint_ms`)、1 つの仕事でコンテキストに入っていた時間の合計 (`upload_ms`)、入った回数 (`strips`。帯の数) と、その 1 回の最大 (`upload_max_ms`) が出る。
- 止め方。合成のソースを削除したとき (`composite_destroy`) と `obs_module_unload` (`release_composite_children`) は、グラフィックスのコンテキストに入る前に `CompositeDecor::stop_painter` で描き直しのスレッドを止めて待つ。待っている仕事は捨て、描いている最中の仕事は描き終えるまで待つ (1 回の描画なので、待ちは既定の見た目なら長くても 20 ms ほど、ぼかしと広がりが範囲の上の端なら 0.5 秒ほど。描き終えた画像は捨てる)。帯ごとにテクスチャを作っている最中なら、帯の間の待ちをやめ、残りの帯は作らない。描き直しのスレッドはテクスチャを作るときにコンテキストに入るので、止める側がコンテキストの中で待つと、どちらも進まない。OBS はソースの `destroy` をコンテキストの外 (破棄のタスクのスレッド。OBS 31.1.1 の `libobs/obs-source.c` の `obs_source_destroy_defer`) で呼ぶ。
- 明るさを掛ける方法。光の画像は最大の明るさで描いておき、描くたびに明るさ (0 から 1) を掛けて置く。OBS の標準の効果には、乗算済みアルファの画像の色とアルファの両方に同じ倍率を掛けるものがない (`default.effect` の `DrawMultiply` は色だけに掛け、アルファが残って背景が暗くなる)。明るさを変えるたびにテクスチャを作り直すと描き直しと同じ重さになるので、色を `level` 倍し、さらに色だけを暗さの倍率 `dim` 倍する効果を `gs_effect_create` で文字列から 1 度だけ作る。光は `dim` 1 で、名前ラベルは明るさ 1 と暗さの倍率で置く (暗くしないときは効果を通さずに置く。同じ値になる)。効果のファイルを置くと、同梱するファイルとアンインストールで消すものの一覧に足すことになるので、文字列にした。作れなかったときは警告を 1 回ログに書き、暗さは掛けず、明るさが半分以上のときだけ最大の明るさで置く。
- 形。`label_glow_frame`、`label_glow_avatar`、`label_glow_name` で選んだものだけ光らせる (枠の光は `paint_frame_glow`、アバターと名前の光は `paint_composite_label` の `glow`)。`label_show_speaking` が偽なら描かない。
- 名前ラベルの光の形。名前ラベルの見える縁 (縁取りの外側。縁取りが 0 なら字形とアバターの円) を、広がりの分だけ円の範囲で膨らませ (`glow_filter.h` の `dilate_disk`。どの向きにも同じ距離で、角は丸い)、ぼかす。文字とアバターは同じ処理を通るので、同じ値なら同じ太さとぼけ方になる。アバターと頭文字の円にも、文字と同じ色と同じ見える太さの縁取りを付ける。背景を出すときは、背景を含む名前ラベル全体の外側に光を付け、背景の下には光を描かない。広がりもぼかしも 0 なら光は描かない。
- 名前ラベル全体の不透明度。`label_opacity_pct` は、光と背景とアバターと文字をまとめた全体に 1 度だけ掛かる (光が文字や縁取りの上に透けない。重なった所が濃くならない)。光の画像には、名前ラベルの下になる所を抜き、上に重ねる名前ラベルが下を残す割合を打ち消す倍率を掛けてある (式は `composite_label.h` の `paint_composite_label` のコメント)。光と名前ラベルを別々に置いても、明るさがいくつでも、1 枚にまとめてから不透明度を掛けた値と同じになる (8 ビットの丸めの差まで。`decor_tests` の「名前ラベル全体の不透明度は、光と名前ラベルを 1 枚にまとめた全体に 1 度だけ掛かり」のテスト)。枠の光には掛けない。
- 名前ラベルの隅。`label_corner` (`tl` `tr` `bl` `br`。既定は `bl`) は、画面共有している参加者の名前ラベルを置く枠の隅で、全員一律の 1 つの値。
- アバターの位置。名前ラベルの中の並びを左右入れ替えるときは `avatar_side` が右 (アバターが右端、名前がその左)。背景の内側の余白も入れ替わり、アバターのある側が `plate_pad_v_em`、名前のある側が `plate_pad_right_em` になる。光の形は同じ配置から作るので、入れ替えた形になる。名前の省略とアバターを省く判断は、左のときと同じ (幅だけで決まる)。設定は 2 つに分かれ、`label_avatar_side` (`left` と `right`。既定は `left`) は画面共有している参加者の名前ラベルだけ、`roster_avatar_side` (既定は `right`) は画面共有していない参加者の名前ラベルと縦並びの列の中の揃えに反映される。`composite_label_look_from_settings` は前者を入れ、並びの名前ラベルは描く側が後者 (`CompositeRosterParams::avatar_side`) に入れ替える。
- 話していない人の暗さ。`label_dim_pct` (0 から 90。5 刻み) が 0 より大きいとき、名前ラベルの画像 (背景、輪郭、アバター、文字) の色の 3 つのチャンネルだけに倍率 f を掛ける。アルファは変えず、光の画像と枠の光には掛けない。`f = 1 - (暗さ / 100) x (1 - 明るさ)` で、明るさは光と同じ値 (話していれば 1、黙って保持時間とフェードアウトが過ぎれば 0) なので、f は光と同じ時間で動く (`composite_label_dim_factor`)。光のオンとオフには依らない (`composite_label_dim_level` は光の表示の設定を読まない)。常に f = 1 (暗くしない) になるのは、cordmux がその人の声を聞けない人 (配置の入力の `hears_voice` が偽の人。自分の声の経路がないときの自分の枠の人だけで、声の枠に上限がないので、ほかの人は常に聞ける) と、OBS のミキサーで合成のソースがミュートか音量 0 の間の全員である (`composite_label_dim_at`)。自分の枠の人は、サブアカウントの構成でメインアカウントの声を受け取っていれば、ミキサーで自分の声をミュートしていても、受け取った声で光り、黙ると暗くなる (pipeline/README.md の「自分の声」)。倍率は置く計画の `CompositeDraw::dim` に入り、GPU で置く側 (効果の `dim`) と CPU で重ねる側が同じ式で掛ける。暗さと明るさが変わっても、名前ラベルの画像は描き直さない (キーに入らない。`label_dim_pct` を変えても表の version は進めない)。
- 画面共有していない参加者の並び (通話の参加者のうち、名前ラベル付きで描くタイルがない人。`roster_show`、`roster_anchor`、`roster_direction`、`roster_avatar_side`、`roster_gap_ratio`、`roster_offset_x_px`、`roster_offset_y_px`。既定は表示、右下、縦並び、アバター右、間隔 0.5、ずれ 0)。
  - 大きさ。参加者ごとの名前ラベルは、画面共有の人と同じ見た目の値、同じ `paint_composite_label` で、名前の幅の上限 (キャンバスの幅の半分 - 余白 x 2。`composite_roster_cap_width`) の幅のセルに、余白 0 で描いて、大きさ (`box_w` と `box_h`) を得る。
  - 並べ方。純粋関数 `plan_composite_roster` (`composite_roster.h`) が決める。順は画面共有の枠と同じ比べ方 (`share_less`。表示名の自然順で、同じなら user_id)。横並びは左から右へ並べ、使える幅 (キャンバスの幅 - 余白 x 2) を超えたら次の行へ折り返す。縦並びは上から下へ並べ、高さが足りなければ次の列へ移る。行 (列) は、全体のまとまりを配置の端に寄せたままキャンバスの中央の側へ伸びる。行の揃えは配置の左、中央、右。縦並びの列の中の揃えはアバターの位置 (左なら左揃え、右なら右揃え)、縦の揃えは配置の上、中央、下。上と下の中央は横並びだけ、左と右の中央は縦並びだけで、合わない組は読むときに配置に合う並びへ修正する。全員が入りきらないときは、入るところまで置き、置かなかった人の数を返す。置く位置には、ずれ (キャンバスのピクセル。右と下が正) をそのまま足し、キャンバスの外へはみ出しても戻さない (誰を置くかと折り返しは、ずらす前の位置で決める)。
  - 重ね方。映像の上に重ねて描き、映像の枠は縮めない。画面共有の人の名前ラベルとは互いに干渉しない層として重ね、重なっても避けない (設定の位置のとおりに置く。避けて動かすと、位置が利用者に予測できなくなるため)。置く物は `CompositeDrawRequest::roster` に入り、画面共有の枠の物の後に、全部の光、全部の名前ラベルの順で置く (切り抜きはキャンバス)。
  - 並べる人。配置の入力の `roster` は、名前ラベルを出す人の全員 (メインアカウントと画面共有している人も入る) で、その人と名前とアバターを決めて渡すのはドックである (`dock/build_observation.h` の `composite_roster_people`)。合成のソース (`composite_decor.cpp`) は、`roster` を並べる順に並べ (user_id が空の人と、同じ人の 2 人目以降は描かない。`composite_roster_drawn`)、名前ラベル付きで描くタイルがない人だけを並びに置く。タイルに名前ラベルを描くかと、その人を並びに置くかは、同じ描画の中で同じ関数で決める (`composite_label_plan.h` の `composite_tiles_labeled`、`composite_labeled_tile_users`、`composite_roster_shows`。タイルの人は `composite_input.h` の `composite_tile_user_ids`)。そのため、全画面で描かれていないタイルの人、「1 人のときは非表示」で名前ラベルを隠した全面の 1 枚の人、映像がまだないタイルの人、描けない画面共有の人 (dropped) は並びに出て、同じ人が枠と並びの両方に出ることはない。
  - 画像。並びの名前ラベルの画像は、いまタイルに名前を出している人の分も先に描いておく (並びに移ったとき、描き終えるのを待つ間に消えないように)。見分けに使う名前 (`CompositeRosterLabelKey::others`) は、見えている名前の全部から本人を除いて並べ替えたもの (`composite_roster_others`) で、人がタイルと並びの間を移っても変わらないので、描き直さない。参加者ごとの名前とアバターは user_id で引く表 (`decor_registry.h` の `set_roster_person_decor`。表にない人は描かない) から読む。名前ラベルは CPU の側 (`src-obs/tests/decor_preview/composite_scene.cpp`) と同じセル、余白、隅、見た目で描き、描き終えていない人は並べず、描き直しを待つ間は同じ人の前の画像を置く。並びから消えた人のテクスチャは、その描画 (コンテキストの中) で捨て、描き直しの保存先を次に来た人に使い回す (`composite_roster_departed`)。
  - 設定とログ。並びの設定はドックが `set_composite_roster_params` で渡す。置けなかった人の数が変わると、ログに `Composite roster has no room for N participant(s)` を 1 行書く。
- 隠す。`label_hide_when_single` が真で、合成が 1 枚をキャンバス全体に置いているときだけ、名前ラベルと光を描かない (`composite_hides_label`)。全面にしない設定で 1 枚を左上の 4 等分に置いているときは描く。隠した 1 枚の人は、並びに出る。`label_show_in_slot` が偽なら、どのタイルにも名前ラベルとその光を描かず (`composite_tiles_labeled`)、タイルの人は並びに出る。枠の光はタイルに描く (`composite_tiles_framed`。描き直しの仕事は、名前ラベルの画像を作らずに枠の光だけを作る)。
- 話している人の条件。合成のソースでは、ミキサーが声を OBS へ出した区間に、その人の声の音があったことで決める (`pipeline/README.md` の「話している人の光」)。時刻は `set_voice_speaking` で表に入る。枠の描く人と声の人は user_id で結ぶ。声の組は、声の枠に載っている人の user_id で、画面共有の枠の描く人は、その画面共有をしている人の user_id なので、同じ人なら同じ文字列になる。OBS のミキサーの合成のソースの行がミュートか音量 0 のときは、光らせない (`obs_source_muted` と `obs_source_get_volume` を描くたびに読む)。
- テクスチャの寿命。テクスチャはグラフィックスのコンテキストの中でだけ破棄する (所有者の型が、破棄するときにコンテキストに入る)。描画のスレッドは、置き換えた前のテクスチャ、キーの違うテクスチャ、並びから消えた人のテクスチャを、その描画の中で破棄する。描き直しのスレッドが、受け取られる前に次のものができて捨てるテクスチャは、受け渡しのロックを放してから破棄する。合成のソースを削除したとき (`composite_destroy`) と、`obs_module_unload` の `release_composite_children` は、描き直しのスレッドを止めた後に、保存先に残ったものも含めて破棄し、明るさを掛ける効果も `obs_module_unload` で破棄する。
- ロック。描画のスレッドは、モジュールのロックを放した後に、表のロックと `CompositeDecor` の内部のロックを 1 つずつ順に取る。どちらも持ったままほかの cordmux のロックは取らない (`CompositeDecor` は、内部のロックを放してから表のロックを取る)。描き直しの受け渡しのロックは葉のロックで、内部のロックを持ったまま取る。描き直しのスレッドは、受け渡しのロックと、テクスチャを作るときのグラフィックスのコンテキストを取り、どちらかを持ったままもう一方を取らない。順は `composite_source.h` の冒頭にある。
