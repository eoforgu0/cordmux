# 画面の文字列に使わない記号と内部の語と、表記と空白の誤りの一覧。forbidden_ui_words.py が src-obs/data/locale の ini の値を
# チェックし、一致するとエラーにする (キーとコメントはチェックしない)。表記のルールは docs/ui_guidelines.md の「表記」に、
# 画面で使う語は「用語集」にある。
#
# 各行は Python の正規表現で、re.search で値に一致するかを調べる。大文字と小文字を区別し、re.ASCII を付ける (\b と \w は
# ASCII の英数字と _ だけを語の文字とする)。空行と # で始まる行は読み飛ばす。行の先頭の空白も正規表現の一部である
# (spacing のセットの「 \?」)。曖昧幅の文字は、\u と 16 進数 4 桁の形で書く。
#
# セット: 「# set: <名前> <説明>」の行から、次のセットの行の前までが 1 つのセットになる。名前は、出力の行にチェック項目の
# 名前として表示する。最初のセットの行より前に正規表現の行があると、一覧を読めないエラーになる。どのセットを使うかは
# ツールごとに決まっている。
#   forbidden_ui_words.py     すべてのセットを ini の値に使う
#   install_guide.py          internal-words を手順書の全体に使う。spacing は、[ ] と「」の中を伏せた手順書に使う
#   make_release_notes.py     internal-words をリリースノートに使う (load_word_patterns の既定)。spacing は、引用の中を
#                             伏せたリリースノートに使う
#
# 行の先頭の指定 (どれも「名前:」の形で、いくつでも続けて書ける。指定の後ろが正規表現):
#   ja: / en:                 その言語の ini にだけ使う (言語はファイル名の先頭の ja か en で決める)
#   spacing=A: / spacing=B:   ja_style.txt の spacing がその値のときだけ使う
#   question=halfwidth: / question=fullwidth:
#                             ja_style.txt の question がその値のときだけ使う
#   not_names:                ja_style.txt の name_keys のキー (OBS の一覧に表示する名前) には使わない
# 例: 「ja:question=fullwidth:\?」は、疑問符を全角で書く設定のとき、ja の値の半角の ? に一致する。
# 先頭が「ja:」の文字列そのものを探す行は、「(?:ja):」のように書いて指定と区別する。
#
# internal-words に、Discord の内部への依存箇所の id のうち sharing・self は入れていない。英語の画面で
# 普通の語として使うためである。
