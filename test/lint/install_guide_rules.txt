# install_guide.py が読む、手順書 (guide/ja.md と guide/en.md) の lint の見出しと語。lint のコードを変えずに見出しと語を
# 直せるように、データとしてここに置き、日本語のセットと英語のセットを同じキーで並べて書く。手順書の書き方は
# docs/ui_guidelines.md の「手順書の書き方」に、Markdown の形と zip のテキストへの変換は dist/README.md の「手順書の形」にある。
# 配布用の zip のツール (test/tools/dist-zip) も、このファイルの target、zip_name、heading、role、placeholder を読む。
#
# 形: 1 行に 1 つの「キー: 値」。空行と # で始まる行は読まない。target: の行から次の target: の行の手前までが、1 つの
# 手順書のセット。セットは 2 つ (guide/ja.md と guide/en.md)。
#
#   target:           チェックする手順書 (リポジトリのルートからのパス。Markdown)
#   ini:              [ ] の名前と「」の中の文字列を照合し、手順書への参照を探す ini (同じ言語の ini)。ファイル名の先頭
#                     (ja か en) が手順書の言語になる
#   zip_name:         zip の中の手順書の名前。make_dist_zip.py が target を変換して、この名前で zip の最上位に置く。画面の文言は
#                     この名前で手順書を指す
#   title:            1 行目の # のタイトル
#   heading:          ## の節の見出し。書いた順に、手順書の中にも同じ順で 1 回ずつ書く
#   procedure:        【最初の節】 【最後の節】。手順の部分の範囲 (1 つ以上)。forbidden の語と、引用 (quote_check) の照合は
#                     この範囲の節だけを見る
#   max_steps:        【節】 <数>。その節の手順の数の上限 (節の直下の番号付きの項目と、### N. の見出しを数える)
#   forbidden:        手順の部分に書かない語 (Python の正規表現。大文字と小文字を区別せず、\b は ASCII の英数字だけで
#                     境界を作る。forbidden_ui_words.py の re.ASCII と同じ理由)
#   copied:           【節の見出し】 <ini のキー>。その節に ini の値をコピーしてある (%1 %2 などの所は何が書いてあってもよい。
#                     空白は比べない)
#   fixture:          このセットのセルフテストの OK 例のフォルダー (リポジトリのルートから。セットごとに必ず 1 つ)。中に
#                     target と同じ名前の手順書 (ja.md か en.md) と、ini: と同じ名前の ini を置く。同じ親フォルダーの bad_* が、このセットの NG 例 (ini が
#                     なければ OK 例の ini を使う。どれも expect.txt に、出力されるはずの問題の文の一部を書く)
#   role:             【見出し】 <役割>。役割は maintenance (互換性の節)、update (更新) の 2 つで、セットごとにちょうど
#                     1 回ずつ書く。zip のチェックとリリースノートのツールは見出しの文字列を持たず、この行で節を探す
#   placeholder:      後で書く所に置く仮の文字列 (正規表現でなく、文字列のまま)。セットごとにちょうど 1 つ。手順書の lint は
#                     placeholder を許すが、この文字列のまま書く (括弧を変えると問題にする。リリースのツールが文字列で
#                     探すため)。接尾辞のないタグ (正式版) のリリースでは、1 つでも残っていれば失敗する。role が
#                     maintenance の節はリリースノートにそのまま載るので、-rc のタグでも placeholder があれば失敗する
#   forbidden_all:    手順書のどこにも書かない語 (Python の正規表現。forbidden と同じフラグ)。タイトルと全部の節を
#                     チェックする
#   contains:         【節の見出し】 <文>。その節にその文がある (空白は比べない。copied と同じ)
#   quote_check:      手順の部分の引用の開きと閉じ (ja は「」、en は "")。中の文字列は、ini の値 (先頭や末尾を省いた形も)、
#                     手順書の ## と ### の見出し、outside_text のどれか。リンクはテキストで比べる。入れ子の引用は、
#                     外側が合えば内側を見ない
#   outside_text:     引用のチェックで許す、ini にない文字列 (OBS、Windows、Discord の画面の文字列と、ファイルとフォルダーの名前)
#   ini_term:         引用のチェックで許す、ini の値の中で使う語 (画面のメッセージの中の語を説明するときの引用)。lint は、
#                     その語が ini のどれかの値にあることも確かめる (画面の語を変えたら、手順書の引用も直すため)
#   item_titles:      【節】。その節の項目は ### の見出しで書く (節の直下に - と番号付きの項目を置かない)。画面の文言と、
#                     手順の中の「うまくいかないときは」のリンクが、項目の見出しを指すため
#   component_word:   <語> <種類>[,<種類>]。[ ] のすぐ後ろにこの語が続くとき、その種類のキーの値と比べる
#   outside_button:   [ ] で許す、ほかのアプリの UI 要素の名前 (OBS、Windows、Discord、Vesktop の画面の文字列のまま)
#   ini_ref:          ini の値が手順書を指す形 (Python の正規表現)。{zip_name} を zip_name に置き換えてから使う。
#                     (?P<heading>...) の見出しが手順書の ## か ### にあり、(?P<step>...) の番号があれば、その ## の節に
#                     ### <番号>. の見出しがあることを確かめる。ini の値に zip_name があるのにどの形にも一致しなければ、
#                     参照の形が読めないので問題にする
#   target_optional:  yes のとき、target のファイルがなくても lint を失敗にしない (NOTE の 1 行を出力して飛ばす)。
#                     ファイルがあるのにこの行が残っていれば失敗にする (ファイルを置くときに、この行を消す)
# 節を指すキー (copied、contains、role、procedure、max_steps、item_titles) は、英語の見出しが空白を含むので【見出し】の形で書く。
