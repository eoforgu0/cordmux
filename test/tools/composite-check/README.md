# test/tools/composite-check

OBS の中で合成のソース (`cordmux_composite`) が GPU で描いた名前ラベル、話している人の光、話していない人の暗さ、画面共有していない参加者の並びが、CPU で描いた参照と同じ値になるかを、ピクセルで比べるツール。参照は `decor_preview.exe --composite-check` が、製品と同じ関数 (設定の読み込み、配置、名前ラベルと光の描画、暗さの倍率、並びの位置、置く物の計画、CPU で重ねる処理) で描く。名前ラベルの見た目の既定値を決める調整ツール (`src-obs/tests/label_tuner`) は CPU で描くので、配信の画面と同じ画像を見ていることをここで確認する。

| ファイル | 中身 |
|---|---|
| `run-check.mjs` | セットごとにテスト用の OBS を起動して画像を撮る。`--dry-run` は書く物と呼び出しを出すだけ |
| `compare.py` | 撮った画像と参照を比べる (`judge`、`gate`)。`sample-check` と `--selftest` も持つ |
| `run-check.test.ts` | `run-check.mjs` の単体テスト (セットの表、書く JSON、人と話す人、環境変数、ログの行の読み方、hold の JSON の読み方、ドライランの参照の要求) |

## 使い方

```
node test/tools/composite-check/run-check.mjs --obs <テスト用の OBS のフォルダー> --plugin <テスト用にインストールしたファイルのフォルダー> --out <出力のフォルダー> --built-dll <ビルドした cordmux.dll> --decor-preview <decor_preview.exe> --dry-run
node test/tools/composite-check/run-check.mjs (同じ引数で --dry-run なし)
python test/tools/composite-check/compare.py judge --run <出力のフォルダー>/<セット> --decor-preview <decor_preview.exe>
```

- `test/tools/harness` で `npm run build` を通してから実行する。
- `--sets` で実行するセットを選ぶ (既定は `seed,c1,c2c5,c3,c4c7,c6,c8`)。`seed` は初期設定の書き込みで、送信側を起動せずに OBS の設定を作り、その `settings.json` を `<out>/seed/settings.json` に取っておく。セットの実行の `prepare` はこれを元にする。
- 起動の前に、`--plugin` の `cordmux.dll` と `--built-dll` の大きさと SHA-256 を比べ、違えば始めない。
- `c1` の後に `compare.py gate` を実行し、通らなければ残りのセットを始めない (`--no-gate` で外せる)。関門は、背景 (何も置かないピクセルが完全一致)、立ち上がり (`rise`) の終わりまでに光が点くこと、配置の行、並びの行 (並びが空なので出ない)、PNG の値の並び、光の効果を作れないというログの行。
- `--dry-run` は OBS もテスト用の送信側も起動しない。セットごとに、書く `settings.json` と `seen_people.json` (`<out>/dry-run/<セット>/`)、run-window.mjs の呼び出しと環境変数、`run-window-plan.mjs` が作る手順の一覧、話す人を出し、DLL を確認し、参照の画像を試しに描いたもの (明るさ 0、1、0.5) を `<out>/dry-run/<セット>/ref/` に書く。この描画で、製品がその settings.json を読めることも確認する。送信側のアバターはまだないので、試しの描画は見本のアバター(`--composite-check-avatar`) で描く。
- `compare.py` は、参照を Qt の windows プラグイン (`--backend windows`。OBS の中と同じ) で描く。decor_preview の既定のプラグイン `cordmuxdecorpreview` も、文字を混ぜるときのガンマ (Qt の `FontSmoothingGamma`) を OS の値に合わせているので、同じ画像になる (`compare.py sample-check` を両方のプラグインで実行して確認できる)。

## 途中で止めるとき

`run-check.mjs` を Ctrl+C で止めない (テスト用の OBS が開いたまま残る)。実行中のセットの `<out>/<セット>/window3b/stop-run.txt` を置くと、run-window.mjs が次の境目で手順を抜けて OBS を閉じ、後片付けを実行する。`run-check.mjs` は obs-websocket の要求が失敗したところで残りのセットを始めずに止まる。run-window.mjs も止まってしまったときは、`test/tools/obs-run/cleanup.ps1` を実行する (使い方は `test/tools/obs-run/README.md` の「後片付け (`cleanup.ps1`)」)。

## しくみ

- テスト用の OBS は `test/tools/obs-run/run-window.mjs --step hold` で起動する (APPDATA と LOCALAPPDATA の差し替え、起動と終了、テスト用の送信側、後片付けの `cleanup.ps1` は run-window.mjs がする)。`run-check.mjs` は hold の JSON を待ってから obs-websocket に接続し、終わったら hold の JSON の `goFile` を置く。
- 自分の枠には、OBS の「画像」ソースで決まった背景 (`--composite-check-background` が描く 960 x 540 の PNG) を出す。画面共有の枠には、テスト用の送信側の映像 (960 x 540) が入る。2 人なので配置は 2 x 2 の左上と右上で、下の 2 つは何も描かれず透明になる。並び (画面共有していない参加者) は既定の右下に置かれるので、透明の上に描かれる。
- 話している状態は、製品の「使う声」で作る。`seen_people.json` で、自分の枠の人 (`check-self`) の使う声をテスト用の送信側の声 2 に、画面共有の人 (`harness-screen-1`) の使う声を声 3 に結ぶ。テスト用の送信側は、環境変数 `CORDMUX_HARNESS_VOICE_TONE_FILE` のファイルがある間、中に書いた番号の声に 1 kHz の音を乗せる (`test/tools/harness/voice_tone.ts`)。自分の枠の人は通話に参加していないが、使う声の人が通話にいれば声の枠とミキサーの組に入る (`src-obs/tests/test_pipeline_composite_audio_plan.cpp` で確認している)。
- 自分の声: `broadcaster_user_id` の人 (`check-self`) の声の組は、ミキサーで既定でミュートされる。声 2 は自分の枠の人の声の枠に入るので、この組に入り、合成のソースの音には混ざらない。話しているかはミュートと音量を掛ける前の音で判定するので、自分の枠は光る。
- 話していない人の暗さ: 製品は、話していない人の名前ラベルの色に f = 1 - 暗さ / 100 x (1 - 明るさ) を掛ける (`sources/composite_label_plan.h` の `composite_label_dim_factor`。既定の暗さは 30)。cordmux がその人の声を聞けないときと、OBS のミキサーで合成のソースがミュートか音量 0 のときは f = 1 (暗くしない。このときは光も出ない)。どのセットでも全員が声を聞ける人である。自分の枠の人は、声 2 が自分の枠の人の声の枠に経路を持つので聞け (`dock/build_observation.h` の `self_frame_hears_voice`)、画面共有の人と並びの人は、声の枠 (8) が埋まらないので聞ける (`person_hears_voice`)。参照には、参加者ごとの声を聞けるかと、1 枚ごとのミキサーで鳴っているかを渡す。
- アバター: テスト用の送信側は、送信側の人 (画面共有の人と声だけの人) の全員のアバターを送る。アバターは Chromium の `OffscreenCanvas` で描くので参照の側では同じ画像を作れない。そこで、送信側が送った PNG を、環境変数 `CORDMUX_HARNESS_AVATAR_DIR` のフォルダー (`<out>/<セット>/avatars/<userId>.png`) に書き出し、参照はその PNG で描く。自分の枠の人は送信側が知らない人なので、アバターがなく頭文字の円になる。
- 並び: `c1` から `c6` では並びは空である。テスト用の送信側の人は、画面共有の人と、声 2 と声 3 だけである。画面共有の人は枠に名前ラベル付きで描くので、並びには出ない。声 2 と声 3 は、ほかの人の使う声に選ばれているので、名前ラベルを出す人に入らない (`dock/build_observation.h` の `composite_roster_people`)。自分の枠の人は通話に参加しておらず、送信側は受け取りに使うアカウント (`self_user_id`) を送らない。`c8` は、使う声に結ばない声だけの人 (声 4 と声 5) を足して並びに出す。合成のソースは、枠に名前を出している画面共有の人の並びの名前ラベルも先に描く (並びに移ったときに一瞬消えないように) ので、`Composite roster label ready` は、どのセットでも画面共有の人の分 (`c8` は 3 人分) が出る (`run-check.mjs` の `rosterLabelCountOf`)。合成のソースを置いた直後は、画面共有の人がまだ枠に載らず (合成のソースが現れてから送信側が流し始めるまで、1 秒ほど)、並びに描かれることがある。並びが空であることは、最後の配置の行が出た後で見る。
- 明るさ 0 と 1 は、声の音の入り切りと、合成のソースのミュートと音量 0 で作る。途中の明るさは、フェードインとフェードアウトを 4000 ms にして撮り続け、画像ごとに明るさを 1 つの数で合わせてから、その明るさで参照を描き直して比べる。暗さで名前ラベルの色も明るさとともに変わるので、合わせるときは光のピクセルと名前ラベルのピクセルの両方を使う (下の「合格の基準」)。
- 撮るのは obs-websocket の `GetSourceScreenshot` で、幅と高さを渡さない (キャンバスの等倍)。シーン `Main` も撮り、シーンの項目を通った画像が同じかも見る。

## セット

どのセットも `assign_mode` を `auto`、`broadcaster_user_id` を `check-self`、`self_frame_source_name` を `gc-background` (`self_frame_source_uuid` は空)、`self_frame_on` を true、`slot_background_show` を false にする (参照は枠の背景を描かないため)。名前ラベルの設定は OBS を起動するときにしか読まれないので、セットごとに OBS を起動し直す。

| セット | settings.json で変えるキー | 自分の枠の背景 | 話す人 (立ち上がり / 2 人以上) | 主に見ること |
|---|---|---|---|---|
| `c1` | なし (時間も既定) | 細かい縞 | 自分の枠の人 / 自分の枠の人と画面共有の人 | 名前ラベルと光の位置と値、暗さ、ミュートと音量 0、シーンを通った画像、並びが空であること。関門のセット |
| `c2c5` | `label_show_plate` true、`label_opacity_pct` 50、時間 4000 | 明るい空 | 同上 | 光が背景の周りに付き、文字と縁取りの上に透けない。不透明度を下げた名前ラベルの暗さ |
| `c3` | `label_glow_frame` true、`label_glow_blur_ratio` 0、`label_glow_spread_ratio` 0.15、`label_show_plate` false、時間 4000 | 細かい縞 | 同上 | ぼかし 0 の枠の光の位置と、明るさを掛けた色。背景のない名前ラベルの光が文字とアバターの形に付く |
| `c4c7` | `label_glow_frame` true、`label_margin_pct` 0、時間 4000 | 細かい縞 | 同上 | 枠の光がセルの中だけに出て、名前ラベルの光はキャンバスの左端で切れ、セルの下の境では切れない |
| `c6` | `label_glow_blur_ratio` 3.0、`label_glow_spread_ratio` 1.0、`label_em_ratio_pct` 8.5、`label_corner` br、時間 4000 | 細かい縞 | 同上 | 光が隣のセルへ広がり、隣の名前ラベルの下にある (名前ラベルは全員一律の隅なので、右下にして自分の枠の名前ラベルを右上の枠に近づける) |
| `c8` | `roster_show` true、`label_avatar_side` right、時間 4000 | 細かい縞 | 並びの「さくら」(声 4) / 画面共有の人と並びの 2 人 (声 3、4、5) | 並びの名前ラベルと光と暗さ、アバターが右の名前ラベル、並びのない所の背景の完全一致 |

「時間 4000」は `label_border_rise_ms` と `label_border_fade_ms` (フェードインとフェードアウト) を 4000 にすること。まとめたセットで違いが出たら、`--sets c2` のように元のセット (`c2`、`c4`、`c5`、`c7`) を 1 つずつ実行できる。まとめてよいのは、GPU がするのが画像を置く、明るさと暗さを掛けて置く、切り抜くの 3 つだけで、背景・縁取り・不透明度・光の形は CPU で描いた画像の中にあるためである。`c4c7` の 2 つは、枠の光がセルの中、余白 0 の光が左端と下の境で、比べる場所が重ならない。

`c8` の並びの 2 人は、声だけの人 `harness-voice-4` (「cordmuxでの名前」は「さくら」) と `harness-voice-5` (「Ken」) で、使う声に結ばない。並びの置き方は既定 (右下、縦並び、アバターは右で右揃え、間隔 0.5) で、名前の順 (「Ken」、「さくら」の順) に並ぶ。画面共有の人の名前ラベルもアバターを右にする (`label_avatar_side` right)。テスト用の送信側は声を 4 本 (声 2 から 5) 送る。

## 1 つのセットの流れ

| 段階 | すること |
|---|---|
| `prepare` | テスト用の OBS の `plugin_config/cordmux` に、初期設定を書き込んだ `settings.json` にセットの値を上から書いた物と `seen_people.json` を書く。`record_pending_dirs.json` を消す。前の実行の `<out>/<セット>/avatars` を消す |
| `launch` | `run-window.mjs --step hold --no-seed --n-screen 1 --n-voice 2 --screen-sizes 960x540 --hw prefer-software --keep-recordings` を起動し (`c8` は `--n-voice 4`)、hold の JSON を待つ。`--keep-recordings` は、run-window.mjs の後片付けがほかの実行の録画を消さないように付ける。環境変数で、声に音を乗せるファイルとアバターを書き出すフォルダーをテスト用の送信側に渡す |
| `create` | シーン `gc-assets` に画像ソース `gc-background`、シーン `Main` に合成のソース `gc-composite` (位置 0,0、拡大なし) を作る。ログの `Composite layout ... count=2 self=...` を待つ。自分の枠に映す画像ソースは、`prepare` が書いた `settings.json` の `self_frame_source_name` で、製品が周期ごとに名前で探して見つける |
| `settle` | 画像ソースだけを撮る。ログの `Composite label ready` が tile=0 と tile=1 に、`Composite roster label ready` が並びの全員 (`c8` は index=0 と 1) に出て、`Avatar: ... people_with_avatar=N` の N が送信側の人の数 (`c8` は 5、ほかは 3) に届き、その後 2 秒、描き終えた行が増えなくなるまで待つ (最長 15 秒)。アバターが届く前に描いた頭文字の円の名前ラベルで比べないためである |
| `silent` | 明るさ 0 の画像を 1 枚 |
| `rise` | 立ち上がりの話す人の声に音を乗せ、立ち上がりを撮り続ける (c1 は 1 秒、ほかは 5 秒) |
| `speaking` | 撮らない 10 秒の前後で `GetStats` を取り、明るさ 1 の画像を 1 枚 |
| `mute` | ミュート、ミュートを外す、音量 0、音量 1 のそれぞれで 1 枚 |
| `scene` | シーン `Main` を 1 枚 |
| `fade` | 音を止め、消える途中を撮り続ける (c1 は 1 秒、ほかは 5 秒) |
| `both` | 2 人以上の話す人の声に音を乗せて待ち (c1 は 1 秒、ほかは 4.5 秒)、送信側のフレームを止めてから、ミュートで 2 枚、ミュートを外して 1 枚 |
| `close` | 作った 3 つを消し、`goFile` を置いて run-window.mjs が OBS を閉じて後片付けを終えるのを待つ。OBS のログを `obs.log` にコピーする |

`create` と `settle` は OBS のログを読みながら待つ。最初のセットで、ログの行がファイルに出るまでの遅れ (見つけた時刻 - 行の時刻) を測り、1 秒を超えたら、以降は決めた時間だけ待つ (`<out>/log-wait.json`)。

## 合格の基準

| ピクセル | 許す差 (各チャンネル) |
|---|---|
| 何も置かないピクセル | 0 |
| 明るさ 0 と 1 で、置く物が 1 つ | 1 |
| 置く物が 2 つ以上重なる | 2 |
| 途中の明るさ (合わせた明るさで描き直した参照と比べる) | 2 |

- GPU は 8 ビットのテクスチャを等倍・整数の位置で読むので、明るさ 0 と 1 では CPU と同じ値になる見込みである。差 1 を許すのは、D3D11 が浮動小数点から 8 ビットへの変換に誤差を認め、混ぜる計算の内側の精度も GPU に任されているためである。置く物が重なるごとに丸めが 1 回入る。名前ラベルの暗さは、色に掛ける倍率が 1 つ増えるだけで、置く物の数は変わらない。
- 参照は、明るさと暗さの倍率を GPU の効果と同じ 32 ビットの小数で掛ける (sources/composite_draw_cpu.cpp)。64 ビットで掛けると、白 (255) に暗さ 30% を掛けた値がちょうど 178.5 になって 179 に丸まり、GPU の 178 と合わない。名前ラベルの文字の中のピクセルがそろって 1 ずれるので、偏りが -0.1 から -0.2 になる。32 ビットで掛けても、掛けた値が半分ちょうどに近い色 (`c8` のアバターの 135 に 0.7 を掛けた 94.5) では GPU が 1 暗くなり、偏りが -0.03 ほど残る (下の限度の中)。
- 比べる参照: 明るさ 0 (`silent`) は全員が話していない参照 (声を聞ける人の名前ラベルは暗い)、明るさ 1 (`speaking`、ミュートを外した後、音量 1 の後、シーン) は立ち上がりの話す人が明るさ 1 の参照、ミュートと音量 0 (`mute`、`vol0`、`both` のミュートの 2 枚) は光らせず暗くもしない参照 (ミキサーで鳴っていない)、`both` のミュートを外した 1 枚は 2 人以上の話す人が明るさ 1 の参照。
- 比べるピクセルは、背景が分かるピクセル (左上、左下、右下。並びは右下の透明の上にある) と、名前ラベルのアルファが 255 のピクセル。右上は映像が動くので、フレームを止めた `both` のミュートを外した 1 枚だけ、ミュートした 1 枚を背景にして、名前ラベルのアルファが 0 のピクセルも比べる。
- 置いたピクセルの差の平均 (符号つき) が -0.05 から +0.05 であること (切り捨てる GPU を見分ける)。
- 名前ラベル (並びの名前ラベルも) を上下左右に 2 ピクセルまでずらした参照と比べ、ずらさない (0, 0) が最もよく合うこと。
- まとめたセットで違いが出たときにどの物のピクセルかを分けられるように、`summary.json` の `separation` に、置く物ごとの「その物だけが置かれたピクセル」と「セルの外へ出たピクセル」(並びの物はキャンバスの外) の数と差の最大、同じ人のほかの物と重なるピクセルの数を書く。`c4c7` では、枠の光と名前ラベルの光はセルの左下の隅で約 500 ピクセル重なるが、名前ラベルの光がセルの下の境を越える所 (下のセル) と、キャンバスの左端で切れる所のうち下のセルにある部分は、名前ラベルの光だけが置かれる。
- 途中の明るさは、立ち上がりの話す人 1 人の光と名前ラベルが明るさとともに変わる (ほかの人は黙っている)。明るさを 1 つの数で合わせるピクセルは 2 種類で、どちらも製品の形では値が明るさの 1 次式になる。光のピクセル (話す人の光が 1 つだけ置かれ、どの名前ラベルも置かれない) は 値 = 下 + 明るさ x (光 - 光のアルファ x 下)、名前ラベルのピクセル (話す人の名前ラベルのアルファが 255 で、ほかの人の名前ラベルが置かれない) は 色 = 名前ラベル x f。どちらも背景が分かり、背景のアルファが 0 か 255 のピクセルだけを使う。製品の形 (光は 4 つの値すべてに明るさを掛け、名前ラベルは色だけに暗さの倍率を掛ける) で合わせた残りが 2 以下で、ほかの形 (光の色だけに掛ける、sRGB の光の量で混ぜる、明るさ 0.5 以上でそのまま置き未満で置かず暗くもしない予備の描き方、暗さを名前ラベルのアルファにも掛ける) は合わないこと。光のピクセルがなければ光の形を、暗さが 0 か名前ラベルのピクセルがなければ暗さの形を見分けない (製品の形と同じ値になる)。形は、明るさが 0.2 から 0.8 の画像で見分ける。時間を 4000 ms にしたセットで途中の明るさの画像が 3 枚未満なら、予備の描き方の疑いで不合格にする。明るさを時刻に並べた傾きは、設定の時間から決まる傾きの 15% 以内。
- 並び: 最後に並びに置いた人の数 (`Composite roster shows N participant(s)`) が、並びの人の数 (`c1` から `c6` は 0、`c8` は 2) であること。`Composite roster label ready` が、並びの名前ラベルを描く人の全員 (`rosterLabelCountOf`) の番号に出ること。参照が並びに置いた人の数が 2 であること (`c8`)。
- ログに `Couldn't create the speaking glow effect`、`Composite layout has no room`、`Composite roster has no room`、`Couldn't create the screen share tile` がなく、配置の行が参照の配置と同じこと。名前ラベルを描き終えた後、何も変えていない間に描き直さないこと (`Composite label ready`、`Composite roster label ready`、`Stats composite_decor` の行が出ない)。
- 統計の行 (`Stats composite_decor`) で、`decor_upload_max_ms` と `decor_swap_max_ms` がどちらも 5 ms 以下、`decor_dropped` が 0。`decor_dropped` は、配置が落ち着いた (最後の配置の行が出た) 後に始まった周期の行だけで見る。合成のソースを置いた直後は配置が続けて変わり、描き直しの仕事が次の仕事に置き換わって捨てられるのが正しい動きのため。`GetStats` の `renderSkippedFrames` が撮らない 10 秒の間に増えないこと。
  - `decor_upload_max_ms` は、描き直しのスレッドがテクスチャを作るためにグラフィックスのコンテキストを 1 回 (帯 1 つ) 持った時間の最大である。OBS の描画のスレッドは、フレームを描く間このコンテキストを持つので、この時間だけ次のフレームを描き始めるのを待たされうる。製品は大きな画像を 512 KB 以下の帯に分け、コンテキストに入るのを 1 フレームに 1 回までにする (`src-obs/sources/README.md` の「名前ラベルと話している人の光」) ので、1 フレームに待たされうるのはこの 1 回分である。1 つの仕事の合計は統計の行には出ず、`Composite label ready` などの行の `upload_ms` に出る。同じ行の `strips` は帯の数、`upload_max_ms` はその仕事の 1 回の最大である。
  - `decor_swap_max_ms` は、描画のスレッドが描き終えた仕事を受け取ってテクスチャを置き換えた 1 回の時間の最大である (`sources/composite_decor.cpp` の `update_tile` と `update_roster` が、受け取ってから `note_swap` までを測る。その間に、前のテクスチャを壊す `gs_texture_destroy` が入る)。描画のスレッドの中の時間なので、置き換えたフレームの描画の時間にそのまま足される。
  - どちらも 1 回の名前ラベルの作り直しが描画のスレッドを止める長さなので、同じ 5 ms を上限にする。この線は、置き換えにかかる時間を測って決めた値ではない。
- アバターの PNG (`<out>/<セット>/avatars/`) が送信側の人の全員の分あること。なければ参照を描かずに不合格にする (製品と同じ名前ラベルを描けない)。
- PNG の 4 つの値が乗算済みのままか、アルファで割り戻した値かは、背景が透明な所に置いた半透明のピクセルから見分ける。そういうピクセルがないセット (c1 の既定の値では、光が下のセルまで届かない) では見分けず、どちらでも比べる値は変わらない。`c8` では並びの名前ラベルと光が透明の上にあるので見分けられる。

`compare.py --selftest` は、作った画像で、一致・1 px のずれ・sRGB で混ぜた画像・色だけに掛けた画像・予備の描き方・暗さをアルファにも掛けた画像 (縞の上と、透明の上の並び)・暗くしていない名前ラベル・値の並び・ログの行の読み方 (並びの行、統計の置き換えの時間) を確認する。`compare.py sample-check` は、`--composite-check` が `--composite-sample` と同じ入力から同じ画像を描くかを確認する (アバターは PNG にして渡す。見本は暗さを描かないので、全員を声を聞けない人にして渡す)。
